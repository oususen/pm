# 将来構成検討（ミエデン主DB・社内アプリPC）

## 方針

開発中は、アプリの画面、API、定時処理、PostgreSQLを社内環境で運用する。機能追加、DB変更、検証を迅速に実施できる状態を維持するためである。

機能、更新手順、バックアップ・障害対応、利用現場が定型化した後に、ミエデンの遠隔地環境への移設を検討する。移設範囲は、DBのみとするか、画面・API・定時処理を含むアプリ全体とするかを、その時点で決定する。

## 段階別の運用

| 段階 | 配置 | 目的 |
| --- | --- | --- |
| 開発・検証中（現在） | 社内: 画面、API、定時処理、PostgreSQL | 機能追加・修正・DB変更を迅速に検証する |
| 本番運用の定型化後（将来） | ミエデン: DB、必要に応じて画面・API・定時処理 | サーバー保守、バックアップ、監視を外部へ委託する |

## 将来の移設後構成

```text
社内業務端末
    |
    | HTTPS（社内LAN）
    v
社内アプリPC
  - Vue画面
  - Django API
  - 定時処理（scheduler）
  - Docker
    |
    | VPN等で暗号化したDB接続
    v
ミエデン遠隔地環境
  - 本番PostgreSQL
  - DBバックアップ
  - DB監視・復旧
```

## 将来の役割分担

| 対象 | 社内 | ミエデン |
| --- | --- | --- |
| アプリのソースコード・機能改修 | 開発・テスト・リリース判断 | 変更内容の受領 |
| 社内アプリPC | アプリの起動確認、更新実施 | ハードウェア・OS保守の範囲を要確認 |
| Dockerの画面・API・定時処理 | アプリ更新時の再構築・再起動 | 原則対象外 |
| 本番PostgreSQL | 業務データの利用・整合性確認 | 構築、監視、バックアップ、復旧、パッチ適用 |
| VPN・DB接続経路 | 利用者・接続元の管理 | 構築、アクセス制御、監視 |
| DB障害 | 業務影響の連絡・アプリ側の確認 | 原因調査、復旧、バックアップからの復元 |

## 将来の接続・セキュリティ要件

- 社内アプリPCからミエデンDBへは、VPNまたはミエデン指定の閉域・暗号化経路で接続する。
- PostgreSQLの接続元は社内アプリPCの固定IPまたはVPN上の固定アドレスに限定する。
- PostgreSQLをインターネットへ直接公開しない。
- DB接続用アカウントはアプリ専用とし、管理者アカウントをアプリ設定へ使用しない。
- DBの接続先・ID・パスワードは社内アプリPCの環境変数ファイルで管理し、Gitへ登録しない。
- ミエデン側で通信経路、DBアカウント、バックアップ暗号化、保管期間を設定する。

## 移設判断の条件

- 対象機能の開発・検証が完了していること。
- リリース、DB変更、ロールバック、障害連絡の手順が文書化されていること。
- 利用対象の現場・業務範囲と、導入順序が決まっていること。
- ミエデン側の保守範囲、費用、責任分担を合意していること。

## 事前確認事項

- ミエデンがPostgreSQLの提供・運用保守、VPNまたは閉域接続に対応できるか。
- 社内アプリPCを常時稼働する端末として認めるか。停電対策、再起動後の自動起動、保守担当を決める必要がある。
- 社内アプリPCのハードウェア・OS障害を誰が対応するか。
- 添付ファイル・帳票出力の保管先をミエデン側に用意できるか。
- DBバックアップの頻度、保持世代、復旧目標時間、復旧時の連絡手順。
- DBのデータ所在地、アクセス権限、監査ログ、個人情報の取扱いに関する社内承認。

## 判断

現在は開発中のため、ミエデンへの移設は行わない。機能と運用が定型化した後に、ミエデンへDBのみを移すか、アプリ全体を移すかを判断する。
