## 導入目的

### 背景

- 既存の基幹システムは、製缶領域では実績の入力・管理に機能が限定されており、生産計画や進度管理の基盤として十分に活用されていない。
- 生産計画は各ラインで個別のExcelファイルにより管理されており、計画・進度・在庫を部門横断で確認しにくく、属人化されやすい。
- 外作品・購入品の一部は、仕入先へ進度表を共有する運用となっており、納期・納入数量の一元管理が不足している。
- 上記に加え、製造業ではIoT・DX・AIの活用が加速しており、生産データのリアルタイム管理、業務プロセスのデジタル化、AIによる自動化が競争力の要素となっている。紙・Excelに依存した業務からの脱却と、データに基づく生産管理体制の構築が急務である。

### アプリの現状機能

- 受注、生産計画、工程実績、進度、在庫、発注、納入、検収の情報を一元管理している。
- 各工程間のデータ連携により、ライン計画を立てると工程計画を自動生成し、後ラインの計画から前ラインの計画も自動生成する。
- 出荷便の自動振り分けにより、手作業による便割り当てを削減している。
- これらの自動化により、管理業務の簡易化、属人化の解消、業務処理時間の削減を実現している。また、工程間のデータ連携により、計画変更・納入遅れ・在庫不足を早期に把握できる体制を構築している。

### 現状の課題

- 現段階ではアプリの実運用は現場ラインの半数にとどまっているが、使用ユーザーの増加により現存サーバーPCの処理能力が不足しつつある。
- 全ラインへの展開を進めるにあたり、安定稼働を支える本番運用基盤の確保が必要である。

### PC導入後に実装予定の機能

- 全生産現場への段階展開（残り半数のラインへの運用拡大）。
- 注文書自動送信・トラック積載判定の本番運用開始。注文書Excel/PDF・進度表・外作納品書の自動生成・自動メール送信、安全在庫・ロット丸めを加味した発注数量の自動算出、トラック荷台寸法と容器情報に基づく積載可否・占有率の自動判定により、購買業務の自動化を推進する。
- 社内通話の録音・自動文字起こし機能の本番運用開始。通話内容をWhisperモデルで自動文字起こしし、現場のリアルなノウハウ・判断・対処事例を原始データとして蓄積する。蓄積データは将来のナレッジ検索・AI活用の基盤となる。
- 自動計画の高度化（現在の工程間連携方式から、計画在庫に基づく自動計画へ拡張）。
- Ollamaによる社内ローカルLLM環境の構築と、業務知識の検索・回答、帳票作成支援、データ分析補助などのAIエージェント導入。社外AIサービスを使わずに社内で完結するため、社外秘情報の流出リスクを防止できる。
- Difyを活用した社内AI知識基盤の構築（社内ドキュメント・データのRAG構造化、業務特化AIエージェントのノーコード構築）。
- PostgreSQL + pgvectorによるベクトルDB構築と、製品名・品番・工程名等の自然言語あいまい検索基盤の整備。
- 蓄積した生産データ（実績・仕損・設備状態・品質記録）を活用したトラブル傾向分析・再発防止の分析基盤構築。
- 現場ロボット・設備とのデータ連携により、設備運転情報（稼働状態・サイクルタイム・停止要因等）をリアルタイムに取得し、稼働監視・予防保全・生産効率分析を実現する（IoT連携）。
- 画像認識モデルの学習・検証による検査自動化。

## 導入理由

| 項目 | 理由 |
| --- | --- |
| Core Ultra 9 285K | アプリ、データベース、画像処理を同時に実行するため、高性能CPUを採用する。 |
| メモリ64GB | 業務システムとDocker環境を安定して同時稼働させるため。負荷増加時は128GBへ増設できる。 |
| RTX 5090 | 将来の画像認識モデル学習を高速化し、社内ローカルLLM（30Bクラス）の運用に対応するため。より大規模なモデル（70B以上）が必要になった場合は、2枚目のGPU増設でVRAMを拡張できる。 |
| NVMe SSD 2TB | OS・業務アプリ・データベース・書類data、学習データを高速に扱うため。 |
| 2.5GbE LAN | 業務端末からのアクセスおよびバックアップ時の通信余裕を確保するため。 |
| 1200W以上の電源・360mm簡易水冷 | 高性能CPUとGPUを高負荷時にも安定して動作させるため。 |
