# 旧本番の案内ページ(PM移転のお知らせ) 手順書

目的: 切替後、旧本番 `https://10.0.1.232:8501` を開いた人に、ログイン画面ではなく案内ページを見せる。
案内ページには、新しいアドレス(`https://10.0.1.139:8501`)、証明書のダウンロードとインストール手順、新しいAndroidアプリ(WANBASE)のダウンロードとインストール手順がある。全員への通知はしない。

- 旧本番のコード・DB・バックエンドは変更しない。画面側(`pm_frontend_prod`)を停止して、案内ページ用の小さなnginx(`pm_notice_prod`)を8501で起動するだけ。
- 旧本番のバックエンド・スケジューラを止めるのはBOSS(別作業)。

## 用意したもの(このフォルダ)

| ファイル | 内容 |
|---|---|
| `notice.html` | 案内ページ本体 |
| `nginx.conf` | どのURLでも案内ページを返す。`/api/` は 503(移転の案内の文)。`/downloads/` からAPK・証明書を配る |
| `docker-compose.notice.yml` | 案内ページ用コンテナ(8501、旧本番と同じ証明書) |
| `配置ファイル/app-debug.apk` | **新アプリ「WANBASE」**(新アドレス https://10.0.1.139:8501 に接続、新PCの証明書を組み込み済み) |
| `配置ファイル/pm-pc2.crt` | 新PC(10.0.1.139)のHTTPS証明書(公開側のみ。秘密鍵は含まない) |

## 旧本番PCでの手順

1. 旧PCの `pm` フォルダに、`notice/` フォルダごとコピーする(または `git pull`。`配置ファイル/` の中身は手でコピー)。
2. **APKと証明書を、旧本番のダウンロード置き場に置く**(プロフィール画面の「Androidアプリ ダウンロード」と同じ場所):
   `pm-ui/public/downloads/app-debug.apk`(今のAPKを上書き。古いAPKは念のため別名で残す)と `pm-ui/public/downloads/pm-pc2.crt`
3. (切替後の)差し替え。**リポジトリ直下で**:
   ```
   docker stop pm_frontend_prod
   docker compose -f notice/docker-compose.notice.yml up -d
   ```
4. 確認: 別のPCのブラウザで `https://10.0.1.232:8501/`、`/login`、`/settings/profile` を開き、案内ページが出る。「証明書をダウンロード」「アプリ(APK)をダウンロード」が動く。ログインできない。
5. nginxのイメージ(`nginx:alpine`)が旧PCにない場合は、取得にインターネット接続が必要。旧本番の画面側は同じイメージを土台にしているため、通常はある。

## 戻す(案内ページをやめて、元の旧本番画面に戻す)

```
docker compose -f notice/docker-compose.notice.yml down
docker start pm_frontend_prod
```

`pm_frontend_prod` は削除せず停止しただけなので、すぐ元に戻る。

## 注意

- 新アプリは、これまでのアプリ(「オーシャン」、同じ`com.daiso.pm`)と署名が違うため、**上書きできない**。利用者は、旧アプリをアンインストールしてから入れる(案内ページに記載済み)。
- 旧アプリの画面(アプリ内)から案内ページを開いた場合、APKのダウンロードは端末のブラウザ(Chrome)で行う必要がある(案内ページに記載済み)。
- 新アプリは、デバッグ署名(この作業PCで生成)のAPK。Playストアには出さない社内配布用。
