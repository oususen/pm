## 2. 在庫・計画在庫・進度の実行タイミング

- 生産計画入力「保存」:<br>`linePlans.save` → `expand_processes(include_coproduct_children=true)` → **recalculate_inventory（include_progress=false, line_final_only=true／仕損集計あり・進度は更新しない）** → `line-gantt-plans.generate`
- 生産計画入力「取り込み」:<br>`line-backlogs.pickup` → **recalculate_inventory（include_progress=false, line_final_only=true／在庫・計画在庫のみ更新）**
- 在庫/残量一覧「在庫再計算」:<br>表示中ラインを対象に並列で `pickup` → `recalculate_scrap` → **recalculate_inventory（include_progress=true, line_final_only=false）**（recalculate_inventory内でも仕損集計を実施）
- 在庫/残量一覧「調整数保存」:<br>`line-backlogs.save` 後に **recalculate_inventory（include_progress=true）** を実行

## 3. 計算ロジック（要点）

### 実在庫（stock_qty）

- 日次計算:<br>`前営業日の stock_qty + actual_qty - 出庫`
- 出庫:<br>最終品は確定受注（FIRM）をLT遡りで計上、それ以外は親製品の実績＋仕損（ScrapRecord.qty）をBOM展開して子部品の出庫として計上
- 調整・仕損:<br>`adjust_qty`・`scrap_qty`は式に直接加えず、仕損は出庫側で反映
- 起点:<br>8:00区切りで算出した**前々営業日の stock_qty**を初期値に採用

### 計画在庫（planned_stock_qty）

- 計算開始日:<br>業務日（today）から「親BOMの最大LT+1」営業日前（`calc_start_date`）
- 初期値:<br>`calc_start_date` 以前で最も近い `stock_qty` を初期値とし、見つからなければ0
- 日次計算:<br>
  - 過去（plan_date < today）: `前日 planned_stock + actual_qty - 計画出庫`<br>
  - 未来（plan_date >= today）: `前日 planned_stock + plan_qty - 計画出庫`
- 計画出庫:<br>最終品はFIRM優先（未来はFIRM>0ならFIRM、なければorder_qty）、ライン最終品は `order_qty`、その他は親製品の実績+仕損または計画をBOM展開して算出
- adjust_qty・scrap_qty は直接加算せず、仕損は出庫側で反映

### 進度（progress_qty）

- 計算開始日:<br>業務日（today）から「親BOMの最大LT+1」営業日前（`calc_start_date`）
- 初期値:<br>`calc_start_date` 以前で最新の `progress_qty` を使用（無ければ0）
- 非稼働日は前営業日の進度をそのまま保持
- 日次計算:<br>`前日進度 + actual_qty - 需要(LineDemand: FIRM優先→FORECAST) + adjust_qty`
- 仕損:<br>progress計算には含めず（仕損は実績/出庫側で反映済み）

### 5) 生産実績入力 (/production/mobile-input)

| 操作 | API | 参照（テーブル/列） | 計算/処理 | 保存先（テーブル/列） |
| --- | --- | --- | --- | --- |
| 実績登録 | `POST /process-realtime-records/` | `Process`<br>`Product`<br>`Line`<br>`CalendarDay`（勤務カレンダ＋8時境目でplan_date決定） | 計画日決定（`resolve_workday_date_for_process`）<br>→ ProcessRealtimeRecord作成<br>→ LineBacklog.actual_qty（seq=0）更新<br>→ BOM展開して後工程実績を `actual_shipment_qty` に即時反映 | `ProcessRealtimeRecord.*`<br>`LineBacklog.actual_qty`<br>`LineBacklog.actual_shipment_qty` |
| 仕損登録 | `POST /process-realtime-records/`<br>(event_type='SCRAP') | `BOMItem`（展開用）<br>`StockAllocation` | ScrapRecord作成<br>→ BOM展開してScrapRecordDetail作成<br>→ `LineBacklog.scrap_qty`（自製品）/`adjust_qty`（子部品）即時反映<br>→ 在庫控除 | `ScrapRecord.*`<br>`ScrapRecordDetail.*`<br>`LineBacklog.scrap_qty/adjust_qty`<br>`StockAllocation.current_stock` |
| 仕損判定 | `POST /process-realtime-records/{id}/scrap-disposition/` | `ScrapRecord`<br>`ScrapRecordDetail` | RETURN: 戻し処理（在庫復帰＋LineBacklog.stock_qty/planned_stock_qty補正）<br>CONFIRM_SCRAP: 仕損確定 | `ScrapRecord.disposition_status`<br>`LineBacklog.stock_qty/planned_stock_qty/scrap_qty`<br>`StockAllocation.current_stock` |

**重要ポイント**:
- **8時日替わり＋勤務カレンダ**: 8:00未満や夜勤跨ぎは前日扱い（`LineWorkCalendar`による判定）
- **自動連動**: 実績保存と同時にLineBacklog.actual_qty/actual_shipment_qtyが即時更新
- **在庫・計画在庫・進度の再計算は自動では実行されない**: 在庫残量画面の「在庫再計算」で明示的に実行が必要
