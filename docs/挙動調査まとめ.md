## 2. 在庫・計画在庫・進度の実行タイミング

- 生産計画入力「保存」:<br>`linePlans.save` → `expand_processes` →（必要に応じて`resolve_upstream_lines`/`pickup`）→ **recalculate_inventory（include_progress=false, final_only=true）** → `line-gantt-plans.generate`
- 生産計画入力「取り込み」:<br>**recalculate_inventory は include_progress=false, final_only=true（最終品のみ、進度は更新しない）**
- 在庫/残量一覧「在庫再計算」:<br>期間・ライン単位で **全製品の進度含め再計算**（final_only=false）
- 在庫/残量一覧「調整数保存」:<br>`line-backlogs.save` 後に **recalculate_inventory** 再実行

## 3. 計算ロジック（要点）

### 実在庫（stock_qty）

- 日次計算:<br>`前営業日実在庫 + 実績生産 - 出庫 + 調整 - 仕損`
- 出庫:<br>最終品は確定受注（`OrderLine`）をLT遡り、非最終品は親製品の実績をBOM展開
- 起点:<br>**前々営業日の在庫を初期値**として前日以降を再計算（8:00日替わり対応）

### 計画在庫（planned_stock_qty）

- 過去: 実績ベース、今日以降: 計画ベース
- 日次計算:<br>`前営業日計画在庫 + 計画 or 実績生産 - 計画出庫 + 調整 - 仕損`
- 起点:<br>**前々営業日の実在庫**を初期値として使用

### 進度（progress_qty）

- 式:<br>`前日進度 + 実績 - 需要(LineDemand) + 調整 - 仕損`
- 需要:<br>確定優先、無ければ内示
- 起点:<br>**前々営業日の進度**を初期値に前日以降を再計算

### 5) 生産実績入力 (/production/mobile-input)

| 操作 | API | 参照（テーブル/列） | 計算/処理 | 保存先（テーブル/列） |
| --- | --- | --- | --- | --- |
| 実績登録 | `POST /process-realtime-records/` | `Process`<br>`Product`<br>`Line`<br>`CalendarDay`（8時日替わり判定） | 計画日決定（8時境目）<br>→ ProcessRealtimeRecord作成<br>→ LineBacklog.actual_qty更新<br>→ 出庫自動反映 | `ProcessRealtimeRecord.*`<br>`LineBacklog.actual_qty`<br>`LineBacklog.actual_shipment_qty`（後工程→前工程） |
| 仕損登録 | `POST /process-realtime-records/`<br>(event_type='SCRAP') | `BOMItem`（展開用）<br>`StockAllocation` | ScrapRecord作成<br>→ BOM展開してScrapRecordDetail作成<br>→ 在庫控除 | `ScrapRecord.*`<br>`ScrapRecordDetail.*`<br>`StockAllocation.current_stock` |
| 仕損判定 | `POST /process-realtime-records/{id}/scrap-disposition/` | `ScrapRecord`<br>`ScrapRecordDetail` | RETURN: 戻し処理（在庫復帰）<br>CONFIRM_SCRAP: 仕損確定 | `ScrapRecord.disposition_status`<br>`StockAllocation.current_stock` |

**重要ポイント**:
- **8時日替わり**: 8:00未満の記録は前日扱い
- **自動連動**: 実績保存と同時にLineBacklog.actual_qty/actual_shipment_qtyが即時更新
- **在庫・計画在庫・進度の再計算は自動では実行されない**: 在庫残量画面の「在庫再計算」で明示的に実行が必要
