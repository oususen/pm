# クボタ堺 納期調整・便計画・生産計画の業務フローと責任分担

## 1. 納期調整とは

クボタからの受注（内示・確定）は「この日にこれだけ欲しい」という顧客要求ですが、
そのまま出荷計画には使えません。**受注数と実際に納入する数の間にギャップ**が生じるためです。

### 受注数 ≠ 納入数になるケース

| 要因 | 説明 |
|---|---|
| 生産能力の制約 | 1日の要求数を全量生産できない場合、前倒し・後ろ倒しで調整する |
| 在庫状況 | 手持ち在庫で当日分を賄えるか、分割納入にするか判断が必要 |
| トラック積載制限 | 便の容量に物理的な上限があり、全量を1便で送れない場合がある |
| 容器不足 | 出荷に必要な容器が不足している場合、納入数を減らす必要がある |

### 内示→確定の変動

クボタからはまず**内示**が届き、後から**確定**に切り替わります。
確定時に数量や日付が変わることがあるため、その差分を管理する必要があります。

### 残量の管理

受注数と納入数の差を「残量」としてシステムが自動計算します。

- **残量 > 0** → 先行分がある（前倒し納入済み）
- **残量 < 0** → 未納入分がある（納入遅れ）
- **残量 = 0** → 受注と納入が一致

---

## 2. 現状の運用と課題

### 現状

営業担当が**週1回（火曜日）**に納期調整を実施しています。

### なぜ営業が担当しているか

クボタ堺の注文には以下の特徴があり、顧客事情を知る営業が対応してきました。

| クボタの注文パターン | 問題 |
|---|---|
| まとめ注文 | 2日分を1日にまとめて発注してくる |
| 追加注文 | たまに5日以内の短納期納入を要求してくる |
| 特殊要求 | 検査行きなど通常と異なる納入先・条件の要求がある |
| 内示と確定の乖離が大きい | 確定で数量・日付が大きく変わる |

### 実は判断は難しくない

営業は基本的に**前倒しで納期調整**しており、常に先行納入済みの状態を維持しています。
判断基準は**「残量がマイナスにならないか（＝納入遅れが発生しないか）」**だけです。

```
通常時:   残量 = +20（20台分 先行納入済み）
トラブル: 9台不足 → 残量 = +11（まだ11台の貯金 → 問題なし）
危険:     残量 < 0 → 納入遅れ → 顧客に迷惑がかかる
```

この判断に顧客の事情は関係なく、数字だけ見ればよいため、**生産側でも対応可能**です。

## 3. 生産トラブル時の連絡義務

生産トラブル（例: 前工程の加工ミスで当日9台不足）により納入数が変わる場合、
**関係者へメールで連絡しなければなりません。** 連絡なしに納入数を変更することは許されません。

### 連絡の責任

**連絡責任は原因工程と最終工程の両方にあります。**

- **前工程（板金、仕入先など。例: プレス）** — ミスの発生元として**最も責任が大きい**。自工程のミスが後工程・納入に影響を与えることを認識し、速やかに連絡する義務がある
- **最終工程（マテハン1）** — 自分のミスでなくても、納入数を満たせない事実を把握した時点で連絡する義務がある

### 連絡先

| 連絡先 | 内容 |
|---|---|
| 営業 | 不足数と理由の報告。顧客への説明が必要かを判断してもらう |
| 便計画担当 | 積載数が変わるため、便割付の変更が必要か確認 |
| クボタ（顧客） | 納入数減の連絡（営業経由） |

## 4. あるべき姿 — 各担当の責任分担

現状は営業が納期調整を一括で担当していますが、本来は以下の責任分担で運用すべきです。

| 担当 | 責任 |
|---|---|
| **営業** | 顧客窓口、追加注文の受付・連絡、容器確保、顧客のまとめ注文をなくす交渉、検査行き等の本来クボタ内部で管理すべき特殊要求をなくす交渉 |
| **生産側** | 納期調整（納入数の決定）。目標は**納入遅れなし**、かつ**できるだけ前倒し生産なし**（資材調達、前工程へ負荷をかけるため） |
| **前工程（板金、仕入先など。例: プレス）** | トラブル発生時の即時メール連絡。9月11日の納入不足についても**最も責任が大きい** |
| **最終工程（マテハン1）** | 納入数不足発生時のメール連絡。**原因が自分のミスでなくても連絡義務あり** |
| **便計画担当** | 便割付、積載確認。通常は自動便割付の結果をそのまま使用する。手動でAM便⇔PM便の変更を行う場合は**必ず生産側に確認**すること（生産締切日が変わるため） |

### 営業の役割の変化

納期調整を生産側に移管した場合、営業の役割は以下に変わります。

- **容器確保**: 出荷に必要な容器が不足しないよう管理・調達する
- **まとめ注文をなくす交渉**: クボタに対して、2日分をまとめず日別に発注してもらうよう交渉する
- **特殊要求をなくす交渉**: 検査行き等、本来クボタ内部で管理すべき特殊要求をなくしてもらうよう交渉する
- **注文の正常化こそ営業が取り組むべき本質的な課題**

### 生産側の目標

- **納入遅れなし**: 残量がマイナスにならないこと（最低限の要件）
- **前倒し生産の最小化**: 前倒し納入は安全だが、前倒し生産は資材調達や前工程に負荷をかける。必要以上の前倒しは避ける

## 5. 便計画 — 何をどの便に積むか

納期調整で確定した納入数を、**どのトラック（便）に・何台積むか**を決める工程です。

### 便の構成

クボタ堺向けには4便が運行しています。

| 便名 | グループ | 出発 | 到着日 | 積載量 |
|---|---|---|---|---|
| 2便 | AM | 当日朝/昼 | 当日着 | 10t |
| 3便 | AM | 当日朝/昼 | 当日着 | 10t |
| 4便 | PM | 前日夕方 | 翌日着 | 10t |
| 5便 | AM | 当日朝/昼 | 当日着 | 4t |

**4便のみ前日出発（翌日着）。** 製品はAM/PMグループに事前に割り当てられており、基本固定です。

### 4便の日ずれが納期調整を難しくする

4便に積む製品は**前日に生産完了**が必要です。
納期調整で納入数を決めるとき、この日ずれを考慮しないと便計画が成り立ちません。

そのため、**製品ごとにAM/PMグループを必ず固定しなければなりません。**
AM/PMが固定されていないと日ずれが確定せず、生産締切日がわからないため、
生産キャパオーバーかどうかの判断ができません。
AM/PMを固定することで、どの便に載るかが自動的に決まり、日ずれの判断をシステムに任せることができます。

## 6. 生産計画への連携

便割付を保存すると、以下が自動で実行されます。

1. **出荷情報の記録** — 出荷管理テーブルに出荷情報を記録
2. **生産計画への反映** — 配送ラインの生産計画に割付数量を書き込む
3. **前工程への自動伝播** — 配送ラインの計画が、前工程の需要として自動的に全製造工程に波及
4. **在庫再計算** — 全ラインの在庫・計画を更新

**便計画を保存するだけで、前工程まで自動的に計画が連鎖する仕組み**になっています。

### 前工程の生産締切日

| 便 | 動き | 前工程の生産締切 |
|---|---|---|
| 2便・3便・5便（AM） | 当日出発 → 当日着 | 出発日の1営業日前 |
| 4便（PM） | 前日夕方出発 → 翌日着 | 出発日の2営業日前 |

---

## 7. 全体フロー

```
クボタ堺 確定/内示
    ↓
① 納期調整（現状: 営業 → あるべき姿: 生産側）
    受注数 → 納入数を決定
    ↓
② 便計画（業務/物流担当）
    納入数 → どの便に何台積むかを決定
    ↓
③ 生産計画への反映（自動）
    便割付の結果が前工程まで自動的に伝播
    ↓
④ 在庫再計算（自動）
    全ラインの在庫・計画を更新
```

---

## 8. 今後の改善方針

### 自動提案機能の導入

納期調整を「誰でもできる」ようにするため、システムによる**納入数の自動提案機能**を導入予定です。

**仕組み:**
1. 製品のAM/PMグループから生産締切日を自動判定
2. ラインの稼働時間とサイクルタイムから日産上限を自動計算
3. 納入数 = 受注数と日産上限の小さい方を自動提案
4. 残量がマイナスになる場合は警告表示
5. 警告解消するための前倒し調整

**担当者がやること:**
- 画面で「自動提案」ボタンを押す
- 提案された納入数を確認する
- 問題があれば（容器不足、部品不足など）手動で修正する
- 保存する
- 調整結果を関係者へ送信する

必要なデータはすべてシステムに揃っており、新たなデータ入力は不要ですが、以下の前提条件が必要です。

**前提条件:**
1. まとめ注文なし（顧客が日別に発注している）
2. 容器不足なし
3. 顧客の特殊要求なし（検査行き等）
4. 製品のAM/PMグループが固定されている
5. 生産側の各日生産時間が整備されている（ラインカレンダと稼働時間）
6. 各製品のサイクルタイムが明確になっている
