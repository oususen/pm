# PM 本番環境移行マニュアル

## 前提条件

- 本番PCにDockerがインストール済み
- 共通MySQLコンテナが起動済み（ネットワーク: `ts_pm_network_v2`）
- Gitがインストール済み

---

## 1. ソースコードの取得

### 方法A: Git clone（初回）

```bash
cd /path/to/apps
git clone <リポジトリURL> pm
cd pm
```

### 方法B: Git pull（更新時）

```bash
cd /path/to/pm
git pull origin main
```

---

## 2. 環境変数の設定

### 2.1 .envファイルの作成

```bash
cp .env.example .env
```

### 2.2 .envファイルを編集

```env
# Database設定
DB_HOST=mysql
DB_PORT=3306
DB_USER=root
DB_PASSWORD=実際のパスワード
DB_NAME=pm_db

# Django設定
DEBUG=False
SECRET_KEY=ランダムな文字列を生成して設定
ALLOWED_HOSTS=localhost,127.0.0.1,本番PCのIPアドレス
```

#### SECRET_KEY の生成方法

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(50))"
```

---

## 3. データベースの準備

### 3.1 Adminerでデータベース作成

1. ブラウザで `http://本番PC:8080` （Adminer）にアクセス
2. MySQLにログイン
3. 以下のSQLを実行:

```sql
CREATE DATABASE pm_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

### 3.2 既存データの移行（必要な場合）

開発環境からデータをエクスポート:

```bash
# 開発PC
mysqldump -u root -p pm_db > pm_db_backup.sql
```

本番環境にインポート:

```bash
# 本番PC（Adminerまたはコマンドライン）
mysql -u root -p pm_db < pm_db_backup.sql
```

## 6. トラブルシューティング

### コンテナが起動しない

```bash
# ログを確認
docker-compose logs pm-backend

# よくある原因:
# - DB接続エラー → .envのDB設定を確認
# - ポート競合 → 他のアプリとポートが被っていないか確認
```

### データベース接続エラー

```bash
# MySQLコンテナが起動しているか確認
docker ps | grep mysql

# ネットワーク確認
docker network ls | grep ts_pm_network_v2

# バックエンドコンテナからMySQLに接続できるか確認
docker exec -it pm_backend_prod python -c "
import MySQLdb
conn = MySQLdb.connect(host='mysql', user='root', password='パスワード', db='pm_db')
print('接続成功')
"
```

### 静的ファイルが表示されない

```bash
# 静的ファイルを再収集
docker exec -it pm_backend_prod python manage.py collectstatic --noinput
```

### マイグレーションエラー

```bash
# マイグレーション状態確認
docker exec -it pm_backend_prod python manage.py showmigrations

# マイグレーション実行
docker exec -it pm_backend_prod python manage.py migrate
```

## 7. 運用コマンド

### 再起動

```bash
# 全体
docker-compose restart

# バックエンドのみ
docker-compose restart pm-backend
```

### 停止

```bash
docker-compose down
```

### 更新（コード変更後）

```bash
git pull origin main
docker-compose up -d --build
```

### コンテナ内でコマンド実行

```bash
# Django shell
docker exec -it pm_backend_prod python manage.py shell

# スーパーユーザー作成
docker exec -it pm_backend_prod python manage.py createsuperuser
```

## 8. バックアップ

### データベースバックアップ

```bash
# バックアップ取得
docker exec mysql mysqldump -u root -pパスワード pm_db > backup_$(date +%Y%m%d).sql

# リストア
docker exec -i mysql mysql -u root -pパスワード pm_db < backup_20250115.sql
```

```bash
# pm_backend/media フォルダをバックアップ
tar -czvf media_backup_$(date +%Y%m%d).tar.gz pm_backend/media/
```

## 9. CORS/CSRF設定の更新

本番PCのIPアドレスを追加する場合、`pm_backend/project/settings.py` を編集:

```python
CORS_ALLOWED_ORIGINS = [
    # ... 既存の設定 ...
    "http://本番PCのIP:8501",
]

CSRF_TRUSTED_ORIGINS = [
    # ... 既存の設定 ...
    "http://本番PCのIP:8501",
]

ALLOWED_HOSTS = [
    # ... 既存の設定 ...
    "本番PCのIP",
]
```

編集後、再ビルド:

```bash
docker-compose up -d --build
```

## 10. 移行時の注意点（実績ベース）

### 10.1 日本語フォント問題

PDF生成機能で日本語が文字化けする場合、Dockerfileに日本語フォントが必要。
現在のDockerfileには以下のフォントがインストール済み:

- `fonts-ipafont-gothic` (IPA ゴシック)
- `fonts-takao-gothic` (Takao ゴシック)

### 10.2 ネットワーク構成

docker-compose.ymlでは2つのネットワークを使用:

| ネットワーク | 用途 |
|-------------|------|
| `pm_internal` | フロントエンド↔バックエンド間の内部通信 |
| `ts_pm_network_v2` | 共通MySQLコンテナへの接続（外部） |

### 10.3 本番IP設定

本番PCのIPアドレス（例: `10.0.1.232`）は以下に追加済み:

- `settings.py` の `ALLOWED_HOSTS`
- `settings.py` の `CORS_ALLOWED_ORIGINS`
- `settings.py` の `CSRF_TRUSTED_ORIGINS`

新しいIPで運用する場合は、上記3箇所すべてを更新すること。

### 10.4 HTTPS設定（PWA対応）

本番環境もHTTPSで運用（PWA対応のため）。

**アクセスURL**: `https://10.0.1.232:8501`

**SSL証明書**:
- 証明書ファイル: `pm-ui/certs/pm-prod.crt`
- 秘密鍵: `pm-ui/certs/pm-prod.key`
- CA証明書: `pm-ui/certs/pm-ca.crt`

**ブラウザでの警告回避**:
`pm-ca.crt` を「信頼されたルート証明機関」としてインポートする。

**証明書の再生成**（IPアドレス変更時）:
```bash
cd pm-ui/certs
# pm-prod.ext を編集してIP追加
bash generate-prod-cert.sh
```
