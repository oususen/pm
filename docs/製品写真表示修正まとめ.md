# 製品写真 保存・プレビュー表示 修正まとめ

## 概要

ブレーキ品入力画面（`/production/brake-line-input`）の製品写真が、撮影後に即時プレビューされない・次回開いたときに表示されない問題を修正した。

---

## 問題1: 撮影直後にプレビューが表示されない

### 原因
`onPhotoSelected` でサーバーへのアップロード完了後に `photoPreviewUrl` をセットしていたため、アップロード中はプレビューが空のままだった。

### 修正
`URL.createObjectURL(file)` でローカルのblobURLを即座にプレビューにセット（kaizen_ppのアプローチを参照）。アップロード完了後もblobURLを維持し、失敗時は元のURLに戻す。

**ファイル**: `pm-ui/src/views/production/BrakeLineInput.vue`

```javascript
// 選択直後にローカルプレビューを表示
let objectUrl = URL.createObjectURL(file)
photoPreviewUrl.value = objectUrl

// アップロード成功後はサーバーURLをitemに保存しblobURLを維持
selectedItem.value = { ...selectedItem.value, image_url: imageUrl }

// 失敗時はプレビューを元に戻す
URL.revokeObjectURL(objectUrl)
photoPreviewUrl.value = selectedItem.value?.image_url || ''
```

---

## 問題2: 次回開いたときに写真が表示されない（Mixed Content）

### 原因
`build_media_absolute_url` が `request.build_absolute_uri()` を使って絶対URLを生成していた。nginx リバースプロキシ経由では backend への通信が HTTP になるため、Django が `http://` のURLを返す。ブラウザは `https://` ページから `http://` 画像をロードしようとして **Mixed Content** としてブロックする。

### 修正
絶対URLへの変換をやめ、相対パス（`/media/products/xxx.jpg`）をそのまま返す。ブラウザが現在のオリジンで解決するため Mixed Content が起きない（kaizen_ppの `build_media_url` の設計を参照）。

**ファイル**: `pm_backend/apps/masters/views.py` / `pm_backend/apps/masters/serializers.py`

```python
def build_media_absolute_url(request, raw_url):
    if not raw_url:
        return raw_url
    path = str(raw_url)
    if path.startswith(('http://', 'https://')):
        return path
    # /で始まる相対パスはそのまま返す（ブラウザのオリジンで解決）
    if path.startswith('/'):
        return path
    # 相対パスの場合はMEDIA_URLを付与
    media_url = settings.MEDIA_URL.rstrip('/')
    return f"{media_url}/{path}"
```

## 問題3: `/media/media/` と二重になるバグ

### 原因
`default_storage.url()` が返す `/media/products/xxx.jpg` に対して、さらに `MEDIA_URL（/media/）` を付与していたため `/media/media/products/xxx.jpg` になっていた。

### 修正
パスが `/` で始まる場合はそのまま返す（上記の修正で同時に解消）。

---

## 問題4: 開発環境で404（DEBUG=False）

### 原因
`.env` に `DEBUG=False` が設定されていたため、`urls.py` の `if settings.DEBUG:` 条件が False になり、Django が `/media/` URLパターンを登録しなかった。

### 修正
開発環境の `.env` を修正。

**ファイル**: `pm_backend/.env`

```env
DEBUG=True
ALLOWED_HOSTS=localhost,127.0.0.1,192.168.0.15,10.0.1.194
```

> **注意**: 本番デプロイ時は `DEBUG=False` に戻すこと。本番環境では nginx が `/media/` を直接配信するため Django の設定不要。

---

## 本番環境での動作フロー

```
ブラウザ (https://10.0.1.232:8501)
  ↓ GET /media/products/xxx.jpg
nginx (port 8501)
  ↓ /media/ → /app/media/ (直接配信)
  → ファイル返却 ✅
```

## 開発環境での動作フロー

```
ブラウザ (http://10.0.1.194:8501)
  ↓ GET /media/products/xxx.jpg
Vite dev server (port 8501)
  ↓ proxy /media → http://localhost:8081
Django (port 8081, DEBUG=True)
  ↓ static() URLパターンで配信
  → ファイル返却 ✅
```

## 追加設定

### sys.path 設定（kaizen_ppパターンを適用）

**ファイル**: `pm_backend/project/settings.py`

```python
import sys
BASE_DIR = Path(__file__).resolve().parent.parent
ROOT_DIR = BASE_DIR.parent

if str(BASE_DIR) not in sys.path:
    sys.path.insert(0, str(BASE_DIR))
if str(ROOT_DIR) not in sys.path:
    sys.path.insert(0, str(ROOT_DIR))
```

ルートの `config.py` 等を import できるようにパスを追加。

### SECURE_PROXY_SSL_HEADER 設定

**ファイル**: `pm_backend/project/settings.py`

```python
SECURE_PROXY_SSL_HEADER = ('HTTP_X_FORWARDED_PROTO', 'https')
```

nginx が `X-Forwarded-Proto: https` を送る場合に Django が HTTPS を認識できるようにする。開発環境（直接8081接続）では影響なし。
