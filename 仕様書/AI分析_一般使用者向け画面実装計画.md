# AI分析 一般使用者向け画面 実装計画

作成日: 2026-10-18。作成元: BOSSとClaude Codeの計画セッション（本計画はClaude Codeが計画・整理したもの。実装はCodexが行う。2-C以降の役割分担はBOSS指示どおり、Claude Codeは実装後の読み取りレビューのみ）。

正式な仕様書は`AI分析基盤仕様書.md`。本計画は、一般使用者向け新画面の追加に関する要求・決定事項を整理したもので、実装後はCodexがこの計画書に進捗・検証結果・未完了事項・開発／本番の反映状況を追記すること（コード追加だけで検証完了・本番完了と扱わない）。

## 1. 目的

現在の`/ai/chat`（`AIAnalysis.vue`）は、送信文（AIへの送信内容・外部送信プレビュー）や生成されたSQL/Pythonの生テキストを表示する、技術的な画面になっている。BOSS（システム管理者）はこのまま使うが、一般使用者には不要な情報が多く窮屈でもあるため、一般使用者向けに別の画面を新設する。

## 2. 対象範囲

### 2.1 現状維持（変更しない）

- `/ai/chat`・`AIAnalysis.vue`・`AIAnalysisConsult.vue`・`AIAnalysisExecution.vue`・`AIAnalysisTemplates.vue`は、BOSS（システム管理者）専用としてそのまま残す。送信文表示・生コード表示・テンプレート管理機能を含め、既存の挙動・レイアウトを変更しない。
- アクセス権限（`ai.chat`・`ai.analysis`リソース）の定義は変更しない。

### 2.2 新規作成

一般使用者向けの新しい画面（新コンポーネント・新ルート。名称・パスはCodexの実装時に決めてよいが、既存の`/ai/chat`とは別パスにすること）。

## 3. 新画面の仕様

### 3.1 アクセス権限

- 既存の`ai.chat`権限（`hasPermission(user, 'ai.chat', ...)`想定）をそのまま使う。新しい権限区分（リソース）は作らない。

### 3.2 レイアウト（BOSS承認済み）

- チャット風レイアウト。会話スペース（「AIと目的を整える」相当の相談チャット）を広く確保する。
  - 現状の`AIAnalysisConsult.vue`は入力欄`rows="2"`・会話ログ`max-height: 220px`で窮屈。新画面では、相談の入力欄・会話ログを十分な高さで表示すること（具体的な数値はCodexの実装時の判断でよいが、現状より明確に広げること）。
- 成果物（分析案の目的・手順・出力案、テンプレート推薦、分析結果等）は画面右側に配置し、クリックで展開する構成にする（Claude Codeのチャット画面のような、左右分割＋右側パネル展開のイメージ）。

### 3.3 一般使用者ができること

- 新規分析の作成：AIへの目的相談 → 分析案作成 → コード生成 → 実行、という既存の一連の流れを一般使用者もできるようにする。
- 既存テンプレートの利用（`useTemplate`相当）。
- 分析をテンプレートとして保存。

### 3.4 一般使用者画面で隠すもの

- 送信文：社外送信前プレビュー（`externalPreview`相当）、実行履歴内の「送信文」表示（`AIAnalysisExecution.vue`の`送信文 {index}（{role}）`表示相当）を、一般使用者画面には出さない。
- 生成されたSQL/Pythonの生テキスト（コード生成結果の`codegen.sql`・`codegen.python`相当の表示）を、一般使用者画面には出さない。

### 3.5 承認の分担

- **コード実行の承認**：一般使用者本人が行う。
  - 判断材料は、コード生成前に既に表示・承認済みの「分析案」の説明（目的・手順・出力案。`plan.proposal.purpose`・`plan.proposal.steps`・`plan.proposal.outputs`相当）を、コード生成後の承認時にそのまま再表示する。コードの内容を新たにAIへ言語化させる機能は**追加しない**（BOSS決定：既存の分析案説明の再利用のみ）。
  - 既存の「コードに固定値が直接書かれている」等の警告（`codegen.literal_values`等）は、一般使用者にも分かる表現であれば表示してよい（生コードそのものは出さない）。
- **テンプレートの正式承認**（`pending_admin`の解除、管理者承認）：BOSSが行う。既存の管理者承認フロー（`AIAnalysisTemplates.vue`の管理者承認画面）は変更しない。一般使用者はテンプレートを保存できるが、正式テンプレートとして他者が使えるようになるのはBOSS承認後（既存のまま）。

### 3.6 AIプロバイダ・モデル選択

- 一般使用者画面にも出す（現状の`AIAnalysis.vue`ヘッダーのプロバイダ・モデル選択と同様）。社外サービス選択時の送信了承チェックも維持する。

### 3.7 システム管理者への質問・失敗報告（新規）

既存の「システム管理者へリクエスト」機能（`RequestDialog.vue`・`openRequestDialog()`・バックエンド`UserRequestTask`モデル・`UserRequestTaskDialog.vue`・`TaskInbox.vue`）をそのまま活用する。新しいバックエンドの仕組みは作らない。

- 一般使用者画面に「システム管理者へ質問する」ボタンを常時表示する。BOSSはAIとシステム管理者本人との会話内だけの呼称とし、社内利用者向けUIには表示しない。
- 分析が失敗したとき（コード生成の失敗・実行の失敗等）は、リクエスト送信を自動で提案する（強制はしない。失敗時に目立つ形で「うまくいかないときはシステム管理者へ相談できます」のような案内＋ボタンを出す）。
- リクエストダイアログを開く際、件名・内容欄に、今の分析の情報を事前入力する。
  - 内容欄には、現在の目的文（`purpose`）を**そのまま（要約・加工せず）**含めること。
  - 加えて、分かる範囲でエラー内容・どの段階で失敗したか等の文脈情報を含めること。
  - 事前入力後も、本人が書き足し・編集できること（既存の`RequestDialog.vue`の入力欄は編集可能なテキストのまま）。
- 実装上の変更点：現在の`openRequestDialog()`（`src/composables/requestDialog.js`）は引数なしで呼ばれ、`RequestDialog.vue`内部の`subject`・`body`は空で初期化される。事前入力に対応するため、`openRequestDialog({ subject, body })`のように初期値を渡せるよう拡張し、`RequestDialog.vue`側もその初期値を受け取って反映すること。既存の呼び出し元（`AIFloatingButton.vue`等、引数なしで呼んでいる箇所）の動作は変えないこと。

## 4. 明示的に対象外（今回は扱わない）

- コード実行承認の材料として、AIに新たな言語化（コード内容の平易な説明）をさせる機能（将来必要になれば別途計画する）。
- 一般使用者向けの新しいアクセス権限区分の追加（既存`ai.chat`を使う）。
- `AIAnalysis.vue`（BOSS専用画面）側の変更。

## 5. Codexへの依頼時の留意点（CLAUDE.md規約より）

- 日時取得は`datetime.now()`を使うこと（`timezone.now()`等は使用禁止。本プロジェクトは`USE_TZ=False`）。
- 新規の上限値（取得件数・ページサイズ等）を設ける場合は、実装前にBOSSへ確認すること。
- フォールバックの新規追加は、実装前にBOSSの同意を得ること。
- 実装後、本計画書に進捗・検証結果・未完了事項・開発／本番の反映状況を追記すること。

## 6. 進捗・検証結果

### 6.1 実装進捗（2026-10-18）

- 実装済み
  - 一般使用者向け画面を`AIAnalysisUser.vue`として新設し、専用ルート`/ai/analysis`を追加した。
  - 管理者向け`/ai/chat`には「検索」「分析」「分析（一般）」の3タブを設け、新画面を「分析（一般）」へ割り当てた。既存の`AIAnalysis.vue`は「分析」タブのまま変更していない。
  - 一般向けの相談・実行・テンプレート表示を専用コンポーネントへ分離し、会話ログと入力欄を拡大した。
  - 成果物・分析結果・テンプレートを右側の展開領域へ配置した。狭い画面では縦並びに切り替わる。
  - 一般向け画面では、社外送信前プレビューの送信文、相談時の置換後送信文、生成SQL/Python、実行履歴のコードハッシュ・実行設定を表示しない。
  - コード承認時は、生コードの代わりに承認済み分析案の目的・手順・出力案を再表示する。
  - 既存のAIプロバイダ・モデル選択、社外サービス利用了承、分析案作成・承認、コード生成・安全確認・承認・実行、テンプレート利用・保存のAPIフローを再利用した。
  - `openRequestDialog({ subject, body, requestType })`を追加し、既存の引数なし呼び出しを維持した。一般向け画面の常設ボタンと生成・実行失敗時の案内から、現在の目的文を加工せず含む問い合わせを開ける。
  - 一般画面の入口は`ai.chat`権限、既存分析APIの操作可否は従来どおり`ai.analysis`権限を使用する。管理者向け`/ai/chat`は`settings.ai`編集権限に限定した。

### 6.2 検証結果

- `npm run build`: 合格（Vite本番ビルド完了）。既存のチャンクサイズ警告のみで、ビルドエラーなし。
- `git diff --check`: 合格（空白エラーなし）。
- 一般向け4コンポーネントを静的検索し、SQL問い合わせ・Python本文・SQL/Pythonハッシュ・置換後送信文を描画する記述がないことを確認した。
- `npm run check:date-utc`: リポジトリ既存の別画面12ファイルで違反を検出して不合格。今回の変更ファイルには検出なし（既存違反は本実装の対象外で変更していない）。
- 実装者とは別の読み取り専用評価: 合格。3タブ、権限、右側成果物、送信文・生コード非表示、実行前承認、テンプレート、システム管理者への質問初期値を差分と行番号で再確認した。
- バックエンド、DBモデル、マイグレーション、取得件数・ページサイズ等の上限値、フォールバックは変更していない。

### 6.3 未完了事項・反映状況

- 開発コードへの実装: 完了。
- 開発環境での実ユーザー権限・実AIプロバイダを使った画面操作確認: 未実施。
- 本番反映: 未実施（コミット・push・デプロイは行っていない）。

### 6.4 左右ペイン幅変更（2026-10-18）

- PC表示（画面幅960px超）の「分析（一般）」画面で、相談欄と成果物欄の境界をドラッグして幅を変更できるようにした。
- 画面全体の最大幅制限を撤廃し、利用可能な横幅を全面利用する。外側の余白は20pxを維持する。
- 初期状態は左側66.7%で、左側35〜75%の範囲に制限する。変更した比率は画面内だけで保持し、再読み込み時には初期値へ戻る。
- 境界はキーボード操作にも対応し、左右矢印キーで2%ずつ変更できる。支援技術向けに区切りであること、向き、現在値、最小値、最大値を通知する。
- Pointer Eventsとポインターキャプチャを使用し、キャンセル時・画面破棄時にもドラッグ状態と文字選択禁止を解除する。
- 評価で確認された複数ポインターの同時押下に対応し、ドラッグ中の追加押下では最初のポインター捕捉と復元用状態を上書きしない。
- 画面幅960px以下では従来どおり縦並びとし、ドラッグ境界を表示しない。
- 検証結果: `npm run build`は合格（既存のチャンクサイズ警告のみ）、`git diff --check`は合格（空白エラーなし）。
- 開発コードへの反映: 実装済み。開発環境での実ドラッグ・キーボード操作確認、本番反映: 未実施。

### 6.5 分析処理の再生成導線（2026-10-18）

- 分析処理が未作成の場合は、従来どおり社外送信確認またはローカル生成の操作を表示する。
- 分析処理が作成済みの場合、通常は「分析処理を作り直す」だけを表示し、押したときだけ社外送信確認・再生成操作と「作り直しをやめる」を表示する。
- 再生成欄の開閉ではAPIを呼ばず、現在のコード・試行結果・コード承認を変更しない。分析案の変更時または編集権限を失ったときは再生成欄を閉じる。
- テンプレートから作成した分析案は、従来どおりAIによる再生成を行えない。
- `generateCode`と分析APIの処理は変更していない。
- 検証結果: `npm run build`は合格（既存のチャンクサイズ警告のみ）、`git diff --check`は合格（空白エラーなし）。

### 6.6 社外送信する目的文の確認導線（2026-10-18）

- 「社外送信する目的文を確認」は、社外AIを選択し、確認内容をまだ取得していない場合だけ表示する。
- 確認内容の取得後はボタンを隠す。目的・期間・AIプロバイダ・モデル等を変更して既存の確認内容が破棄された場合は、再度表示する。
- 確認内容の取得中は、従来どおり「目的文を確認中…」を無効状態で表示する。
- API・DB・社外送信確認処理は変更していない。
- 検証結果: `npm run build`は合格（既存のチャンクサイズ警告のみ）、`git diff --check`は合格（空白エラーなし）。

### 6.7 対象件数の確認導線（2026-10-18）

- データ範囲の承認待ちで、対象件数をまだ取得していない場合だけ「対象件数を確認」を表示する。
- 件数確認中は従来どおり「件数を確認中…」を無効状態で表示し、取得後は確認ボタンを隠して件数・確認日時を表示する。
- 件数取得後も「データ範囲を承認」は表示し、上限超過時を除いて操作できる。目的・期間を変更する場合は既存の「目的・期間を変更して作り直す」を使用する。
- API・DB・対象件数の確認処理は変更していない。
- 検証結果: `npm run build`は合格（既存のチャンクサイズ警告のみ）、`git diff --check`は合格（空白エラーなし）。
