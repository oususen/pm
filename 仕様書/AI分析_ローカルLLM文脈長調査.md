# AI分析 ローカルLLMの文脈長の調査

調査日: 2026-10-09 / 状態: **文字数の実測まで完了(トークン数の実測は未実施)** / 依頼: BOSS(「AIがだんだん賢くなる」計画の②)
関連: `仕様書/AI分析_結果の記録実装計画.md` 第0章、`仕様書/AI分析基盤仕様書.md` 5.3-3・5.3-11

## 1. 目的

ローカルLLM(Qwen)で、AI分析(分析案の作成・コード生成・参考にした生成)を使うために、文脈長の制約を、確認する。将来は、ローカルLLMだけにする方針のため、これが解決しないと、お手本(参考にした生成)が、ローカルで、使えない。

## 2. 現状の設定(コードの読み取り)

- `chat_service._ollama_chat`(`chat_service.py`)は、Ollamaへ、`num_ctx: 4096`・`num_predict: AGENT_MAX_TOKENS(4096)`を渡す。
- `num_ctx`は、**入力(プロンプト)と出力(返答)を合わせた、全体の窓**。`num_predict`が`num_ctx`と同じ4096なので、入力が、1トークンでもあると、返答の上限まで書くと、窓を超える。
- Ollamaは、窓を超えるとき、古い側(先頭)のトークンを捨てて続ける(文脈の移動)。**先頭にある、system指示(規則)が、切り捨てられる**恐れがある。サーバー(PM)は、切り捨てを検出しない(仕様書5.3-3の既知の制約)。
- 既定のモデル: `qwen3:4b-instruct`(`OLLAMA_MODEL`)。評価では、Qwen3 14B(OpenRouter経由)を、最良の候補としていた(将来、16GBのGPUに載せる想定)。

## 4. 分かったこと

1. **分析案の作成**: 入力が、約0.9〜2.0千トークン。返答(分析案のJSON、数百トークン)を含めても、`num_ctx=4096`に、収まる可能性が高い。
2. **コード生成**: 入力だけで、約3.4〜7.6千トークン。**`num_ctx=4096`を、超える可能性が高い**(推定の下限でも、返答の余地が少ない)。超えると、system指示の先頭(基本の規則)が、切り捨てられ、規則を守れなくなる。ローカルQwenのコード生成が、不安定な原因の1つの可能性がある(未検証)。
3. **参考にした生成(段階B)**: コード生成の入力に、参考のテンプレート(約1,000〜2,000字)が加わる。`num_ctx=4096`では、確実に足りない。外部AIだけに限定しているのは、この理由。
4. コード生成のsystem指示(8,660字)は、規則・見本のJSONの積み重ねで、長くなった。**半分近くが、特定の分析(期間の比較・複数の品番・2つのビューの比較)の見本**で、毎回送る必要がない。

## 5. 対策の案(承認が必要なものを含む)

| # | 対策 | 内容 | 承認 |
|---|---|---|---|
| A | **実測** | Ollamaを起動し、実際の文面で、`prompt_eval_count`(入力のトークン数)と、切り捨ての有無を測る。**今は、Ollamaが起動していないため、未実施** | 不要(読み取り) |
| B | **指示文の必要な部分だけを送る** | 目的の言葉(「比べる」「月別」「複数の品番」など)から、機械的に、必要な見本・規則だけを、選んで送る(AIは使わない)。期間の比較の見本は、比較の目的のときだけ、など。入力を、半分以下にできる見込み | 指示文の構成の変更なので、BOSS承認(評価と実機の試験が必要) |
| C | **指示文の整理** | 重複・冗長な規則を、短くする(意味を変えない) | BOSS承認(試験が必要) |
| D | **`num_ctx`を引き上げる** | 8192、16384など。VRAMの使用量が増える(モデルの大きさ・KVキャッシュ)。購入予定のPC(RTX 5060 Ti 16GB)で、14Bモデルを、どの文脈長まで載せられるかを、実測で決める | **BOSS承認が必要**(仕様書5.3-3) |
| E | **`num_predict`の見直し** | 返答の上限(4096)は、窓全体と同じ。窓に合わせた値にする | BOSS承認(上限値の変更) |
| F | **検出** | 入力が、窓を超えそうなときに、実行前に、警告・停止する(切り捨てを、無言で許さない) | 上限値(閾値)の新設に当たるため、BOSS承認 |

## 6. 推奨の順序

1. **A(実測)**: Ollamaを起動できる状態にして、実測する。実測の結果で、他の対策の要否が決まる。
2. **B(必要な部分だけを送る)**: 効果が大きく、窓の拡大に、頼らず、ローカルで、使える。評価・実機の試験が必要。
3. **D(`num_ctx`の引き上げ)**: Bの後に、必要な分だけ。VRAMの実測と合わせる。
4. F・Eは、BとDの結果を見て、決める。
