# システム管理者リクエスト仕様書

## 目的

アプリ利用者が、要望・不具合・問い合わせをシステム管理者へメールで送る。画面右下の「Q&A」→「2 リクエスト」から開く。

## システム管理者の定義

- `accounts_userprofile.is_system_admin`（真偽値、既定: False）が True のユーザーを「システム管理者」とする。
- ユーザー管理・権限管理画面の「システム管理者」チェックボックスで設定する。変更できるのは `is_superuser` のユーザーだけで、それ以外が送った値はサーバーが無視する。
- 役割（`role`）・部署・権限とは無関係で、複数人に付けられる。

## 送信方式

- 送信時に、メール送信とあわせて、システム管理者向けのタスク（`notifications_user_request_task`、下記）を **共通の1件** 作る。メール送信が失敗した場合は、タスクも作らない（同一トランザクション）。
- 添付ファイル・画面URLは保存しない（メールにだけ残る）。
- 送信先: `is_system_admin=True` かつ有効（`is_active`）かつメールアドレス（`auth_user.email`）が登録済みのユーザー全員。該当者がいない場合は送信せず、エラーを返す（代替の宛先は使わない）。
- 送信元・SMTP設定: 既存の `EmailService`（`shipping/services/email_service.py`）を使う。送信者本人の `UserSmtpConfig`、なければ `is_admin=True` の共通設定。
- 件名: `[PMリクエスト] 種別: 件名`。`Reply-To` は依頼者のメールアドレス。
- 本文: 種別、依頼者（氏名・ユーザー名・社員コード）、依頼者メール、画面URL、添付ファイル名、内容。

## API

`POST /api/user-requests/`（`multipart/form-data`、ログイン必須）

| 項目 | 内容 |
|---|---|
| `request_type` | `request`（要望）／`bug`（不具合）／`question`（問い合わせ）／`other`（その他） |
| `subject` | 件名（必須） |
| `body` | 内容（必須） |
| `page_url` | 送信時の画面URL（任意） |
| `files` | 添付ファイル（任意、複数） |

エラー: 400（入力不備・添付の制限超過・形式不可・送信先なし）、502（メール送信失敗）。

## タスク（`notifications_user_request_task`）

システム管理者全員で共有する1件のタスク。タスク受信箱（`/tasks`）に、業務「リクエスト」として **システム管理者にだけ** 表示する。

| 項目 | 内容 |
|---|---|
| `request_type` | 種類（要望／不具合／問い合わせ／その他） |
| `subject` | 件名（200文字まで） |
| `body` | 内容 |
| `requester` | 依頼者（ユーザーID。ユーザー削除時は NULL） |
| `status` | 状況: `PENDING`（未対応）／`IN_PROGRESS`（対応中）／`DONE`（完了）／`REJECTED`（却下） |
| `reject_reason` | 却下理由（却下のときだけ保持。それ以外では空） |
| `handled_by` / `handled_at` | 最終対応者・最終対応日時（状況を変更したとき `datetime.now()` で記録） |
| `created_at` | 作成日時 |

- タスクは削除するまで保存する。自動削除はしない。
- 状況の変更・削除は、システム管理者なら誰でもできる（担当者の割り当てはない）。
- 却下するときは、却下理由が必須。却下にした時点で、依頼者（`auth_user.email`）へ返信メール（件名 `[PMリクエスト] 却下: 件名`、本文に種別・件名・却下理由・対応者）を、対応者のSMTP設定で送る。返信メールの送信に失敗した場合は、状況を変更しない。依頼者のメールアドレスが未登録（または依頼者が削除済み）の場合は、却下を保存し、画面に警告を表示する。すでに却下のタスクを再度保存しても、返信メールは再送しない。
- 完了・対応中への変更では、依頼者へのメールは送らない。

### タスクAPI（いずれもシステム管理者のみ。それ以外は403）

| API | 内容 |
|---|---|
| `GET /api/user-requests/tasks/` | タスク一覧（新しい順。`?status=` で絞り込み） |
| `PATCH /api/user-requests/tasks/<id>/` | `status`（必須）と `reject_reason`（却下のとき必須）で状況を変更 |
| `DELETE /api/user-requests/tasks/<id>/` | 削除 |

## リクエスト履歴（全ユーザー）

重複リクエストを避けるため、ログイン済みの全ユーザーが、全員のリクエストを閲覧できる（Q&Aメニューの「リクエスト履歴」）。

- `GET /api/user-requests/history/?requester=<ユーザーID>&status=<状況>&q=<キーワード>`（読み取りのみ）
- 絞り込み: 依頼者、状態、キーワード（件名・内容の部分一致）。最新200件まで。応答には、依頼実績のある依頼者の一覧（`requesters`）も含める。
- 全員に見せる項目: 送信日時、種類、件名、内容、依頼者名、状況。
- **見せない項目**: 却下理由、対応者（最終対応者・最終対応日時）、依頼者のメールアドレス。
- 送信画面（`RequestDialog.vue`）に、送信した内容が全員に表示される旨と、個人情報を書かない旨を表示する。
- リクエスト送信画面とリクエスト履歴画面のヘッダには、×の右に「?」を置く。押すと `/manual?path=共通/リクエスト.md` を別タブで開く（フロントエンドのみ。API・DBは変更しない）。
- システム管理者がタスクを削除すると、履歴からも消える。
- 依頼者による取り消し・追記は行わない（やり取りが必要になる場合は、別途リクエストチャットとして検討する）。

## 添付ファイル

- メールの添付として送る。サーバーには保存しない。
- 最大5個、1ファイル10MBまで、合計20MBまで。
- 対応形式（拡張子で判定）: 画像（`.png` `.jpg` `.jpeg` `.gif` `.webp`）、Excel（`.xlsx` `.xlsm` `.xls`）、Word（`.docx` `.doc`）、PDF、CSV、テキスト（`.txt`）。
- 上記以外（実行ファイル・スクリプト・ZIPなど）は受け付けない。
- ファイル名は、制御文字とパス区切りを除いてから、RFC 2231形式でメールに付ける。
- 画面では、画像はサムネイル、書類はファイル名とサイズを表示する。本文欄で Ctrl+V をすると、クリップボードの画像（スクリーンショット）を添付できる。
