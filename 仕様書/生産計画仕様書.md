# 生産計画機能仕様書

## 概要

ライン別に製品の生産計画を立案・管理する機能。
1日に複数ロット（順序）の計画を登録可能で、後工程需要を取り込み、工程展開と在庫計算を自動実行する。

## 関連テーブル

### LinePlan（ライン別生産計画）

ユーザーが入力した生産計画を保持するテーブル。

| フィールド名 | 型 | 説明 |
|------------|-----|------|
| plan_date | DATE | 計画日 |
| process | FK | 工程 |
| product | FK | 製品 |
| line | FK | ライン |
| plan_qty | INT | 計画生産数 |
| sequence_no | INT | 順序番号（同日内のロット順序） |
| plan_id | VARCHAR | 計画ID（自動生成） |
| created_at | DATETIME | 作成日時 |
| updated_at | DATETIME | 更新日時 |

#### 制約

- `unique_together`: `(plan_date, line, sequence_no)`
  - 同じライン・同じ日・同じ順序番号は重複不可
- `indexes`: `(plan_date, line)`
  - 日付・ライン検索の高速化

### LineBacklog（ライン別バックログ）

生産計画と在庫情報を保持するメインテーブル（LinePlanから展開される）。

| フィールド名 | 型 | 説明 |
|------------|-----|------|
| plan_date | DATE | 計画日 |
| process | FK | 工程 |
| product | FK | 製品 |
| line | FK | ライン |
| order_qty | INT | 後工程需要（内示/計画） |
| plan_qty | INT | 計画生産数 |
| actual_qty | INT | 実績生産数 |
| stock_qty | INT | 実在庫 |
| planned_stock_qty | INT | 計画在庫 |
| adjust_qty | INT | 調整数 |
| scrap_qty | INT | 仕損数 |
| actual_shipment_qty | INT | 実績出庫数 |
| sequence_no | INT | 順序番号 |
| plan_id | VARCHAR | 計画ID |

## 計画ID（plan_id）の生成ルール

計画を一意に識別するためのID。

### 生成形式

```
{product_code}_{YYYYMMDD}_{qty_label}_{sequence_no}
```

### 構成要素

- `product_code`: 製品コード
- `YYYYMMDD`: 計画日（8桁）
- `qty_label`: 計画数量のラベル
  - 小数点がある場合は `.` を `p` に置換（例: `10.5` → `10p5`）
  - 末尾の `0` と `.` は削除（例: `10.0` → `10`）
- `sequence_no`: 順序番号

### 例

| 製品コード | 計画日 | 計画数量 | 順序番号 | 生成されるplan_id |
|----------|--------|---------|---------|-----------------|
| ABC123 | 2025-01-15 | 100 | 1 | ABC123_20250115_100_1 |
| ABC123 | 2025-01-15 | 50 | 2 | ABC123_20250115_50_2 |
| XYZ789 | 2025-01-16 | 10.5 | 1 | XYZ789_20250116_10p5_1 |

## 主要な機能

### 1. 生産計画の取り込み（pickup）

後工程の計画情報をLineBacklogに反映。

#### 処理フロー

1. `LineBacklog.pickup()` APIを呼び出し
   - 後工程のLinePlanから前工程への需要を計算
   - LineBacklogに`order_qty`として反映
2. 在庫再計算APIを実行
   - 実在庫・計画在庫を更新

#### APIエンドポイント

```
POST /api/line-backlogs/pickup/
```

**リクエスト**:
```json
{
  "line_id": 8,
  "start_date": "2025-01-01",
  "end_date": "2025-01-31"
}
```

**レスポンス**:
```json
{
  "detail": "Pickup completed successfully"
}
```

### 2. 生産計画の保存（save）

ユーザー入力した計画データをLinePlanに保存。

#### 処理フロー

1. フロントエンドから計画データを送信
   - ライン別・製品別・日別・ロット別のデータ
2. バックエンドでバリデーション
   - product_id, process_id, plan_date, sequence_noが必須
   - plan_qty ≤ 0の場合は削除処理
   - sequence_no重複チェック（同日・同ライン内）
3. LinePlanにupsert（作成または更新）
4. 工程展開（expand_processes）を実行
5. 在庫再計算を実行
6. 工程ガント計画（LineGanttPlan）を再生成

#### APIエンドポイント

```
POST /api/line-plans/save/
```

**リクエスト**:
```json
{
  "line_id": 8,
  "items": [
    {
      "product_id": 123,
      "process_id": 5,
      "plan_date": "2025-01-15",
      "plan_qty": 100,
      "sequence_no": 1
    },
    {
      "product_id": 123,
      "process_id": 5,
      "plan_date": "2025-01-15",
      "plan_qty": 50,
      "sequence_no": 2
    }
  ]
}
```

**レスポンス**:
```json
{
  "created": 2,
  "updated": 0,
  "deleted": 0,
  "skipped": []
}
```

#### バリデーションルール

1. **必須フィールド**
   - `product_id`, `process_id`, `plan_date`, `sequence_no`

2. **数量チェック**
   - `plan_qty ≤ 0`: 該当レコードを削除
   - `plan_qty > 0`: 作成または更新

3. **順序番号重複チェック**
   - 同じライン・同じ日に同じsequence_noが存在する場合はエラー
   - ただし、同じproduct_id + process_idの組み合わせは更新可能

4. **製品存在チェック**
   - product_idが存在しない場合はスキップ

### 3. 工程展開（expand_processes）

LinePlanのライン最終品計画を、BOMに従って前工程に展開。

#### 処理フロー

1. ライン最終品（`is_line_final_product = true`）のLinePlanを取得
2. BOMを参照して前工程製品と必要数量を計算
3. LineBacklogに展開結果を保存
   - `plan_qty`, `plan_id`, `sequence_no`を設定

#### APIエンドポイント

```
POST /api/line-backlogs/expand_processes/
```

**リクエスト**:
```json
{
  "line_id": 8,
  "start_date": "2025-01-01",
  "end_date": "2025-01-31",
  "read_only": false,
  "include_coproduct_children": true
}
```

**レスポンス**:
```json
{
  "detail": "Processes expanded successfully"
}
```

### 4. 在庫再計算（recalculate_inventory）

実在庫と計画在庫を再計算。詳細は[在庫計算仕様書](./在庫計算仕様書.md)を参照。

#### APIエンドポイント

```
POST /api/line-backlogs/recalculate_inventory/
```

### 5. 工程ガント計画生成（generate）

LinePlanから工程別の時間軸計画（LineGanttPlan）を生成。

#### 処理フロー

1. ライン最終品のLinePlanを取得
2. 工程別の所要時間を計算
   - 製品ごとのサイクルタイム × 計画数量
3. 勤務時間カレンダーに基づいて工程開始・終了時刻を決定
4. LineGanttPlanに保存

#### APIエンドポイント

```
POST /api/line-gantt-plans/generate/
```

**リクエスト**:
```json
{
  "line_id": 8,
  "start_date": "2025-01-01",
  "end_date": "2025-01-31",
  "clear_existing": true
}
```

**レスポンス**:
```json
{
  "detail": "Gantt plans generated successfully"
}
```

## フロントエンド仕様

### 生産計画入力画面（ProductionPlanInput.vue）

#### 画面構成

1. **ツールバー**
   - 処理区分: 生産計画 / 実績
   - ライン選択
   - 表示開始日
   - 期間: 30日 / 60日 / 90日
   - 検索（品番/品名）

2. **グリッド表示**
   - 固定列: No / 品番 / 品名
   - 日別列（各日6列）:
     - 需要: 後工程需要
     - 実績: 実績生産数
     - 在庫: 実在庫
     - 計画: 計画生産数（入力可能）
     - 順序: 順序番号（入力可能）
     - 計画在庫: 計画在庫

3. **ボタン**
   - 新規行追加: 空行を追加
   - クリア: 全行削除
   - 保存: 計画データをサーバーに保存
   - 取り込み: 後工程需要を取り込み
   - 工程ガント表示: 工程ガント計画を表示
   - 工程負荷表示: 工程別負荷を表示

#### グリッド操作

##### セル移動

- **Enter**: 下セルに移動（Shift+Enterで上セルに移動）
- **矢印キー**: 上下左右のセルに移動
- **Tab**: 次のフィールド（計画→順序）に移動

##### 複数ロット入力

1. 計画セル内の「+」ボタンをクリック
2. 追加ロットの入力欄が表示される
3. ロットごとに計画数量と順序番号を入力
4. 「x」ボタンでロットを削除

**注意**:
- 最初の行は常にメインロット
- 追加ロットは2番目以降のロット
- 順序番号は昇順で採番推奨

##### 行の並び替え

- No列の「↑」「↓」ボタンで行を移動
- 並び順は製品の表示順序のみに影響（保存データには影響なし）

#### 表示ルール

##### 数値表示

- **0値**: 空白表示
- **プラス値**: 通常表示（カンマ区切り）
- **マイナス値**: 赤背景、赤文字、太字で強調

##### 在庫表示の特殊ルール

LineBacklogが存在しない日（`has_row = false`）は、直前の在庫値を引き継いで表示。

**例**:
| 日付 | has_row | 在庫（DBの値） | 画面表示 |
|------|---------|--------------|---------|
| 1/10 | true | 100 | 100 |
| 1/11 | false | 0 | 100（1/10の値を引き継ぎ） |
| 1/12 | false | 0 | 100（1/10の値を引き継ぎ） |
| 1/13 | true | 120 | 120 |

#### 取り込み処理の流れ

1. **pickup API**呼び出し
   - 後工程計画からorder_qtyを算出してLineBacklogに反映

2. **recalculateInventory API**呼び出し
   - 在庫・計画在庫を再計算

3. **LineBacklogとLinePlanを取得**
   - `line-backlogs`: 需要、実績、在庫データ
   - `line-plans`: 計画数量、順序番号

4. **グリッドデータの組み立て**
   - ライン最終品（`is_line_final_product = true`）のみを対象
   - 製品ごとに1行を作成
   - 日別に需要・実績・在庫・計画・順序を設定
   - 複数ロット（sequence_no順）を展開

5. **画面表示**
   - グリッドにデータを反映
   - 0値は空白表示

#### 保存処理の流れ

1. **バリデーション**
   - ラインが選択されているか確認
   - product_idとprocess_idが存在するか確認

2. **保存データの作成**
   - 各行の日別データをループ
   - メインロットと追加ロット（extraLots）を配列に変換
   - plan_qtyとsequence_noがnullの行はスキップ

3. **save API**呼び出し
   - LinePlanに保存
   - 作成/更新/削除件数を返却

4. **後続処理の実行**
   - **expand_processes**: 工程展開
   - **recalculateInventory**: 在庫再計算
   - **generate**: 工程ガント再生成

5. **画面更新**
   - 工程ガントを再読み込み
   - 工程負荷を再計算（表示中の場合）

#### 工程ガント表示

生産計画の時間軸シミュレーション。

- **表示内容**:
  - 製品別・工程別の作業時間
  - 段取り時間
  - 開始・終了時刻
- **編集**: 工程ガント画面で手動調整可能
- **保存**: 「工程ガント保存」ボタンで保存

#### 工程負荷表示

工程別・日別の負荷時間を分（H）で表示。

- **データソース**: LineGanttPlanから集計
- **表示形式**: `XXX分 (YYY時間)`
  - 例: `480 (8.0)` = 480分 = 8時間
- **更新**: 工程ガント再生成時に自動更新

## データフロー

```
[ユーザー入力] → LinePlan
                     ↓
           [工程展開] → LineBacklog（plan_qty, plan_id, sequence_no）
                     ↓
           [在庫計算] → LineBacklog（stock_qty, planned_stock_qty）
                     ↓
         [ガント生成] → LineGanttPlan（processes_plan）
```

## 運用フロー

### 日次運用

1. **後工程需要の取り込み**
   - 「取り込み」ボタンをクリック
   - 後工程計画からorder_qtyを反映

2. **生産計画の入力**
   - 計画数量と順序番号を入力
   - 複数ロットの場合は「+」ボタンで追加

3. **計画の保存**
   - 「保存」ボタンをクリック
   - 工程展開・在庫計算・ガント生成が自動実行

4. **工程ガントの確認**
   - 「工程ガント表示」ボタンで確認
   - 必要に応じて手動調整

5. **工程負荷の確認**
   - 「工程負荷表示」ボタンで工程別負荷を確認
   - 負荷が過大な場合は計画を調整

### 週次運用

1. **翌週の計画立案**
   - 表示開始日を翌週に設定
   - 新規行追加で製品を選択
   - 計画数量を入力

2. **複数ライン調整**
   - ライン別に負荷バランスを確認
   - 過負荷ラインの計画を他ラインに移動

### 月次運用

1. **月間計画の確認**
   - 期間を90日に設定
   - 全体の計画バランスを確認

2. **計画の見直し**
   - 受注状況に応じて計画を調整
   - 在庫過多/不足の製品を調整

## 注意事項

### 順序番号の管理

- **同日・同ライン内で重複不可**
- **推奨**: 1, 2, 3, ...の連番
- **重複時**: エラーメッセージが表示され、保存失敗

### 計画数量の扱い

- **0以下の入力**: 該当計画を削除
- **空白入力**: 0として扱われ、削除される
- **小数入力**: 許可（plan_idに反映）

### 工程展開の前提

- **LinePlan**: ライン最終品のみ登録
- **LineBacklog**: 全工程に展開される
- **BOM**: 正しく設定されている必要がある

### パフォーマンス

- **推奨期間**: 30日（デフォルト）
- **最大期間**: 90日
- **大量データ**: ライン・期間を絞り込み

## エラーハンドリング

### 保存時のエラー

| エラー内容 | 原因 | 対処法 |
|----------|------|-------|
| sequence_no required | 順序番号が未入力 | 順序番号を入力 |
| sequence_no already used | 同日・同ラインで順序番号が重複 | 順序番号を変更 |
| product_id/process_id/plan_date required | 必須項目が未入力 | 製品・工程・日付を確認 |
| product not found | 製品が存在しない | 製品マスタを確認 |

### 取り込み時のエラー

| エラー内容 | 原因 | 対処法 |
|----------|------|-------|
| 取り込みに失敗しました | APIエラー | サーバーログを確認 |
| 工程展開/ガント再計算に失敗しました | 後続処理エラー | BOM設定を確認 |
