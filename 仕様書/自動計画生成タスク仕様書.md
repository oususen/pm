# 生産計画自動生成タスク仕様書

## 概要

定時タスクによって、指定ラインの生産計画を自動生成する機能。  
手動計画（UI）と同等の挙動を実現し、需要取り込みから工程展開・ガント生成まで一括実行する。

### ライン区分と実行タイミング（2026-02 追加）

- 自動計画の対象ラインは `PROD`（社内）に加え、`OUTSOURCE`（外作）、`PURCHASE`（購入）も設定可能。
- UI では実行タイミングを2系統で保持する。
  - 社内生産ライン用タイミング
  - 外作・購入品ライン用タイミング
- 保存時は、各ラインの `line_type` に応じて `ScheduleConfig.scheduled_dom/hour/minute` を反映する。
- 実行順（`execution_order`）は従来どおり全対象ラインで管理する。

### Step2: ライン最終品需要の抽出

```python
def fetch_final_demands(line_id, start_date, end_date):
    """自動計画対象の需要行を取得（ライン種別で条件分岐）"""
    base_qs = LineBacklog.objects.filter(
        line_id=line_id,
        plan_date__range=[start_date, end_date],
        sequence_no=0,                        # 基礎データのみ
        demand_qty_plan__gt=0,                # 需要 > 0
    )
    if line_type == 'PROD':
        # 社内ラインはライン最終品のみ
        base_qs = base_qs.filter(product__is_line_final_product=True)
    # 外作/購入ラインは is_line_final_product に依存しない
    return base_qs.values('plan_date', 'process_id', 'product_id', 'demand_qty_plan')
```

**条件：**
- `sequence_no = 0` — 工程展開前の基礎データのみ対象（手動と同じ）
- `PROD` ライン: `is_line_final_product = True` のみ対象
- `OUTSOURCE` / `PURCHASE` ライン: `is_line_final_product` が `0` の品目も対象
- `demand_qty_plan > 0` — 需要がある品目のみ

**差分：**
- 旧ロジック（Routing/BOMから対象を収集）→ 削除
- 新ロジック（LineBacklog直接フィルタ） ✅

### Step3: 期間内の計画を一括削除（カスケード）

```python
def delete_existing(line_id, start_date, end_date):
    """
    指定期間・ラインの計画系を全削除（需要有無関わらず）
    → 冪等性を確保し、重複・取り残しを防止
    """
    # 1. LinePlan削除
    plan_ids = list(LinePlan.objects.filter(
        line_id=line_id,
        plan_date__range=[start_date, end_date],
    ).values_list('plan_id', flat=True))
    LinePlan.objects.filter(...).delete()

    # 2. LineGanttPlan削除（手動saveと同じ）
    LineGanttPlan.objects.filter(...).delete()

    # 3. LineBacklog計画行削除（sequence_no > 0のみ）
    if plan_ids:
        LineBacklog.objects.filter(
            plan_id__in=plan_ids,
            sequence_no__gt=0,
        ).delete()
```

**設計方針：**
- 期間内を **完全にリセット** してから再生成
- 需要がゼロに変わった品目の古い計画も確実に削除
- 月が重なった場合（e.g., 3月を複数回生成）の重複を防止
- 再実行しても同じ結果（冪等性）を保証

### Step4: 計画作成（社内/購買で分岐）

- `PROD` / `OUTSOURCE`:
  - 従来どおり `LinePlan` を作成（`sequence_no >= 1`）。
- `PURCHASE`:
  - `LineBacklog(sequence_no=1)` の `plan_qty` に計画値を保存（1ロット固定）。`sequence_no=0` は基礎データ行のため `plan_qty` は保存しない。
  - 需要が消えた日付の `sequence_no=1` レコードは削除（`plan_qty=0` 扱い）。
  - 購買は工程展開・ガント生成を行わない（`LinePlan` を作らない）。

#### 4-1. `PROD` / `OUTSOURCE`: LinePlan 作成 + sequence_no採番

```python
def generate_line_plans(line_id, demand_rows):
    """
    ライン最終品需要から LinePlan を作成（手動save互換）
    
    sequence_no採番ルール:
      1. 日付ごとに product_code昇順 → process_id昇順 でソート
      2. 同日に残っている自動対象外計画の max(sequence_no) を起点に続番
    """
    # 日付ごとにグループ化
    items_by_date = defaultdict(list)
    for row in demand_rows:
        items_by_date[row['plan_date']].append(row)

    # 既存の自動対象外計画から各日付の最大seq を取得
    existing_max = {
        rec['plan_date']: rec['max_seq']
        for rec in LinePlan.objects.filter(
            line_id=line_id,
            plan_date__in=items_by_date.keys(),
        ).exclude(product_id__in=product_ids)  # 自動対象外
          .values('plan_date').annotate(max_seq=Max('sequence_no'))
    }

    for plan_date, items in items_by_date.items():
        # product_code → process_id で安定ソート
        items.sort(key=lambda x: (product_code_cache.get(x['product_id'], ''), 
                                  x['process_id'] or 0))

        # 次のsequence_no を決定
        next_seq = (existing_max.get(plan_date) or 0) + 1

        # LinePlan作成 + plan_id生成
        for it in items:
            plan_qty = int(Decimal(it['demand_qty_plan'] or 0))
            product_code = product_code_cache.get(it['product_id'], str(it['product_id']))

            # plan_id フォーマット（手動と同じ）
            qty_label = str(plan_qty)
            plan_id = f"{product_code}_{plan_date.strftime('%Y%m%d')}_{qty_label}_{next_seq}"

            LinePlan.objects.create(
                plan_date=plan_date,
                process_id=it['process_id'],
                product_id=it['product_id'],
                line_id=line_id,
                plan_qty=plan_qty,
                plan_id=plan_id,
                sequence_no=next_seq,
            )
            next_seq += 1
```

### Step5b: ガント計画生成

```python
def generate_gantt(line_id, start_date, end_date):
    """
    LineGanttPlan を再生成（手動generate互換）
    ラインのデフォルト設定を参照し、なければ08:00でフォールバック
    """
    # ラインのデフォルト開始時刻を取得
    default_setting = LineDefaultScheduleSetting.objects.filter(line_id=line_id).first()
    if default_setting and default_setting.final_process_start_time:
        start_time_str = default_setting.final_process_start_time.strftime('%H:%M')
        adjust_break = default_setting.adjust_to_break_end
    else:
        start_time_str = '08:00'
        adjust_break = True

    # ガント計画生成
    plans = generate_line_gantt_plans(
        line_id=line_id,
        start_date=str(start_date),
        end_date=str(end_date),
        clear_existing=False,
        final_process_start_time=start_time_str,
        adjust_to_break_end=adjust_break,
    )

    # DB保存（update_or_create → 既存は上書き）
    new_plan_ids = []
    for plan in plans:
        LineGanttPlan.objects.update_or_create(
            plan_id=plan['plan_id'],
            defaults={
                'line_id': plan['line_id'],
                'product_id': plan['product_id'],
                'plan_date': plan['plan_date'],
                'plan_qty': plan['plan_qty'],
                'sequence_no': plan['sequence_no'],
                'start_datetime': plan['start_datetime'],
                'end_datetime': plan['end_datetime'],
                'processes_plan': plan['processes_plan'],
            }
        )
        new_plan_ids.append(plan['plan_id'])

    # 古いガントをクリア（新規生成分以外）
    old_qs = LineGanttPlan.objects.filter(
        line_id=line_id,
        plan_date__range=[start_date, end_date],
    )
    if new_plan_ids:
        old_qs = old_qs.exclude(plan_id__in=new_plan_ids)
    old_qs.delete()
```

**ポイント：**
- ラインのデフォルト開始時刻 (`LineDefaultScheduleSetting.final_process_start_time`) を優先
- なければ 08:00 / adjust_to_break_end=True でフォールバック
- 期間内の古いガントを削除（新規生成分以外）

## スケジューラ統合（tasks_auto_plan.py）

### 実行条件

```python
def run_auto_plan(force=False, config_id=None):
    """
    - ScheduleConfig(task_name='AUTO_PLAN') から対象設定を取得
    - force=True: 日付チェックなし（手動実行 or テスト）
    - force=False: scheduled_dom と本日を比較 → マッチしなければスキップ
    """
    qs = ScheduleConfig.objects.filter(task_name='AUTO_PLAN')
    config = qs.select_related('line').first()
    
    today = datetime.now().date()
    if not force and config.scheduled_dom and today.day != config.scheduled_dom:
        # 本日が実行日でなければスキップ
        return
```

### 月オフセット処理

```python
def _selected_month_offsets(config):
    """
    include_next_month / include_second_month / include_third_month から
    実行対象月を決定
    """
    months = []
    if getattr(config, 'include_next_month', True):
        months.append(1)  # 翌月
    if getattr(config, 'include_second_month', False):
        months.append(2)  # 翌々月
    if getattr(config, 'include_third_month', False):
        months.append(3)  # 翌々翌月
    return months or [1]

def _month_range_from(base_date, months_ahead):
    """base_date から months_ahead 月先の 月初～月末 を返す"""
    first = base_date.replace(day=1)
    for _ in range(months_ahead):
        first = (first + timedelta(days=32)).replace(day=1)
    start = first
    end = (first + timedelta(days=32)).replace(day=1) - timedelta(days=1)
    return start, end
```

### 月重複対応（例）

**シナリオ:**
- 1/1: 翌月+翌々月+翌々翌月 設定 → 2月、3月、4月を生成
- 2/1: 同設定 → 3月、4月、5月を生成

**結果:**
- 3月、4月は 1/1時点での計画が 2/1で **上書き**
- 新たに5月が作成
- 重複や取り残しはなし（期間一括クリア方式で実現）

```python
def run_auto_plan(force=False, config_id=None):
    line_stats = []
    
    for offset in months:
        start, end = _month_range_from(today, offset)
        cmd = GeneratePlanCommand()
        cmd.handle(
            run_date=str(today),
            start=str(start),
            end=str(end),
            lines=[config.line_id],
            stats=line_stats,  # コマンドが stats.append() で結果を追記
        )
    
    # stats の例
    # [
    #   {
    #     'line_id': 11,
    #     'line_code': 'LINE II',
    #     'start': '2026-03-01',
    #     'end': '2026-03-31',
    #     'created': 113,
    #     'updated': 0,
    #   },
    #   ...
    # ]
    
    config.last_run_message = '\n'.join([
        f"ライン:{st['line_code']}({st['line_id']}) 期間:{st['start']}~{st['end']} 作成:{st['created']} 更新:{st['updated']}"
        for st in line_stats

```

**ScheduleConfig への記録：**
- `last_run_at` — 実行日時
- `last_run_status` — 'SUCCESS' / 'FAILED' / 'RUNNING'
- `last_run_message` — 実行結果（行数/エラーetc）
- `last_run_duration_seconds` — 実行時間(秒)

**失敗時の通知：**
- `config.notify_users` に登録されたユーザーへ通知を送信
- 通知フォーマット: ライン名 + 失敗理由

## 自動計画ロック機能（2026-09 追加）

### 概要

特定の日×製品の計画を自動計画で変更されないようにロックする機能。
生産計画入力画面・仕入計画入力画面でロックモードを使い、セル単位でロック/解除できる。

### データモデル

汎用ロックテーブル `production_lock` を使用する。

| カラム | 型 | 説明 |
|--------|-----|------|
| `lock_type` | VARCHAR(50) | ロック種別。自動計画ロックは `auto_plan` |
| `line_id` | FK → Line (nullable) | 対象ライン |
| `plan_date` | Date (nullable) | 対象計画日 |
| `product_id` | FK → Product (nullable) | 対象製品 |
| `locked_qty` | Decimal(12,2) | ロック時の保存済み計画数 |
| `locked_by` | FK → User (nullable) | ロック操作者 |
| `locked_at` | DateTimeField | ロック日時 |

- ユニーク制約: `(lock_type, line_id, plan_date, product_id)`
- レコード存在＝ロック中、削除＝解除

### ロック時の自動計画動作

- `production_lock.locked_qty` に保存済みの日別計画数を保持する（ゼロも固定値）。
- 生産は `LinePlan` の当日・製品の全ロット合計、購買は `LineBacklog(sequence_no=1)` の計画数を使用する。ロック登録時は画面送信値ではなく、保存済みDB数量と照合して保存する。
- 需要取得後、計画生成前に `apply_locked_quantities()` でロック数値を採用する。需要がなくなった日も対象とする。
- 期間内の計画を通常通り更新し、工程展開・ガント生成は一度だけ実施する。購買は従来通り工程展開・ガント生成を行わない。
- 数量を固定する機能であり、ロット分割・順序・ガント時刻は固定しない。

### 注文書自動送信との連携

注文書自動送信（`tasks_auto_order_send` / `services_auto_order_send`）もロックを参照する。
対象納入日の既存計画を一括削除する前にロック情報をメモし、削除後に即復元する。
注文計画の再作成後も末尾で再度復元し、進度再計算と注文書出力はロック数量を正とする。
ロック数量が0の場合は計画0として復元するが、注文書明細には出力しない。
詳細は `注文書自動送信設定仕様書.md` を参照。

### UI上の自動計画と手動編集

生産計画・仕入れ計画画面では、計画数の算出後、保存用データ作成前にロック数値を採用する。
表示時にもロック数値を使用する。複数ロットの合計が固定値と異なる場合は固定値を主ロットへ設定し追加ロットをクリアする。
ロック中の数量入力・追加ロットの数量変更は禁止。変更は **解除→編集→保存→再ロック** の順に行う。
ロックを含む日の一括削除は解除が必要。ロック情報の取得失敗時は保存・自動計画を中止する。

### API

| メソッド | パス | 説明 |
|---------|------|------|
| GET | `/api/production/production-locks/?lock_type=auto_plan&line_id=X&start=Y&end=Z` | ロック一覧取得 |
| POST | `/api/production/production-locks/` | ロック追加（locked_qty 必須、保存済み数量と不一致なら409） |
| DELETE | `/api/production/production-locks/` | ロック解除 |

### 操作方法

1. 計画を保存してから、計画入力画面または仕入計画入力画面のツールバーで「🔒ロック」ボタンをクリック → ロックモード ON
2. ロックしたい計画セル（日×製品）をクリック → ロック設定（黄色背景 + 🔒マーク）
3. 解除は同じセルを再度クリック
4. 「🔒ロック中」ボタンを再度クリック → ロックモード OFF（通常編集に戻る）

## トランザクション管理

### ライン単位でのアトミック性

```python
with transaction.atomic():
    run_pickup(line.id, line_start, line_end)
    demand_rows = list(fetch_final_demands(...))
    demand_rows = apply_locked_quantities(line, line_start, line_end, demand_rows)
    delete_existing(line.id, line_start, line_end)
    created_count, _ = generate_line_plans(...)
    expand_processes(line.id, line_start, line_end)
    generate_gantt(line.id, line_start, line_end)
    
    if dry_run:
        raise transaction.TransactionManagementError('dry-run rollback')
```

**ドライランモード：**
- 処理は全て実行
- 最後に TransactionManagementError で意図的にロールバック
- DBには変更なし（テスト用）

## コマンドインターフェース

### 使用方法

```bash
# 基本形（翌月を自動計算）
python manage.py generate_production_plan --line 11

# 期間指定
python manage.py generate_production_plan --line 11 --start 2026-03-01 --end 2026-03-31

# ドライラン（変更なし）
python manage.py generate_production_plan --line 11 --start 2026-03-01 --end 2026-03-31 --dry-run

# 複数ラインを順次実行
python manage.py generate_production_plan --line 11 22 33 --start 2026-03-01 --end 2026-03-31

# 設定ファイルから期間を読み込み
python manage.py generate_production_plan --config /path/to/config.json
```

### 引数

| 引数 | 型 | 必須 | 説明 |
|-----|-----|------|------|
| `--line` | int多重 | ✗ | 対象ラインID（複数可）。未指定なら全アクティブライン |
| `--start` | date | ✗ | 期間開始（YYYY-MM-DD）。未指定なら翌月1日 |
| `--end` | date | ✗ | 期間終了（YYYY-MM-DD）。未指定なら翌月末日 |
| `--run-date` | date | ✗ | 実行基準日（月計算用）。未指定なら本日 |
| `--dry-run` | bool | ✗ | ドライラン（変更なしロールバック）|
| `--config` | str | ✗ | 設定ファイルパス（JSON/YAML） |

## 在庫計算について

### 除外理由

自動生成コマンドでは **在庫再計算のステップを実行しない**（削除済み）。

**理由：**
- LT+1日前までの制限がある（過去のデータ計算不可）
- 期間内データが集まらない可能性がある
- 日次バッチで別途実行することが推奨

**代替処理：**
```python
# 日次の別タスク（例）で定期実行
from production.inventory.inventory_calculator import recalculate_inventory_for_line

recalculate_inventory_for_line(
    line_id,
    start_date,
    end_date,
    include_progress=False,
    line_final_only=True,
)
```

## 手動計画との同等性確認チェックリスト

### 計画作成

- ✅ ライン最終品のみ LinePlan 登録
- ✅ sequence_no は同日内で product_code → process_id 昇順
- ✅ plan_id フォーマット（{product_code}_{YYYYMMDD}_{qty}_{seq}）
- ✅ 既存計画の最大seq からの続番
- ✅ ロック済みの日×製品は、生成前の需要行を `locked_qty` に置き換える

### 工程展開

- ✅ expand_processes で工程別 LineBacklog 生成
- ✅ BOM分解・副産物処理を実施
- ✅ sequence_no > 0 の計画行を作成

### ガント生成

- ✅ LineDefaultScheduleSetting から開始時刻取得
- ✅ フォールバック（08:00 / adjust_to_break_end=True）
- ✅ 旧ガント削除（新規生成分以外）

### 後処理削除

- ✅ 期間内を完全リセット（LinePlan/LineGanttPlan/LineBacklog計画行）
- ✅ 需要有無関わらず削除（冪等性確保）

### 再実行

- ✅ 同じパラメータで複数実行 → 同じ結果
- ✅ 月の重なり → 上書き（重複なし）

## トラブルシューティング

### 計画が作成されない

**原因:**
1. ライン最終品の需要がない
2. 期間内に最終品がない
3. LINE がinactive状態

**対応:**
```bash
# デバッグ実行（冗長出力）
python manage.py generate_production_plan --line 11 --start 2026-03-01 --end 2026-03-31 -v 3
```

### sequence_no が重複している

**原因:**
- 手動と自動が混在して作成した可能性

**対応:**
- 期間を完全削除してから再生成
- ドライラン → 本実行 の流れで確認

### ガント生成が失敗

**原因:**
1. LineDefaultScheduleSetting が存在しない（フォールバック使用）
2. プロセス間の待機関係が無限ループ

**対応:**
- LineDefaultScheduleSetting を事前に設定
- プロセス / 工程の循環設定を確認
