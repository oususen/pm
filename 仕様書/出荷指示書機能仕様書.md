## 概要

この機能は、Tiera製品の出荷指示書をPDF形式で生成します。出荷データを4つの便（1便目〜4便目）に自動的に振り分け、容器単位で適切にグループ化してPDFを出力します。

### 主要機能

- 出荷データの4便への自動振り分け
- 納入先コード別リードタイム（営業日）を考慮した出荷対象抽出
- 容器単位でのグループ化と容器数計算
- SUB_BLADE製品の特殊処理（MAIN製品との統合表示）
- PDF形式での出荷指示書生成
- 2便目・3便目に納入先コードを表示（PDF）
- Web UIからの操作（日付選択、プレビュー、PDF生成）

## 機能仕様

### 振り分けルール

#### 1便目（06:00）: 4t／5tブレード（1）

- **対象**: 容器名に「4-5T」を含む製品
- **処理**: 容器数を計算し、半分を1便目に割り当て

#### 2便目（06:30）: ブレード

- **対象**:
  - 機種名が以下のいずれか: `391`, `17U`, `20U`, `26U`, `19-6`, `390`, `KOTEIKYAKU`
  - 製品グループが: `SUB_BLADE`
  - リーデン受注（`is_rieden=True`）
- **特記事項**: リーデン受注を納入先コード別にピンク枠で表示（製品番号・数量）
- **リーデン判定**: `StgOrderDaily.raw_rieden IS NOT NULL` の `customer_id` で動的に特定

#### 3便目（10:00）: オイルタンク・シートベース

- **対象**: 製品グループが `SEATBASE` または `TANK`

#### 4便目（13:00）: 4t／5tブレード（2）

- **対象**: 1便目と同じ製品
- **処理**: 残りの容器を割り当て

### 出荷対象の抽出（納入先コード別リードタイム）

- 出荷指示書の対象データは `t_order_line`（OrderLine）を参照
- `ship_to_code` ごとのリードタイム（営業日）を考慮して、`target_date` に出荷すべき納期を逆算
- 営業日計算は得意先 `TIERA` のカレンダーを使用（未設定時は土日を休業日とする週末判定）
- `ship_to_code` が空/NULL の場合は当日出荷（`due_date = target_date`）

**リードタイム設定（営業日）**:

| ship_to_code | リードタイム | 備考 |
|-------------|------------|------|
| 000010 | 2 | 2営業日前出荷 |
| 000030 | 2 | 2営業日前出荷 |
| 000050 | 0 | 当日出荷 |

**例**:

```
target_date = 2026-01-13
ship_to_code = 000010 (2営業日前出荷)
-> due_date = 2026-01-15（営業日加算で計算）
```

**設定箇所**: `ShippingOrderService.SHIP_TO_LEAD_TIME_DAYS`

### SUB_BLADE製品の特殊処理

- SUB製品（例: `17U-L`, `20U-R`）は対応するMAIN製品（`17U`, `20U`）の容器情報を参照
- MAIN製品とSUB製品が同時にある場合、MAINの最後の容器にSUBの情報を追加表示
- L/R両方のSUB製品がある場合、1つの容器にまとめる

### 注意製品

- **YD40003261**: 別途注意事項として表示（`YD40003117`に付ける製品）

### YD40003261 注意書きロジック

1. 通常の出荷指示書データ（trip1〜trip4）を取得する際、`YD40003261` は明細から除外する。
2. 同時に `YD40003261` を別クエリで集計し、`OPEN` かつ `FIRM`、`quantity > 0`、`due_date = target_date` の条件で数量合計を取得する。
3. 集計結果が 1 以上の場合のみ、APIレスポンスの `attachment_note` に `YD40003261 {数量}個あり` を設定する（0件時は `null`）。
4. PDF生成時に `attachment_note` が存在する場合、帳票の最下部へ `【注意】 {attachment_note}` を赤字で出力する。

## データベース構造

### マスタテーブル

#### m_product_group（製品グループマスタ）

| カラム名 | 型 | 説明 |
|---------|-----|------|
| id | BIGINT | 主キー |
| group_code | VARCHAR(50) | グループコード（BLADE, TANK等） |
| group_name | VARCHAR(100) | グループ名 |
| description | TEXT | 説明 |
| is_active | BOOLEAN | 有効フラグ |

**主要グループ**:
- `FLOOR`: フロア
- `TANK`: タンク
- `BLADE`: ブレード
- `SEATBASE`: シートベース
- `SUB_BLADE`: サブブレード

#### m_container_capacity（容器仕様マスタ）

| カラム名 | 型 | 説明 |
|---------|-----|------|
| id | INT | 主キー |
| name | VARCHAR(50) | 容器名 |
| container_code | VARCHAR(20) | 容器コード |
| width | INT | 幅（mm） |
| depth | INT | 奥行（mm） |
| height | INT | 高さ（mm） |
| max_weight | INT | 最大重量（kg） |
| can_mix | BOOLEAN | 混載可能 |
| stackable | BOOLEAN | 積み重ね可能 |
| max_stack | INT | 最大積み重ね段数 |
| capacity | INT | 入り数（容器に入る製品の個数） |

#### m_product（製品マスタ）拡張フィールド

| カラム名 | 型 | 説明 |
|---------|-----|------|
| model_name | VARCHAR(50) | 機種名 |
| product_group_id | BIGINT | 製品グループ（FK） |
| used_container_id | INT | 使用容器（FK） |
| capacity | INT | 容器入り数 |

### トランザクションテーブル

#### t_order_line（受注明細）※出荷指示書の参照元

| カラム名 | 型 | 説明 |
|---------|-----|------|
| due_date | DATE | 納期 |
| ship_to_code | VARCHAR(40) | 納入先コード（NULL/空許容） |

#### t_delivery_progress（出荷進捗）

| カラム名 | 型 | 説明 |
|---------|-----|------|
| id | BIGINT | 主キー |
| order_id | BIGINT | 受注（FK、nullable） |
| product_id | BIGINT | 製品（FK、nullable） |
| order_date | DATETIME | 出荷日 |
| order_quantity | INT | 受注数量 |
| shipped_quantity | INT | 出荷済数量 |
| remark | VARCHAR(200) | 備考 |

## API仕様

### 1. 利用可能な日付取得

**エンドポイント**: `GET /api/orders/shipping/available-dates/`

**レスポンス**:
```json
{
  "dates": ["2026-01-08", "2026-01-07", ...],
  "count": 30
}
```

### 2. 出荷データ取得

**エンドポイント**: `GET /api/orders/shipping/order-data/{YYYY-MM-DD}/`

**レスポンス**:
```json
{
  "date": "2026-01-08",
  "trip1": [
    {
      "product_code": "YD40003001",
      "product_name": "4tブレードA",
      "model_name": "391",
      "order_quantity": 15,
      "capacity": 3,
      "ship_to_code": "000010",
      "group_name": "ブレード"
    }
  ],
  "trip2": [...],
  "trip3": [...],
  "trip4": [...],
  "trip2_special_annotations": [
    {
      "ship_to_code": "000050",
      "display_name": "滋賀",
      "products": [
        {"product_code": "4338215", "quantity": 150}
      ]
    }
  ],
  "attachment_note": "YD40003261 3個あり"
}
```

### 3. PDF生成

**エンドポイント**: `POST /api/orders/shipping/generate-pdf/`

**リクエスト**:
```json
{
  "target_date": "2026-01-08",
  "creator_name": "山田太郎"
}
```

**レスポンス**: PDF file (application/pdf)

## PDF出力仕様

### レイアウト

- **サイズ**: A4
- **フォント**:
  - Windows: MSゴシック
  - Linux: IPAゴシック
  - Mac: ヒラギノ角ゴ
- **構成**:
  - タイトルバンド: 黒背景に白文字
  - 出荷日表示: 日本語形式（例: 11月4日(月)）
  - 確認／作成者枠
  - 4つの便ごとにセクション分け

### 色分け

- **1便目・4便目**: ブレード青色
- **2便目**: ブレード黄色
- **3便目**:
  - シートベース: 緑色
  - タンク: 青色
- **リーデン受注**: ピンク色（納入先コード別に枠表示: 000010=神立, 000030=つくば, 000050=滋賀）

### 表示ルール（納入先コード・別紙参照）

- **1便目・4便目**: 3台を1容器として「別紙参照」カードを容器数分表示
- **2便目・3便目**: `ship_to_code` がある場合、ラベル3行目に「納入先: XXXXXX」を表示

## 使用方法

### 1. 初期データセットアップ

```bash
cd pm_backend

# 製品グループをインポート
python import_product_groups.py

# 容器データをインポート
python import_container_capacity.py

# テストデータを生成
python create_test_shipping_data.py
```

### 2. Web UIから使用

1. ブラウザで `http://10.0.1.194:8501` にアクセス
2. 「出荷」→「📄 出荷指示書」を選択
3. 「📅 利用可能な日付を表示」をクリック
4. 日付を選択
5. 「🔍 データプレビュー」で内容確認（オプション）
6. 「📄 PDF生成」でPDFをダウンロード

### 3. Django Shellから使用

```python
from datetime import date
from orders.services.shipping_order_service import ShippingOrderService
from orders.services.shipping_pdf_generator import generate_shipping_order_pdf

# サービスを初期化
service = ShippingOrderService()

# 出荷可能な日付を取得
available_dates = service.get_available_dates()
print(available_dates)

# 特定日のデータを取得
target_date = date(2026, 1, 8)
shipping_data = service.get_shipping_data_by_date(target_date)

# PDFを生成
pdf_path = generate_shipping_order_pdf(
    shipping_data=shipping_data,
    output_path="shipping_order.pdf",
    creator_name="山田太郎",
    service=service
)
print(f"PDF生成完了: {pdf_path}")
```

## トラブルシューティング

### 日付が表示されない

**原因**: `DeliveryProgress`テーブルにデータが存在しない

**解決方法**:
```python
from orders.models import DeliveryProgress
from datetime import date

# データ確認
target_date = date.today()
count = DeliveryProgress.objects.filter(
    order_date__date=target_date,
    order_quantity__gt=0
).count()
print(f"{target_date}のデータ件数: {count}")

# テストデータ作成
python create_test_shipping_data.py
```

### PDF生成エラー

**原因**: 日本語フォントが見つからない

**解決方法**（Linux）:
```bash
# Ubuntu/Debian
sudo apt-get update
sudo apt-get install -y fonts-ipafont-gothic fonts-takao-gothic

# Docker環境
apt-get update && apt-get install -y fonts-ipafont-gothic fonts-takao-gothic
```

### CORS エラー

**原因**: Django設定で適切なCORS設定がされていない

**解決方法**:
1. `django-cors-headers`がインストールされていることを確認
2. `pm_backend/settings.py`のCORS設定を確認

### データが正しく振り分けられない

**確認項目**:
1. 製品マスタに`model_name`, `product_group`, `used_container`, `capacity`が設定されているか
2. 容器マスタに正しいデータが入っているか
3. 製品グループマスタに必要なグループ（BLADE, TANK等）が登録されているか
