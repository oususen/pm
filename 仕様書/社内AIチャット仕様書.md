# 社内AIチャット仕様書

## 目的

社内利用者が、ローカルQwenまたはDeepSeek APIを選択して質問し、社内データに基づく回答やチャート・報告書を取得する。

社内AIの業務目的、DBアクセス範囲、外部API送信、禁止操作は、[社内AI運用規約・AI用DB辞書](社内AI運用規約・AI用DB辞書.md) に従う。
画面ごとの業務構造、正規データソース、集計規則は、[PMアプリ構造辞書](PMアプリ構造辞書.md) に従う。

## 実行方式

- 画面上で「DeepSeek API」と「ローカルQwen」を切り替えられる。DeepSeek API選択時は「DeepSeek V4 Pro（高精度）」と「DeepSeek Flash（高速）」を切り替えられる。初期選択は幹部会での実演を想定して DeepSeek V4 Pro とする。
- DeepSeek API選択時は、質問・会話履歴・回答に必要なDB集計結果をDeepSeekへ送信する。APIキーはバックエンドの `DEEPSEEK_API_KEY` 環境変数だけで管理し、画面・ソースコード・Gitには含めない。
- DeepSeek API選択時は、DeepSeekが非思考モードの関数呼び出しで読み取り専用ツールを選ぶ。生産数を照会する場合は、品番マスタ検索を行ってから集計ツールを呼ぶ。PM側がツール実行とデータ範囲の検証を担当し、DeepSeekは任意SQLやDB更新を実行できない。
- ローカルQwen選択時は、PC内で動作する Ollama の `qwen3:4b-instruct`（Qwen3-4B-Instruct-2507）を使用し、外部AIサービスへ質問・データを送信しない。
- 導入済みの `qwen3:4b` は実体がThinking-2507で、Ollamaの `thinking.values` が `[true]` の思考専用モデルだった。`think:false` の指定だけでは通常回答モードに変更できないため、このチャットではInstruct版を明示して使用する。
- Instruct版の生成設定は `think:false`、`temperature:0.7`、`top_p:0.8`、`top_k:20`、`min_p:0`、`num_ctx:4096`。モデルの保持時間は10分とする。

## 処理フロー

質問を受け取った際、以下の優先順で処理を振り分ける。

1. **パターンマッチ即回答**: 「北村さんの8月の残業」のように氏名・月が明示された残業照会は、Qwen呼び出しなしでDBから直接集計して回答する。
2. **DeepSeekによるツール調査／Qwenの固定集計**: DeepSeekでは、生産数・仕損・中断・残業などDB根拠を要する質問に対し、モデル自身が品番マスタ検索・許可済み集計ツールを必要な順番で呼び、集計結果を基に自然文で回答する。ローカルQwenでは既存の固定集計を使う。いずれもチャートや報告書の生成に対応する。
   - このチャットは本社の生産管理を基本対象とする。
   - 品番を会話内で明示した場合は、続く生産数質問でもその品番を引き継ぐ。品番マスタに存在しない場合は全品番集計を行わず、未登録であることを回答する。
   - 品番に空白・ハイフン・英字大小の表記ゆれがある場合は正規化して照合する。完全一致しない場合は近い候補を最大3件提示し、AIが候補を勝手に選んで集計しない。
   - AIが示した「1. 生産数」「2. 仕損」「3. 残業」の選択肢に番号だけで返答した場合は、直前の選択肢を業務質問として復元し、直近15件の会話から正式品番と直近の対象期間を引き継いで集計する。
   - 個人別残業は `overtime.personal_summary` の閲覧権限を持つ画面だけで利用できる。DeepSeekには一時ID・期間・合計時間・しきい値超過者だけを渡し、申請明細・理由・連絡先は渡さない。
3. **一般会話**: 上記に該当しない質問は、選択中のモデルへ会話を渡して回答する。質問文と起点画面に合う正式原本のMarkdown断片をRAGで最大4件付与する。対象は、AI設定で有効な「PMアプリ構造」「マニュアル」「手順書」「安全・運用規約」の区分だけとし、READMEの案内文やリポジトリ全体は渡さない。AI設定で登録したPDF、Excel（`.xlsx` / `.xls`）、CSV、TSV、画像（PNG / JPG / WEBP / BMP）も同じ区分で検索する。画像はローカルTesseract OCRで文字を抽出してから検索する。さらに利用者がチャットで明示添付した画像は、AI設定の許可時にOpenRouterの画像対応モデルへ縮小画像を一時送信して、写真・設備・帳票の見た目を判定できる。明示添付PDFは先頭3ページを画像化して同じモデルへ一時送信できる。全ページを送らないPDFでは、AIは回答内に確認済みページ数と未確認ページ範囲を明記し、未確認範囲を推測しない。元資料は `media/ai_knowledge/` に保存し、抽出本文および送信用縮小画像は保存しない。DB数値が必要な回答では、RAGの文章より読み取り専用DBツールの結果を優先する。
   - チャット入力欄で資料を添付した場合は、資料をAIナレッジへ登録し、その会話では添付資料だけをRAG検索する。明示添付は利用者自身の今回限りの指定であるため、一覧上の資料有効/無効にかかわらず参照・画像化する。新しい会話にすると資料指定を解除する。添付しない会話は従来どおり全有効資料を自動検索する。

## DB集計対象（読み取り専用）

| intent | データソース | 集計内容 |
|---|---|---|
| production | ProcessRealtimeRecord、LaserActualDetail、BrakeLineRecord | 日別生産数・工程別生産数。品番指定時は画面別の正規実績を二重計上せずに使用する |
| operator | ProcessRealtimeRecord | 指定作業者の日別生産数 |
| scrap | ScrapRecord | 確定仕損の理由別数量 |
| interruption | BrakeLineRecord | 中断・強制終了の理由別件数 |
| overtime | OvertimeApplication | グループ別残業申請時間（承認段階別） |
| individual_overtime | OvertimeApplication | 個人の残業申請時間（承認段階別） |
| report | 上記複合 | 生産・仕損・中断の期間集計＋報告書生成 |

## 対象データと安全性

- DBは読み取り専用で集計する。書き込み・更新は行わない。
- 個人の評価・順位付けには使わない。
- 作成した文書は画面からダウンロードされ、サーバーには保存されない。

## API

実装は、生産管理アプリから独立した `ai` アプリで管理する。`ai/views.py` はHTTP入口、`ai/services/chat_service.py` は業務ロジックを担当する。旧 `production/views_ai_demo.py` と `/api/production-ai-demo/` は互換入口として残す。

- `GET /api/production-ai-demo/`: QwenとDeepSeek APIの準備状態を返す。
- `POST /api/production-ai-demo/`: `message`、直近会話、`provider`（`deepseek` または `qwen`）、DeepSeek利用時の`model`（`deepseek-v4-pro` または `deepseek-flash`）を受け取り、以下のいずれかで回答する。
  - パターンマッチ即回答（残業個人照会）
  - DB集計結果＋選択モデルの自然文回答（チャート・報告書含む）
  - 選択モデルの一般会話
- `GET /api/ai/chat/` と `POST /api/ai/chat/`: 社内AIの正式API。リクエスト・レスポンスは旧APIと同じ。

## AIアプリの権限

- AI画面は `ai.chat` の閲覧権限で表示する。`ai.chat` は `ai` 親権限へフォールバックしない。
- 個人別残業集計は、AI画面の利用可否とは別に `overtime.personal_summary` の閲覧権限を必要とする。
- AI設定は `settings.ai` で画面UIを制御する。設定変更には `can_edit` を必要とする。

## AI管理設定

AI設定画面では、任意のSQL・任意テーブル・任意フィールドを登録しない。固定カタログにある安全な機能だけを有効・無効にする。

| 設定区分 | 保存先 | 内容 |
| --- | --- | --- |
| プロバイダ・モデル | `ai_provider_config` | DeepSeek / ローカルQwen の有効状態と既定モデル。APIキーは保存せず環境変数で管理する |
| 画面別ツール | `ai_tool_policy` | 画面起点ごとに公開する固定の読み取り専用ツールと、DeepSeekへ集計結果を送る可否。AI用DB辞書SQLもこの一覧で有効・無効を管理する |
| 外部送信方針 | `ai_data_policy` | 集計結果の外部送信、権限者の個人別集計、明示添付画像・PDFのOpenRouter送信、外部送信する集計行数上限 |
| ナレッジ登録 | `ai_knowledge_source` | PM構造は `仕様書/PMアプリ構造辞書.md` と本仕様書、マニュアルは `pm-ui/public/manual/`、安全・運用規約は `仕様書/社内AI運用規約・AI用DB辞書.md`、手順書は `apps/ai/knowledge/procedures/` を検索対象にする利用状態 |
| 追加ナレッジ資料 | `ai_knowledge_document` | AI設定から登録するPDF、Excel、CSV、TSV、画像の原本。資料名、区分、保存パス、有効状態のみを保持し、15MBを上限とする。画像はローカルOCRで文字化し、画像本文は保存しない |

初期設定では集計済みのデータをDeepSeekへ送ること、利用者が明示添付した画像・PDFをOpenRouterへ送ることを許可し、個人別集計は `overtime.personal_summary` を持つ利用者に限って許可する。画像は最大辺1600px・最大4MBの送信用JPEGへ一時変換し、PDFは先頭3ページを画像化する。元画像・PDFおよび送信用画像は追加保存しない。氏名・ログインID・連絡先・未集計明細は外部送信しない。

## 画面起点のデータ領域

- グローバルナビの先頭にある `AI` タブ、または通常画面の右下に表示する丸いAI吹き出しアイコンを押すと、画面遷移せず右側のAIチャットパネルを開く。元画面の入力・検索状態は保持する。吹き出しアイコンは `ai.chat` の閲覧権限を持つ利用者だけに表示し、チャット表示中は重複して表示しない。
- サーバーは元パスを、登録済みの業務領域（生産・品質・勤務・仕入・出荷・在庫）へ変換する。URLのクエリ文字列や画面入力値を、そのまま外部APIへ送らない。
- DeepSeekには、その業務領域で許可した読み取り専用ツールだけを提示する。さらに集計実行時にも業務領域と集計種別を照合する。
- 現在の対応範囲は、生産（生産数・仕損・中断・残業）、品質（確定仕損）、勤務（残業）、受注の「ルーティング未設定の注文品」である。受注では、画面と同じくOPEN受注明細から有効なルーティングを持たない品番を抽出し、品番ごとに1件へ絞り込む。得意先名、受注番号、受注明細は外部AIへ送らない。仕入・出荷・在庫およびその他の受注集計は正規集計関数が未実装のため、他領域のテーブルを代用して回答しない。
- AIホームから直接開いた場合は、本社横断として現在許可済みの生産・品質・勤務ツールを使用できる。

## AIアプリの育成構成

`pm_backend/apps/ai/` を社内AIの独立した実装単位とする。

| 場所 | 役割 |
| --- | --- |
| `services/chat_service.py` | HTTP入口と会話制御、DeepSeek／Qwen連携、ツール呼出しの許可判定 |
| `services/*_queries.py` | 業務別の読み取り専用集計。現在は `order_queries.py` に受注のルーティング未設定品照会を分離済み。生産・残業・仕入・出荷も同じ単位で追加する |
| `context/` | 画面起点と許可する業務領域・ツールの対応 |
| `security/` | 伏字化、外部送信範囲、DB検索専用ユーザーの運用 |
| `knowledge/` | PM構造・マニュアル・手順書の正式原本への入口。RAGの検索対象と運用区分を管理する単位 |

## MySQL検索専用ユーザー

本番運用では、AI用に `SELECT` だけを持つMySQLユーザーを作成する。アカウント名、接続元、パスワードはGitや仕様書へ保存しない。DB管理者が対象DB名・接続元を確定後、以下を値に置き換えて実行する。

```sql
CREATE USER 'pm_ai_reader'@'＜PMバックエンドの接続元＞' IDENTIFIED BY '＜強力なパスワード＞';
GRANT SELECT ON `pm_db`.* TO 'pm_ai_reader'@'＜PMバックエンドの接続元＞';
SHOW GRANTS FOR 'pm_ai_reader'@'＜PMバックエンドの接続元＞';
```

`INSERT`、`UPDATE`、`DELETE`、`CREATE`、`ALTER`、`DROP`、`EXECUTE` は付与しない。専用接続設定への切替は、ユーザー作成後に接続テストをしてから行う。

Djangoでは `DATABASES['ai_reader']` をAI専用接続とし、AIチャットの全クエリはこの別名を明示して実行する。`DB_USER` / `DB_PASSWORD` へのフォールバックは行わない。Windows開発環境ではAI専用接続だけにMySQL公式ドライバ `mysql-connector-python` を使い、通常業務の `mysqlclient` 接続は変更しない。接続情報は `.env` の `AI_DB_USER`、`AI_DB_PASSWORD`、`AI_DB_NAME`、`AI_DB_HOST`、`AI_DB_PORT` で管理する。MySQLで `REQUIRE SSL` を指定する場合は、AI接続にもSSLを必須とし、サーバー証明書を検証する場合は `AI_DB_SSL_CA` にCA証明書の配置先を設定する。クライアント証明書が必要な環境では、`AI_DB_SSL_CERT` と `AI_DB_SSL_KEY` も設定する。

MySQLのアカウントは接続元ホストごとに別アカウントである。開発バックエンドが `localhost` から接続する場合は、`'pm_ai_reader'@'localhost'` にも同じ `SELECT` 権限が必要であり、`'pm_ai_reader'@'10.0.1.36'` だけでは利用できない。
