# 設備点検表仕様書

## 1. 目的

紙運用している設備点検表を、PMアプリ上で作成・確認・承認し、承認済みテンプレートを現場運用に利用できる状態にする。

対象ファイル:
- `板金3連定置SPOT 設備点検表（20250411).xlsx`
- 初期対象シート: `SM-009`

## 2. 画面構成

配置:
- `品質` → `設備点検表` → `点検項目作成`

画面:
- `点検項目作成`（`/quality/equipment-inspection/master`）
  - テンプレート一覧
  - テンプレート編集（ヘッダ + 点検項目）
  - ワークフロー操作
  - ワークフロー履歴

## 3. データモデル

### 3.1 設備点検表テンプレート

テーブル: `quality_equipment_inspection_template`

主要項目:
- `sheet_code`（例: SM-009）
- `sheet_name`（設備名）
- `title`（帳票タイトル）
- `source_sheet_name`（元シート名）
- `revision_date` / `effective_from`
- `version`
- `status`
- `created_by`, `reviewer_user`, `approver_user`
- `reviewed_by`, `reviewed_at`, `approved_by`, `approved_at`
- `rejection_comment`
- `is_active`

ステータス:
- `DRAFT`（下書き）
- `REVIEW_PENDING`（確認待ち）
- `APPROVAL_PENDING`（承認待ち）
- `APPROVED`（承認済み）
- `REJECTED`（差戻し）

### 3.2 設備点検項目

テーブル: `quality_equipment_inspection_item`

主要項目:
- `template`（FK）
- `section_type`（`DAILY` / `QUARTERLY`）
- `display_order`
- `inspection_no`
- `item_name`
- `standard`
- `frequency`
- `method`
- `record_type`（`CHECK` / `NUMERIC` / `TEXT`）
- `unit`
- `criteria`
- `is_required`
- `is_active`

### 3.3 ワークフロー履歴

テーブル: `quality_equipment_inspection_workflow_log`

主要項目:
- `template`（FK）
- `action`
- `from_status` / `to_status`
- `actor`
- `comment`
- `created_at`

## 4. ワークフロー

### 4.1 基本フロー

1. 作成者が下書き保存
2. 作成者が確認依頼
3. 確認担当が確認完了
4. 承認担当（部課長想定）が承認
5. 承認済みテンプレートを運用対象とする

差戻し:
- 確認待ち / 承認待ちの状態から差戻し可能
- 差戻し後は `REJECTED` となり、再編集後に再度確認依頼する

### 4.2 自動判定ルール（暫定）

作成者の `profile.department` / `profile.role` を基準に判定する。

- 確認担当:
  - 同部署
  - 作成者より上位役割
  - 候補役割: `supervisor`, `chief`, `manager`
  - 上位ランクが最も近いユーザーを採用

- 承認担当:
  - 同部署
  - 候補役割: `chief`, `manager`
  - 最上位ランクを採用

補足:
- 担当者が1名のみで確認/承認が同一になる場合は同一ユーザーを許容する。

## 5. API

ベース:
- `/api/equipment-inspection-templates/`

主なエンドポイント:
- `GET /` 一覧
- `POST /` 作成
- `GET /{id}/` 詳細
- `PUT /{id}/` 更新
- `DELETE /{id}/` 削除
- `POST /{id}/submit_for_review/` 確認依頼
- `POST /{id}/review/` 確認完了
- `POST /{id}/approve/` 承認
- `POST /{id}/reject/` 差戻し
- `GET /{id}/workflow_logs/` 履歴取得

## 6. 権限制御

本機能も既存ルールに従い、権限制御はフロントエンドUIのみで行う。

- 閲覧: `quality` の `can_view` 以上
- 編集/ワークフロー操作: `quality` の `can_edit`

バックエンド側では権限制御を行わず、認証のみ必須とする。

## 7. 初期データ

`SM-009` の点検項目（14項目）と定期実測項目（4項目）を、画面から読み込み可能な初期値として保持する。
