# 単独計画機能仕様書

## 概要

メイン工程の生産計画（工程ガント）を参照しながら、サブ工程の計画を独立して入力・保存する機能。
メインの生産計画入力（ProductionPlanInput）のLinePlan保存フローとは独立し、LineBacklog（seq>0）とLineGanttPlan（SINGLEPROC_プレフィクス）のみを操作する。

## 画面URL

`/production/sub-process-plan`

## 権限

`production.plan_input` の `edit` 権限が必要。

## 関連テーブル

### 読み取り

| テーブル | 用途 |
|---------|------|
| `t_line_backlog` | 参照工程の計画読込（`sequence_no > 0`） |
| `t_line_gantt_plan` | サブ工程の既存ガント読込、完成品エントリ読込 |
| `m_line` | ライン一覧（社内ライン `line_type='PROD'` のみ表示） |
| `m_process` | 工程一覧（参照工程・サブ工程の選択） |
| `m_product` / `m_routing_step` / `m_bom_item` | 関連製品候補の解決 |

### 読み書き

| テーブル | 用途 |
|---------|------|
| `t_line_backlog` | サブ工程計画の保存（`sequence_no > 0` の行を削除→再作成） |
| `t_line_gantt_plan` | サブ工程ガントの保存（`SINGLEPROC_` プレフィクス行を削除→再作成） |
| `t_production_plan_change_log` | 計画変更履歴の記録 |
| `production_plan_line_setting` | 候補製品の個別設定（`special_rules.sub_process_candidate_rules`） |
| `user_favorite` | お気に入りフィルタ条件 |

## plan_id の生成ルール

サブ工程計画の `plan_id` は以下の形式で生成される。

```
SINGLEPROC_{line_id}_{process_id}_{product_id}_{YYYYMMDD}_{sequence_no}
```

### 例

| ライン | 工程 | 製品 | 計画日 | 順序 | 生成される plan_id                    |
|--------|------|------|--------|------|---------------------------------------|
| 11     | 15   | 100  | 2026-06-29 | 1 | SINGLEPROC_11_15_100_20260629_1 |
| 11     | 15   | 200  | 2026-06-29 | 2 | SINGLEPROC_11_15_200_20260629_2 |

## 保存ロジック（sub_process_plan.py）

### 処理フロー

1. `target_dates`（画面の表示期間全日）と `entries`（入力データ）を受け取る
2. `target_dates` の該当工程・ラインの `LineBacklog`（`sequence_no > 0`）を全削除
3. `target_dates` の該当 `SINGLEPROC_` プレフィクスの `LineGanttPlan` を全削除
4. `entries` から `LineBacklog` を `bulk_create`
5. サイクルタイムを元にガント時間を計算し `LineGanttPlan` を `bulk_create`
6. 変更前後の数量差分があれば `ProductionPlanChangeLog` に記録

### LinePlan との関係

- **LinePlan は一切触らない**。サブ工程計画はメインの計画フロー（pickup → save → expand → recalculate → generate）とは独立。
- LineBacklog の `sequence_no > 0` の行のみ操作し、`sequence_no = 0`（需要専用行）は対象外。

### 連産品展開

- 入力品番が連産品親（`BOM.is_coproduct=True`）の場合、子品番に展開して `LineBacklog` を作成
- 展開後の数量 = 入力数量 × BOM倍率（`bom_item.quantity`）
- `LineGanttPlan` は展開前の親品番で作成（ガントは入力単位）

### サイクルタイム解決

1. 連産品の場合: driver子品番 → `RoutingStep`（`output_product = driver`）の `duration_min`
2. 非連産品の場合: `RoutingStep`（`routing.product_id`）の `duration_min`、未ヒット時は `output_product_id` でフォールバック
3. 未解決の場合: 所要時間0（ゼロ幅バー）としてログに警告出力

### ガント時間計算

- 日ごとにエントリを順序順にソートし、前のバーの終了時刻を次のバーの開始時刻とする
- 勤務カレンダに基づき、稼働時間内に収まるよう `add_working_minutes` で計算
- 開始時刻: ライン×工程のガント開始時刻設定（未設定時は 08:00）

## フロントエンド仕様

### 画面構成

1. **ヘッダーバー**（1行）: ライン・参照工程・サブ工程・期間・読込/保存・土日非表示・お気に入り・データソースダイアログ
2. **候補製品編集パネル**（折りたたみ）: サブ工程に関連する製品の選択フィルタ
3. **参照グリッド**: 参照工程の `LineBacklog(sequence_no > 0)` を読み取り専用で日別・順序別に表示
4. **入力グリッド**: サブ工程の計画を日別・順序別に製品選択＋数量入力
5. **工程ガント**: ProcessGanttView 埋め込み（サブ工程のみフィルタ表示）

### 操作フロー

1. 参照ライン・参照工程・サブ工程・期間を選択
2. 「読込」でデータ取得
3. 参照グリッドを見ながら、入力グリッドで製品と数量を入力
4. 「保存」で登録（バックエンドで LineBacklog + LineGanttPlan を再作成）
5. 保存後、工程ガントが自動リロードされ結果を確認

### 候補製品の解決

1. `api.processes.getRelatedProducts(processId)` でサブ工程に関連する製品を取得
2. `production_plan_line_setting.special_rules.sub_process_candidate_rules` に個別設定がある場合、指定品番のみ表示
3. 個別設定がない場合、関連製品をすべて表示

### お気に入り

- `screen_key`: `production.sub_process_plan`
- 保存内容: `lineId`, `refProcessId`, `subProcessId`

### 土日非表示

- ヘッダーのチェックボックスで切替
- `localStorage` キー: `subProcessPlan.hideWeekends`
- グリッド表示のみフィルタし、保存時は期間全日の `target_dates` を送信（土日データが残らないよう対応済み）

## 注意事項

- この画面の保存は **在庫再計算・工程展開を実行しない**。必要に応じて生産計画入力画面から実行すること。
- ガントの時間・数量の直接編集は、工程ガント部分の「時間数量保存」「追加削除保存」ボタンで別途保存する。
