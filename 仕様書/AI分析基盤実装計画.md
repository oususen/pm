# PM社内AI分析基盤 実装計画

更新日：2026-10-09

## 1. 目的

PMの業務データを、利用者が目的・手順・データ範囲を確認したうえで分析できるようにする。AIが作るSQL・Pythonは隔離した環境で実行し、表・グラフ・報告書として結果を表示する。

利用価値のある分析はテンプレートとして保存し、管理者の確認を経て再利用する。現在の再利用は、保存済みコードの変数だけを変更する方式。テンプレートを参考に新しいコードを生成する方式は、将来の追加機能として分ける。

正式な仕様は[AI分析基盤仕様書](AI分析基盤仕様書.md)、権限は[権限仕様書](権限仕様書.md)に従う。本計画は現在の進捗と残作業を管理し、コミット履歴は記載しない。

## 2. 現段階の実装計画と進捗

### 2.1 現在の到達点

開発環境では、分析案の作成から、承認・コード生成・隔離実行・結果表示・テンプレートの保存と再利用まで実装している。テンプレート再利用時に、期間・品番などを入力する画面も実装済み。

ただし、実装済みは、すべての検証・本番反映が完了したことを意味しない。修正後の再レビュー、実ブラウザ、本番などの未確認事項は第3章にまとめる。

重複していた「2-C」等の呼び方は、本計画では「実行・結果画面」「テンプレート再利用の入力画面」のような機能名で区別する。

### 2.3 開発と本番の区別

- 開発：WSL2のlauncher・ジョブ用コンテナと、Windows側の専用ワーカーを使う。起動・確認・停止は `analysis-dev-start.bat`／`analysis-dev-status.bat`／`analysis-dev-stop.bat`。手順は[開発用起動手順書](../analysis-sandbox/開発用_分析AI起動手順書.md)を参照。
- 本番：分析実行基盤は未対応・無効。SQL試行を含む通常のコード承認・実行フローは完了できない。分析案・コード表示・履歴・テンプレート等の本番反映と正常稼働も、今回確認していない。
- 本番のビュー定義者変更や入荷日形式の修正については、BOSSが実施・確認した記録がある。これは、本番の分析実行基盤が稼働したことを意味しない。
- 本番の分析実行は、BOSS方針の **PC入替 → PostgreSQL移行 → AI層移植 → 本番の分析実行** の順で進める。
- 反映時の注意：`analysis_guard_runtime.py`の変更で外枠の版が変わっている。旧版の保存済みコードを使う際は外枠の更新と、再試行・再承認が必要。外枠の更新自体はAIを呼ばず、生成回数を消費しない。本番での試行・実行には、別途実行基盤の準備が必要。

## 3. 実装中の記録

ここには、実装後も修正・検証・判断が残っている項目を記録する。完了した変更の報告を繰り返し追記せず、項目ごとに現在の状態を更新する。

### 3.1 テンプレート再利用の入力画面

- 実装：全体期間・比較／除外期間・品番・顧客コード・納入先コードの入力、変更値だけの送信、取消、今回使う値の表示、固定文によるエラー案内。
- 承認済みの扱い：全体期間は元の範囲の外へも変更可。比較／除外期間が全体期間を外れれば拒否。空欄を「除外なし」や保存済みの値へ置き換えない。成功時だけ分析案を切り替え、データ範囲・件数・試行・コード承認を取り直す。
- 初回レビュー：重大な欠陥はなく、遅延応答による状態の上書き、再利用ボタン押し直しでの入力消失、案内文とテストの不足を指摘。
- 修正：要求の識別番号・開始時の分析案・編集権限で古い応答を採用しない。同じテンプレートでは入力を保持し、変更のある別テンプレートへの切替は破棄を確認。関連する回帰テストを追加した記録あり。
- 残る確認：修正後の独立再レビュー、実ブラウザでの入力・取消・切替・権限喪失・遅延応答。
- 残る制約：保存済みの既定値の不備と今回の入力値の不備は、理由表示で区別していない。目的・手順の文章は保存時のままで、変更値へ自動で書き換えない。

詳細：[仕様書](AI分析基盤仕様書.md) §5.3-5b。

### 3.2 コード生成の安定化と失敗の案内

| 内容 | 実施済み・確認記録 | 残る確認・制約 |
|---|---|---|
| 複数品番・期間の変数化 | 指示と見本、コード内の固定値の警告を追加 | 後半に追加した品番の警告・複数品番の見本は、独立レビュー（Codex検証を含む）未実施。小さいモデルを含む実AIでの安定性も確認が必要 |
| 期間・列の警告 | 目的と期間、列の食い違い、片側だけの除外期間を警告 | 文面の機械的な照合であり誤検知・見逃しあり。警告は承認を妨げない |
| 日付の文字列化 | 実行時のtime import許可を分離し、直接のimportは禁止を維持。実機でstrftimeのimport失敗が解消した記録あり | strptimeは使用不可。日付がNULLの場合など別のコード不備は解決しない。各形式の実Docker確認・再生成後の結果照合は別途必要 |
| 子Python・AI通信の失敗 | 例外名・GuardErrorの許可された固定コード、通信失敗の固定理由を表示 | 実データや例外本文を表示しない方針を維持。失敗の分類と実機での案内を継続確認 |
| 待ち表示・自動更新・通知 | 経過秒、進行中だけの状態GET、終了通知、エラー帯を実装 | 実ブラウザでの長時間待機、連続通信失敗、読み上げ・動きを減らす設定などは未確認 |

生成コードが検査・試行に合格しても、分析結果が正しいとは限らない。実行結果はDB側の集計と照合して確認する。過去の特定モデル・特定目的での成功を、全モデル・全分析の成功とは扱わない。

レビューの状態は変更単位で区別する。テンプレート再利用の入力画面は初回レビュー済み・修正後の再レビュー待ち。後半に追加した品番の警告・見本、テンプレート名の変更は、初回の独立レビューが未実施であり、「再レビュー待ち」や「検証済み」とは扱わない。

### 3.3 基盤・権限・通知の残る確認

- readerは既存チャットと共用し、元テーブルのSELECT権限もある記録。分析用ビューだけに限定するための接続・権限分離は未完了。
- 大きな実DBでの取得・転送性能、既存の上限・期限・チャンクなどの暫定値の妥当性。
- 独立ワーカーの異常停止、複数利用者・複数タブ、後始末未確認からの復旧コマンドの実環境確認。
- 旧版ワーカー拒否・権限剥奪・本人と他人の操作、履歴ページ送り・閲覧専用表示の実ブラウザ確認。
- 管理者承認・訂正版の実DBでの競合、実メール到達、送信者・宛先・基準URL・本番マイグレーションの確認。
- 通知処理はプロセス停止で送信結果が不明になる場合がある。SMTPの待ち時間は操作ごとで、送信全体の期限ではない。現行方式の制約として、運用前に確認する。
- 履歴の保存期間、試行回数／間隔の制限はBOSS判断待ち。未承認の上限や自動フォールバックを追加しない。

## 4. 将来実装予定

以下は現在実装済みの機能とは分ける。実施時期・範囲が未決の項目は、BOSS承認後に現段階の計画へ移す。

| 予定・検討項目 | 内容 | 状態・着手条件 |
|---|---|---|
| テンプレートを参考に新規生成 | 保存済みの目的・手順・SQL・Pythonを参考に、今回の目的へ合わせた新しい分析案・コードを生成する | [個別計画](AI分析_テンプレート参照生成実装計画.md)あり、BOSS承認待ち・未実装。社外送信内容、権限、記録先、ローカルAIの文脈長を決める。元テンプレートは変更せず、承認は取り直す案 |
| 相談画面からの変数入力 | 推薦されたテンプレートでも、使用する値を入力・確認して再利用する | 未実装。現在のテンプレート画面への実装とは別 |
| 前のコードを使った結果の改良 | 前回のSQL・PythonをAIへ渡して修正する | 未実装・範囲未決。現在の「追加指示から新しい分析案を作る」方式とは別 |
| 成長率の0除算への対応 | 前の期間の数量が0の場合に、成長率をどう計算・表示するかを決める | 方針未決。0%などへ自動で置き換えず、業務上の意味とNULLの扱いをBOSSが確認してから実装・検証する |
| 2つのビューを比べる分析の改善 | 片方にしかない行やNULLを含む比較で、欠落・二重計上・Pythonの異常終了を防ぐ | UNION ALLで積み上げて集計する指示・見本は追加済み。ただし、実機で再生成しての結果確認は未実施。DB集計との照合後に、追加の対策の要否を判断する |
| AI用ビューの拡張 | 生産実績、確定仕損、残業などの分析対象を追加する | 未着手。対象テーブル・結合・数量の意味・公開列・個人情報を別計画で確定。既存の入荷・出荷ビューの拡張も同様 |
| 資料取込み・追加条件 | 現在のビュー・期間以外の情報や絞り込みを扱う | 未実装。取得元・保存・外部送信・承認の扱いを事前に決める |
| 公開定義の変更検知 | ビュー・列名だけでなく、列型や業務上の意味の変更を検知する | 現行の確認範囲を超えるため別途設計・承認が必要 |
| 本番実行基盤 | 自動起動、launcher認証、復旧、監視、Docker権限の最小化・ホスト分離を設計する | PC入替・PostgreSQL移行・AI層移植の後。方式・時期はBOSS判断。現行の開発基盤をそのまま本番へ有効化しない |

本計画の整理は、将来機能の実装、上限・フォールバックの新設、DB変更や本番反映を承認するものではない。
