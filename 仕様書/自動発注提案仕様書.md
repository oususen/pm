# 自動発注提案 機能仕様書

---

## 全体フロー

```
① 仕入先ごとに発注タイミングパターンを設定（例: 第2火曜日、毎月15日）
  ↓
② 毎日システムが発注タイミングを確認
  ↓
③ 発注日に該当 → 業務員に「発注提案書作成」タスクを通知
  ↓
④ 業務員が発注提案書を作成（自動提案 or 手動入力）し、サイン（Level 1 承認）
  ↓
⑤ 班長に「承認」タスクを通知 → 承認
  ↓
⑥ 係長に「承認」タスクを通知 → 承認
  ↓
⑦ 事業部長に「承認」タスクを通知 → 承認（最終）
  ↓
⑧ 作成者に「注文書作成」タスクを通知
  ↓
⑨ 作成者が注文書PDFを作成
  ↓
⑩ 作成者に「購入先送信」タスクを通知
  ↓
⑪ 作成者が発注書を購入先へ送信（メール）
```

### B. 新テーブル：`supplier_order_schedule`（仕入先発注スケジュール）

仕入先ごとに複数のパターンを登録可能。

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `supplier` | FK→Supplier | 対象仕入先 |
| `pattern_type` | CharField | パターン種別（後述） |
| `nth_week` | SmallIntegerField (nullable) | 第N週（1〜5）※WEEKLY_NTH_DAY用 |
| `day_of_week` | SmallIntegerField (nullable) | 曜日（0=月〜6=日）※WEEKLY_NTH_DAY / EVERY_WEEK用 |
| `day_of_month` | SmallIntegerField (nullable) | 日付（1〜31）※MONTHLY_DATE用 |
| `lead_time_days` | PositiveIntegerField (default=0) | 発注〜納入のリードタイム（仕入先カレンダーの営業日換算） |
| `is_enabled` | BooleanField (default=True) | 有効/無効 |
| `note` | CharField (nullable) | 備考 |

#### パターン種別（`pattern_type`）

| コード | 説明 | 使用フィールド |
| --- | --- | --- |
| `WEEKLY_NTH_DAY` | 月の第N週の何曜日（例: 第2火曜日） | `nth_week`, `day_of_week` |
| `MONTHLY_DATE` | 月の何日（例: 毎月15日） | `day_of_month` |
| `EVERY_WEEK` | 毎週の何曜日（例: 毎週月曜日） | `day_of_week` |

> パターン判定時、該当日が非稼働日だった場合は**直前の稼働日**に繰り上げる。
> 参照カレンダーは**ダイソウカレンダー**（自社カレンダー）。
> 理由：発注書を作成するのは自社の事務員であるため、仕入先の稼働日ではなく
> 自社の稼働日を基準とする。
> （仕入先カレンダーはリードタイム換算のみに使用する）

## 発注数量の自動提案ロジック

```
対象: 仕入先に紐づく購買ライン(PURCHASE)の全製品

提案元 = 進度 or 計画在庫（UIボタンで選択）

[計画在庫から提案]
shortage_qty = 計画期間内の (min_stock_qty - planned_stock_qty) の最大値
              ※ shortage_qty <= 0 の場合はスキップ

[進度から提案]
shortage_qty = 計画期間内の abs(progress_qty) の最大値（progress_qty < 0 の日のみ対象）
              ※ shortage_qty <= 0 の場合はスキップ

order_qty    = ceil(shortage_qty / order_lot_multiple) × order_lot_multiple
order_qty    = max(order_qty, order_lot_min)

desired_delivery_date = 既存値を保持（自動提案では変更しない）
order_date            = 発注タイミングスケジュールの該当日
```

> 手動作成時は業務員が `order_qty` を直接入力できる。

## 発注タイミング日次チェックロジック

毎日（定時タスク）実行：

```
1. 有効な SupplierOrderSchedule を全件取得
2. 各スケジュールについて「今日が発注日か」を判定
   - WEEKLY_NTH_DAY: 今月の第N週・指定曜日と一致するか
   - MONTHLY_DATE:   今日の日付が day_of_month と一致するか
   - EVERY_WEEK:     今日の曜日が day_of_week と一致するか
3. 非稼働日の場合は直前の稼働日に繰り上げ（ダイソウカレンダー参照）
   ※ 仕入先カレンダーはリードタイム換算にのみ使用する
4. 発注日と判定された仕入先について：
   - 当日分のタスク(CREATE_PROPOSAL)が未生成の場合のみ作成
   - 業務員（APPROVE_L1 設定ユーザー）にタスク・通知を送出
```

## タスク・通知フロー

| ステップ | トリガー | タスク種別 | タスク担当 | 通知先 |
| --- | --- | --- | --- | --- |
| 発注日到来 | 日次チェック | `CREATE_PROPOSAL` | 業務員 | 業務員 |
| 業務員サイン | 提案書 SUBMITTED | `APPROVE_L2` | 班長 | 班長（作成者の所属班の班長を優先。該当なし時はレベル2設定へフォールバック） |
| 班長承認 | APPROVED_L2 | `APPROVE_L3` | 係長 | 係長 |
| 係長承認 | APPROVED_L3 | `APPROVE_L4` | 事業部長 | 事業部長 |
| 事業部長承認 | APPROVED | `CREATE_ORDER_PDF` | 作成者 | 作成者 |
| 注文書作成 | PDF出力実行 | `SEND_TO_SUPPLIER` | 作成者 | 作成者 |
| 差戻 | REJECTED | ― | 作成者（業務員） | 作成者 + 前レベル承認者 |

※ 購買通知の「入力者（operator_name）」は、原則として提案書の作成者を表示する。

### L2（班長）通知先の決定ルール

業務員サイン時（`SUBMITTED` 遷移時）の `APPROVE_L2` タスク担当は、以下の順で解決する。

1. レベル2（班長）の「承認可能ユーザー」設定を取得
2. 作成者の所属班（`profile.team`）がある場合、同一班かつ `role=supervisor` のユーザーを優先
3. 所属班が未設定で所属係（`profile.group`）のみある場合、同一係かつ `role=supervisor` のユーザーを優先
4. 上記で該当がない場合、レベル2設定ユーザー全員へフォールバック
5. 通知は上記担当者 + レベル2の「通知先ユーザー」へ送信

## 購入先への送信（Step 9）

- 最終承認後、詳細画面の「注文書作成」ボタンで **発注書PDF** を出力
- 「購入先へ送信」ボタンは、注文書作成実行後（`SEND_TO_SUPPLIER` タスク生成後）に表示
- 「購入先へ送信」ボタン押下時、`Supplier.order_email` 宛にPDFを添付して送信
- 送信時にPDFを `MEDIA_ROOT/purchase_orders/{YYYY}/{MM}/{supplier_code}/` 配下へ保存
- メール送信はログインユーザーのSMTP設定（未設定時は管理者SMTP）を使用
- 送信成功時にステータスを `SENT` へ更新し、`sent_at` を記録

## 実装スコープ（Phase 分割案）

| Phase | 内容 |
| --- | --- |
| **Phase 1** | マスタ拡張（Supplier.calendar, Product.lot）、SupplierOrderSchedule モデル・設定画面 |
| **Phase 2** | 日次チェックタスク・タスクモデル・通知、発注提案書モデル・API |
| **Phase 3** | 承認フロー API（submit / approve / reject / send）、承認者設定 |
| **Phase 4** | フロントエンド（一覧・詳細・承認操作）、PDF出力 |
