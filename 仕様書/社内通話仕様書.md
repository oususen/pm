# 社内通話仕様書

## 目的

通知タブ配下で、社員同士が 1対1 の音声通話・ビデオ通話を行えるようにする。

## 構成

- フロントエンド: `pm-ui/src/views/notifications/NotificationCallCenter.vue`
- 共通着信監視/Push購読: `pm-ui/src/components/GlobalNavigation.vue`
- Service Worker: `pm-ui/public/sw.js`
- バックエンド: `notifications` アプリ
- 通話方式: WebRTC
- シグナリング: REST API + フロント側ポーリング
- バックグラウンド着信: Web Push

## 画面

- 画面URL: `/notifications/calls`
- 通知一覧のヘッダーから「通話」ボタンで遷移
- 全画面共通で着信監視を行う（`GlobalNavigation.vue`）
- 主な要素
  - 相手選択
  - 音声発信
  - ビデオ発信
  - 着信一覧
  - 最近の通話一覧
  - ローカル映像 / リモート映像
  - 録音中表示
  - 応答 / 辞退 / 終了
  - マイクON/OFF
  - カメラON/OFF

## 着信UI

- 着信中はヘッダー右上に `📞 着信中` バッジを表示する
- 着信中は全画面共通のポップアップを表示する
- ポップアップから以下を実行できる
  - 通話画面へ移動
  - 消音
  - 辞退
- 着信中はブラウザ内で着信音を繰り返し再生する
- 通知ベルの未読一覧で着信通知をクリックした場合、対象セッションの通話画面へ即遷移する

## 権限

- 権限制御はフロントエンドUIのみ
- 必要権限は `notifications / can_view` とする
- URL直打ちは従来どおり許容

## データモデル

### `call_sessions`

- `caller`: 発信者
- `callee`: 着信者
- `call_type`: `voice` / `video`
- `status`: `ringing` / `accepted` / `declined` / `ended` / `missed` / `canceled`
- `initiated_at`: 発信日時
- `accepted_at`: 応答日時
- `ended_at`: 終了日時

### `call_signals`

- `session`: 対象通話
- `sender`: 送信者
- `target_user`: 宛先ユーザー
- `signal_type`: `offer` / `answer` / `ice_candidate` / `hangup`
- `payload`: SDP / ICE candidate JSON
- `created_at`: 作成日時

### `call_recordings`（追加予定）

- `session`: 対象通話
- `recording_started_at`: 録音開始日時
- `recording_ended_at`: 録音終了日時
- `file_path` または保存先識別子
- `file_size`
- `mime_type`
- `created_at`: 作成日時
- 保存期間は半永久とする

### `call_transcripts`（追加予定）

- `session`: 対象通話
- `source_language`: 元言語
- `transcript_text`: 文字起こし原文
- `translated_text_ja`: 日本語翻訳文
- `status`: `pending` / `processing` / `completed` / `failed`
- `created_at`: 作成日時
- `updated_at`: 更新日時
- 全通話を文字起こし対象とする

### `push_subscriptions`

- `user`: 購読ユーザー
- `endpoint`: Push配信先
- `p256dh_key`: ブラウザ公開鍵
- `auth_key`: 認証鍵
- `user_agent`: 端末識別用補助情報
- `created_at`: 作成日時
- `updated_at`: 更新日時

## API

### 通話セッション

- `GET /api/call-sessions/`
  - 自分が参加者の通話一覧を返す
  - `status=ringing,accepted` のようなカンマ区切り指定可
- `GET /api/call-sessions/{id}/`
  - 通話詳細
- `POST /api/call-sessions/start/`
  - 発信開始
  - body: `{ "callee_id": 12, "call_type": "voice" | "video" }`
- `POST /api/call-sessions/{id}/accept/`
  - 着信応答
- `POST /api/call-sessions/{id}/decline/`
  - 着信辞退
- `POST /api/call-sessions/{id}/finish/`
  - 通話終了 / 発信キャンセル

### 録音・文字起こし（追加予定）

- `POST /api/call-sessions/{id}/recording/`
  - 通話録音ファイルを登録する
- `GET /api/call-sessions/{id}/recording/`
  - 録音情報を取得する
- `GET /api/call-sessions/{id}/transcript/`
  - 文字起こし・翻訳結果を取得する

### シグナリング

- `GET /api/call-sessions/{id}/signals/?after_id=10`
  - 自分宛てシグナルを ID 昇順で返す
- `POST /api/call-sessions/{id}/signals/`
  - body:
  ```json
  {
    "target_user": 34,
    "signal_type": "offer",
    "payload": {
      "type": "offer",
      "sdp": "..."
    }
  }
  ```

### Push購読

- `GET /api/push-subscriptions/config/`
  - Push機能有効フラグと VAPID 公開鍵を返す
- `GET /api/push-subscriptions/`
  - 自分の購読一覧
- `POST /api/push-subscriptions/`
  - 購読情報を登録または更新
  - body:
  ```json
  {
    "endpoint": "...",
    "p256dh_key": "...",
    "auth_key": "...",
    "user_agent": "Mozilla/5.0 ..."
  }
  ```
- `POST /api/push-subscriptions/unsubscribe/`
  - 購読解除
  - body: `{ "endpoint": "..." }`

## 着信通知

- 発信時、既存 `notifications` テーブルにも着信通知を1件作成する
- `domain=call`
- 対象ユーザーは着信者
- 通知文面に対象セッションIDを含める
- ヘッダー側では通知本文からセッションIDを読み取り、対象通話へ遷移する
- 着信者が Push 購読済みなら Web Push も送信する
- Push 通知タップ時は対象セッション付きの通話画面を開く

## 動作フロー

1. 発信者が相手を選び、音声またはビデオで発信
2. `call_sessions` を `ringing` で作成
3. 着信者向けに通常通知を1件作成
4. 着信者の Push 購読があれば Web Push を送信
5. 発信者が `offer` を送信
6. 着信者が応答すると `accepted`
7. 着信者が `offer` を受信して `answer` を返す
8. 双方が `ice_candidate` を交換して接続確立
9. 終了時は `finish` と `hangup` を送信
10. 通話開始と同時に録音を自動開始する
11. 通話終了後、録音データを保存する
12. 保存後、全通話に対して文字起こし処理を実行する
13. 元言語が日本語以外の場合も含め、日本語翻訳結果を生成する

## 制約

- 1対1 通話のみ対応
- グループ通話、画面共有、TURN サーバーは未対応
- リアルタイム反映は WebSocket ではなくポーリングで実現
- マイク・カメラ取得のため、ブラウザでは `HTTPS` または `localhost` で開く必要がある
- Push 通知は `HTTPS` 前提
- Push を有効化するには Django 環境変数 `WEB_PUSH_VAPID_PUBLIC_KEY` / `WEB_PUSH_VAPID_PRIVATE_KEY` / `WEB_PUSH_VAPID_SUBJECT` の設定と、`pywebpush` の導入が必要

## 録音・文字起こし・翻訳の追加要件

- 録音は通話開始時に自動開始する
- 録音中であることを通話参加者全員に表示する
- 録音データは半永久保存とする
- 文字起こし対象は全通話とする
- 翻訳対象言語は、現在の `i18n` で対応している言語とする
- 翻訳結果の閲覧は、話者本人とその上位者に限定する
- 権限制御は既存方針どおりバックエンドではなくフロントエンドUIで行う
