# 在庫・進度調整画面仕様書

## 1. 対象画面

- メニュー: `在庫 -> 調整`
- 画面:
  - 在庫調整（`STOCK`）
  - 計画在庫調整（`PLANNED_STOCK`）
  - 進度調整（`PROGRESS`）
  - 計画進度調整（`PLANNED_PROGRESS`）

## 2. 画面共通仕様

- 左側
  - 品番入力で製品を解決
  - 多工程時は工程一覧を表示し、選択工程のみを調整対象にする
  - 項目: 工程順位 / 工程CD / 工程名 / ラインCD / ライン名 / 表示開始日
- 右側
  - 日付30日分を表示
  - 休日（土日 + daisoカレンダー非稼働日）は赤系表示
  - `今回調整値` 入力時に即時プレビュー（進度/在庫値の見え方を即時更新）
  - 入力行の日付を調整日に同期

## 3. 品番解決ルール

- 基本は Routing / RoutingStep から工程候補を作成
- Routingがない場合は BOM明細から候補化
- 購入品・外作（`BUY` / `SUBCON` または `supplier` 設定あり）はBOM優先
  - ラインCD/ライン名は仕入先コード/仕入先名を使用可能
- `lineCode` / `processCode` しかない場合でも、再読込時に `lineId` / `processId` を自動解決する

## 5. データ取得・保存

- 表示データ:
  - `line-backlogs` を日付集計して表示
  - 取得条件は選択中の `line / product / process`
- 調整値:
  - `line-backlog-adjustments` で取得・保存
  - キー: `line + product + process + plan_date + adjust_type`

## 6. 補足

- 進度・在庫の計算ロジック本体は既存計算処理を利用し、画面は調整値入力と可視化を担う
- 権限制御はフロントUIで実施（バックエンド権限チェックなし）

## 7. 調整値の保存先と反映タイミング

- 本画面（在庫調整/計画在庫調整/進度調整/計画進度調整）の `登録` は、`production_line_backlog_adjustment` に保存する。
  - キー: `line + product + process + plan_date + adjust_type`
- 保存直後は画面内プレビューに反映されるが、`LineBacklog` 本体値（`stock_qty` / `progress_qty` など）へは即時反映しない。
- 在庫・進度への反映は再計算実行時（在庫再計算/進度再計算）に行う。

## 8. 在庫残量画面との違い

- 在庫残量画面（在庫/残量一覧）の「調整」は `LineBacklog.adjust_qty` を対象とした別系統の調整である。
- 本画面の調整（`production_line_backlog_adjustment`）とは保存先・参照先が異なるため、同じ「調整」名称でも値は一致しない場合がある。

## 9. 画面内説明文の出し分け

- 工程情報下の説明文は画面種別（`adjust_type`）ごとに出し分ける。
  - `STOCK`: 在庫再計算後に在庫へ反映
  - `PLANNED_STOCK`: 在庫再計算後に計画在庫へ反映
  - `PROGRESS`: 進度再計算後に進度へ反映
  - `PLANNED_PROGRESS`: 進度再計算後に計画進度へ反映
