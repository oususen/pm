# 在庫・進度調整画面仕様書

## 1. 対象画面

- メニュー: `在庫 -> 調整`
- 画面:
  - 在庫調整（`STOCK`）
  - 計画在庫調整（`PLANNED_STOCK`）
  - 進度調整（`PROGRESS`）
  - 計画進度調整（`PLANNED_PROGRESS`）

## 2. 画面共通仕様

- 左側
  - 品番入力で製品を解決
  - 多工程時は工程一覧を表示し、選択工程のみを調整対象にする
  - 項目: 工程順位 / 工程CD / 工程名 / ラインCD / ライン名 / 表示開始日
- 右側
  - 日付30日分を表示
  - 休日（土日 + daisoカレンダー非稼働日）は赤系表示
  - `今回調整値` 入力時に即時プレビュー（進度/在庫値の見え方を即時更新）
  - 入力行の日付を調整日に同期

## 3. 品番解決ルール

- 基本は Routing / RoutingStep から工程候補を作成
- Routingがない場合は BOM明細から候補化
- 購入品・外作（`BUY` / `SUBCON` または `supplier` 設定あり）はBOM優先
  - ラインCD/ライン名は仕入先コード/仕入先名を使用可能
- `lineCode` / `processCode` しかない場合でも、再読込時に `lineId` / `processId` を自動解決する

## 5. データ取得・保存

- 表示データ:
  - `line-backlogs` を日付集計して表示
  - 取得条件は選択中の `line / product / process`
- 調整値:
  - `line-backlog-adjustments` で取得・保存
  - キー: `line + product + process + plan_date + adjust_type`

## 6. 補足

- 進度・在庫の計算ロジック本体は既存計算処理を利用し、画面は調整値入力と可視化を担う
- 権限制御はフロントUIで実施（バックエンド権限チェックなし）
- 進度表示用の基礎行補完で `LineDemand.routing_step.process` が解決できない場合、補完を中断し API は `BACKLOG_PROCESS_MISSING` を返す。この場合は工程補完を行わず、管理者通知対象とする

## 7. 調整値の保存先と反映タイミング

- 本画面（在庫調整/計画在庫調整/進度調整/計画進度調整）の `登録` は、`production_line_backlog_adjustment` に保存する。
  - キー: `line + product + process + plan_date + adjust_type`
- 保存直後は画面内プレビューに反映されるが、`LineBacklog` 本体値（`stock_qty` / `progress_qty` など）へは即時反映しない。
- 在庫・進度への反映は再計算実行時（在庫再計算/進度再計算）に行う。

## 8. 在庫残量画面との違い

- 在庫残量画面（在庫/残量一覧）の「調整」は `LineBacklog.adjust_qty` を対象とした別系統の調整である。
- 本画面の調整（`production_line_backlog_adjustment`）とは保存先・参照先が異なるため、同じ「調整」名称でも値は一致しない場合がある。

## 9. 画面内説明文の出し分け

- 工程情報下の説明文は画面種別（`adjust_type`）ごとに出し分ける。
  - `STOCK`: 在庫再計算後に在庫へ反映
  - `PLANNED_STOCK`: 在庫再計算後に計画在庫へ反映
  - `PROGRESS`: 進度再計算後に進度へ反映
  - `PLANNED_PROGRESS`: 進度再計算後に計画進度へ反映

## 10. 一括タブの再計算動作

一括タブでは調整値を保存後、`adjust_type` に応じて再計算APIの呼び出し方を切り替える。

- 一括タブの `調整対象日` はユーザーが指定できる。
- 一括保存時は各品番の `calc_start_date` 固定ではなく、指定した `調整対象日` に `production_line_backlog_adjustment` を保存する。
- 一括再計算の開始日も、指定した `調整対象日` を使用する。

| adjust_type | APIパラメータ | 説明 |
|-------------|-------------|------|
| STOCK / PLANNED_STOCK | `include_progress: false` | 在庫・計画在庫のみ再計算。進度はスキップ |
| PROGRESS / PLANNED_PROGRESS | `progress_only: true` | 進度・計画進度のみ再計算。在庫・仕損集計はスキップ |

再計算対象は工程の対象品のみ（`product_ids` で絞り込み）。`line_id` でグループ化して並列実行する。

## 11. 調整履歴画面

### 概要

`/inventory/adjustments/history` に遷移する調整履歴一覧画面（`AdjustmentHistory.vue`）。
在庫調整メニューの「調整履歴」タイルからアクセスする。

### 表示データ

`GET /api/line-backlog-adjustments/` を呼び出し、登録済みの調整値一覧を表示する。

### APIレスポンス追加フィールド

`LineBacklogAdjustmentSerializer` に `updated_by_name` フィールドを追加。

| フィールド | 説明 |
|-----------|------|
| updated_by_name | 更新者の氏名（未設定の場合はusername） |
