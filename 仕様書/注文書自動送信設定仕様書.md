# 注文書自動送信設定 仕様書

## 概要

既存の `自動納入リスト送信` とは別機能として、注文書Excelを自動送信する。

- メニュー: `仕入れ > 業務自動タスク > 注文書自動送信設定`
- URL: `/purchase/auto-order-send`

本機能は、Excel生成時点で `LineBacklog(sequence_no=1).plan_qty` へ計画保存を行う。

## 設定項目

- `lead_time_days`
  - 納入日（実行日から何営業日後か）
- `progress_days_back`
  - 進度再計算の開始日。発行日の何営業日前から再計算するか
- `progress_days_forward`
  - 対象納入回の探索終端と、進度再計算の終了日の基準。発行日の何日後までを見るか
- `calc_mode`
  - `需要そのまま / ロット丸め`
- `send_order_excel`
  - 注文書Excelを添付するか
- `send_delivery_note_pdf`
  - 外作納品書PDFを添付するか

設定の見せ方は、既存の `自動納入リスト送信` と同じく
`納入日（何営業日後）` と `進度表期間（何営業日前 ～ 何日後）`
で統一する。

## 数量計算

- 基準は在庫ではなく `計進(planned_progress_qty)`
- 納入日は `lead_time_days` で決める
- 納入回の探索終端は `progress_days_forward` 日後を使う
- その範囲内で最初に到達する納入日 1 回分だけを対象にする
- 本タスクは毎日実行する前提のため、次回納入日は後日の実行で別途処理する
- 対象需要は、その納入日から次回納入日前日までの需要合計とする
- ただし差分計算に使う計進は**納入日前日**の `planned_progress_qty` を基準とする

### 必要数

- `差分 = カバー期間需要 - 納入日前日計進`
- `差分 > 0` のときだけ計画を作成する
- `差分 <= 0` のときは納入不要とし、計画は保存しない

### ロット丸め

`calc_mode = LOT_ROUNDED` の場合:

- `基準数量 = max(必要数, 最小納入数)`
- `丸め後数量 = ceil(基準数量 / 納入倍数) × 納入倍数`
- 最終的な納入数は、必ず `納入倍数` の倍数にする

ロット設定は `Product.order_lot_min / Product.order_lot_multiple` を使用する。

## 保存ルール

- 保存先: `LineBacklog`
- キー: `line, process, product, plan_date, sequence_no=1`
- 保存値: `plan_qty`
- 対象納入日に `production_lock(lock_type='auto_plan')` がある場合、既存計画削除前に `line + product + plan_date + process + locked_qty` を実行中メモとして保持する。
- 対象納入日の既存計画削除後、メモしたロック計画を `LineBacklog(sequence_no=1).plan_qty = locked_qty` として復元してから先頭の進度再計算を実行する。
- 注文計画を再作成した後も同じロック計画を復元し、後尾の進度再計算と注文書作成は復元後の数量を使用する。
- ロック数量が0の場合、計画は0として復元するが、注文書明細には出力しない。
- `production_lock` には `process_id` を保存しない。注文書自動送信では削除前の既存計画行または需要行から `process_id` を取得し、実行中メモだけに保持する。

各納入回の保存後、次の納入回の計算には

`現在計進 = 現在計進 + 保存数量 - その回需要`

を用いる。

## Excel

- `数量` 列: 保存した `plan_qty`
- `日別内訳` 列: 元需要
- 数量合計と日別内訳合計の不一致は許容する

## 添付ファイル

- `send_progress_excel = true` の場合のみ、進度表Excelを添付する
- `send_progress_pdf = true` の場合のみ、進度表PDFを添付する
- 注文書Excelは `send_order_excel = true` の場合のみ添付する
- 注文書Excelは `send_order_excel = true` の場合のみ生成し、履歴保存対象にもする
- `send_delivery_note_pdf = true` の場合、注文書自動送信専用の外作納品書PDFを添付する
- 各ファイルは、設定がONでも元データや生成結果が無い場合は添付しない
- 4種類すべての添付対象が最終的に0件になった場合は、メール送信を行わず `SUCCESS` として終了する
- 納品書数量はカバー期間の日別需要ではなく、各納期日に保存した `plan_qty`（=`expected_qty`）をそのまま使用する
- 自動納入リスト送信の納品書ロジックとは分離し、既存の `/purchase/auto-delivery-list` の納品書生成には影響を与えない
- 外作納品書PDFのファイル名は `外作納品書_{仕入先コード}_{先頭納入日}.pdf`
- メール本文の自動生成では、外作納品書PDFを添付した場合にその旨を追記する
- 自動生成件名は、実際に添付した種別に応じて `注文書 / 外作納品書 / 進度表` を連結して作成する

## 履歴保存

- 自動送信・手動実行・休日手動実行の各実行ごとに、`注文書自動送信履歴` を1件保存する
- 履歴には `開始日時 / 終了日時 / 実行種別 / 実行結果 / 先頭納入日 / 品目数 / 宛先 / CC / 件名 / 添付内容 / 結果メッセージ / 実行時間` を保存する
- 添付内容は `attachment_labels` に改行区切りで保存する
- 注文書Excelを送信対象にした実行では、その実行で生成したExcelを `order_excel_file` に保存する
- `send_order_excel = false` の実行では注文書Excelを生成しないため、履歴からの再ダウンロードも不可
- 履歴一覧では `仕入先 / 結果 / 実行種別 / 件数 / キーワード` で確認できること
- キーワード検索対象は `仕入先コード / 仕入先名 / 宛先 / 件名 / メッセージ` とする
- 履歴詳細では `件名 / 宛先 / CC / 添付内容 / 実行時間 / エラーメッセージ` を確認できること
- 注文書Excelを生成した場合は、その実行で送付したExcelを `MEDIA_ROOT/purchase_auto_order_send/order_excel/` 配下へ保存する
- 送信失敗時でも、注文書Excel生成済みであれば履歴から再ダウンロードできる
- 履歴一覧API: `GET /api/purchase-auto-order-send-histories/`
- 注文書Excel再ダウンロードAPI: `GET /api/purchase-auto-order-send-histories/{id}/order-excel/`

## 画面表示

- 一覧には `送信先 / 添付内容 / 通知先 / 最終実行 / ステータス / メッセージ` の要約を表示する
- 添付内容の要約は `注文書Excel / 進度表Excel / 進度表PDF / 外作納品書PDF` のON/OFF設定をそのまま表示する
- 編集画面の送信ファイル選択では4種類を個別にON/OFFできる
- 送信ファイル説明は「対象データが生成できたファイルだけが添付される」とする
- 保存時バリデーションでは、送信ファイル4種のうち1つ以上をON必須とする
- `alert()` ではなく、ページ上部のメッセージエリアとフォームエラーで結果表示する

## 手動実行・休日手動実行

- `今すぐ実行` は `trigger_type=MANUAL`、`休日手動実行` は `trigger_type=HOLIDAY_TRIAL` で履歴を保存する
- 通常実行は、ダイソーカレンダ基準で当日が休日なら `SKIPPED` とし、メール送信しない
- `休日手動実行` は休日判定を無視して実行する
- 手動実行開始時は一覧の `last_run_status` を `RUNNING`、メッセージを `手動実行中...` または `休日手動実行中...` に更新する
- フロントの進行監視は `setTimeout` による逐次ポーリングで行い、3秒ごとに最新状態を再取得する
- 画面離脱時はポーリングを停止する
- 同一設定が実行中の間は再実行を受け付けず `409 Conflict` を返す
- ただし `RUNNING` が30分を超えて残留していた場合は、古い実行を `FAILED` に更新してから新規実行を受け付ける

## 確認項目

- 手動実行で、平日実行時に `RUNNING -> SUCCESS/FAILED` へ遷移し、一覧メッセージと履歴が一致すること
- 手動実行で、休日の通常実行時に `SKIPPED` となり「本日は休日のため...」のメッセージが一覧と履歴の両方に残ること
- 休日手動実行で、休日でも `SKIPPED` にならず処理継続すること
- `send_order_excel / send_progress_excel / send_progress_pdf / send_delivery_note_pdf` の各ON/OFFが、実際の添付有無と履歴の添付内容に一致すること
- `send_order_excel = false` の場合、履歴に注文書Excel再ダウンロードボタンが出ないこと
- 履歴詳細で `件名 / 宛先 / CC / 添付内容 / メッセージ / 実行時間` を確認できること
- 履歴絞り込みで `仕入先 / 結果 / 実行種別 / 件数 / キーワード` が期待通りに効くこと
- 同一設定を連打した場合、実行中は `409 Conflict` になり二重実行されないこと
- 古い `RUNNING` 状態を意図的に残した場合、30分超過後の次回実行で自動復旧すること
- 送信ファイルを4種類すべてOFFにすると、保存時にバリデーションエラーになること

## 実装メモ

- トラック積載判定の表示では、`直容器数` / `親容器換算数` / `積載枠・段数` を混同しないこと
- `小ｱﾐ×33 ＋ 汎用ポリ×16（ 小ｱﾐ×2）` のような要約表示は、見た目だけでなく「どの数を表しているか」を必ず確認すること
- 表示位置の修正だけを先行させず、数量の意味が業務解釈と一致しているかを先に確認すること
- トラック積載判定は手動実行中のみ `中断` ボタンを表示し、`request_id` 単位で中断要求を出せるようにする
- 中断要求後はフロントの待機を解除し、バックエンド側も積載計算中の要所で中断フラグを確認して途中終了する
- 中断API: `POST /api/purchase-auto-order-send-truck-load-check/cancel/`
- 入力: `{request_id}`
- トラック積載判定APIの入力には `{request_id}` を追加できる

## 自動実行

- APScheduler の `run_scheduler` から実行
- 設定モデル: `PurchaseAutoOrderSendConfig`
- 実行関数: `purchase.tasks_auto_order_send.run_auto_order_send`


## 表示名・運用説明の補足（2026-09-07）

- ボタン・確認ダイアログ・履歴の表示名を「休日手動実行」に統一する。API経路と保存値 `HOLIDAY_TRIAL` は維持し、既存履歴のデータ更新は不要。
- 休日手動実行は処理基準日の休日判定を無視し、実際に仕入れ計画を再作成してメール送信する。納入日判定や添付データ有無によるスキップは引き続き適用される。
- 処理基準日は8時区切り。木曜日7:55の実行は水曜日、木曜日8:00以降は木曜日を基準に休日判定・納入日計算を行う。
- 対象仕入先・納入日の既存計画（sequence_no=1）を削除し、再計算して保存する。送信失敗でも保存済み計画は残る。削除後の再作成中に失敗した場合は計画が欠ける可能性があるため、再実行前に履歴と計画を確認する。
- 対象納入日に自動計画ロックがある場合は、削除後と再作成後にロック数量を復元する。これにより進度再計算・注文書数量はロック数量を正として扱う。
- 実行中の重複起動は拒否するが、終了後の手動再実行によるメール再送は防止しない。
- 基準計進は納入日前日の値を使う。業務日の前日以前の計画進度は実績を使用済みのため、「実績 − 計画」の追加補正を行わない。業務日当日以降に実績がある場合だけ「実績 − 計画」を加え、計画値を実績値へ置き換える。
- 表示名変更のマイグレーションは `0035_rename_holiday_manual_display`。choicesの表示ラベルのみを変更する。反映時はフロントエンドの再ビルドとバックエンドの更新・マイグレーションを行う。
