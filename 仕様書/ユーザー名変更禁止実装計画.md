# ユーザー名（login_id）変更禁止 実装計画

## 目的
`auth_user.username` を作成後に変更できないようにする。仕損の作業者列（`operator_login_id` など）やAI用ビューが `username` で記録・結合する前提を守るため。

## BOSS決定
1. API: 作成後に username が変わる入力は 400（「ユーザー名は作成後に変更できません。」）で拒否する。無視しない。同じ値の再送は通す。比較は完全一致（大文字小文字を区別）。作成は従来どおり重複チェックのみ。
2. Django管理画面: 編集時は username を readonly、追加時は入力可。
3. 画面: ユーザー管理・ユーザー権限編集は編集時のみ readonly（作成時は入力可、値の送信は維持）。説明文「作成後は変更できません」を添える。プロフィール編集は常に readonly。
4. ORM直接変更（shell など）の防止は入れない。
5. 誤作成時の直し方（新規作成して元ユーザーを無効化）をマニュアルに書く。
6. DB・マイグレーションの変更なし。既存データの更新なし。

## 検証項目
1. POST 作成で username 指定が 201、重複は 400
2. PUT/PATCH で別 username が 400 かつ DB 値不変、大文字小文字だけの変更も 400
3. PUT で同じ username 再送が 200、email など他項目は従来どおり更新可
4. `/users/me/` PATCH で username 変更が 400
5. 管理画面の change view で username が readonly、add view で入力可
6. 作成時の初期パスワードが employee_code（なければ username）のまま
7. `makemigrations --dry-run --check` で新規マイグレーションなし
8. フロントビルドが通る、`git diff --check` が通る
