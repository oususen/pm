# 仕入れ検収仕様書

## 1. 概要

仕入先からの納入品を検収する画面。納入パターンに基づくカバー日の予定数量を表示し、検収確定により `ProcessRealtimeRecord` + `LineBacklog` に実績を記録する。

- メニュー: `仕入れ > 仕入れ検収`
- URL: `/purchase/receiving`
- 権限リソース: `purchase.receiving`

## 2. 画面レイアウト

### 2.1 ヘッダ

| 要素 | 説明 |
|------|------|
| 仕入先セレクト | `Supplier` 一覧からドロップダウン選択 |
| 日付ピッカー | 対象日（デフォルト: 当日） |
| 検収データ取得 | GET API を呼び出し |
| Excel出力 | フィルタ後データを XLSX ダウンロード |
| 検収履歴 | 当日の検収レコードをパネル表示 |

### 2.2 パターン情報バー

| 要素 | 説明 |
|------|------|
| 納入パターン | `SupplierOrderPattern` のパターン名＋繰返し種別 |
| 納入日判定 | 当日が納入日かどうかのバッジ |
| 次回納入日 | 未来の最初の納入日 |
| 進度基準 / 在庫基準 | トグルボタン。データソースを切り替える |
| 件数表示 | `フィルタ後件数 / 全件数 / 実績件数` |

### 2.3 フィルタバー

| フィルタ | 種別 | 説明 |
|----------|------|------|
| 品番 | テキスト（部分一致） | 品番コードで絞り込み |
| 移動先 | セレクト | `Product.transfer_destination` の値で絞り込み |
| 後工程 | セレクト | ルーティング上の PURCHASE 次工程名で絞り込み |
| 数変更 | ボタン（全/有/無） | 保留（数変更）状態で絞り込み |
| 差異 | ボタン（全/有/無） | 予定と実績の差異有無で絞り込み。「有」は差異ありまたは実績0の行も表示 |
| 実績 | ボタン（全/有/無） | 実績有無で絞り込み |

### 2.4 データテーブル

| 列 | 説明 |
|----|------|
| 品番 | `product_code` + 「数変更」ボタン |
| 品名 | `product_name` |
| 予定 | coverage期間の合計予定数量 |
| 実績 | 既検収済みの実績数量（読み取り専用） |
| 日別列 | coverage期間の各日付の予定数量。ヘッダは `M/D` + 曜日の2行 |
| 実数 | 入力欄。検収する数量 |
| 差異 | `予定 - 実績`。赤=不足、青=過剰 |
| 備考 | テキスト入力 |

### 2.5 行の装飾

| 条件 | 表示 |
|------|------|
| 数変更（保留）行 | 黄色背景 (`row-held`) |
| 検収済み行（実績 === 予定かつ差異なし） | グレー背景 (`row-done`) |

### 2.6 アクションボタン

| ボタン | 表示条件 | 動作 |
|--------|----------|------|
| 検収確定 | 数変更フィルタが「有」以外 | 保留でない行を POST |
| 数変更検収確定 | 数変更フィルタが「有」 | 保留行のみ POST し、保留状態を解除 |

## 3. データソース（基準切替）

### 3.1 進度基準（デフォルト）

- **予定数量**: `LineDemand`（`firm_qty` + `forecast_qty`）
- ライン = 仕入先の購買ライン（`line_code = supplier.supplier_code`）
- 対象日 = coverage_dates 内
- 需要が 0 より大きい行のみ
- **根拠**: CLAUDE.md 業務ルール「進度計算の需要は必ず LineDemand を使用」

### 3.2 在庫基準

- **予定数量**: `LineBacklog`（`sequence_no=1, process=PURCHASE, plan_qty > 0`）
- 計画数量ベース

### 3.3 実績（共通）

- `LineBacklog`（`sequence_no=0, actual_qty > 0`）
- プロセス不問（同一 product/date に複数プロセス行がある場合は日別 max を取得し合計）

## 4. カバー日（coverage_dates）

納入パターンに基づき、当日から次回納入日の前日までの日付範囲を coverage とする。

1. `SupplierOrderSchedule` から仕入先の有効パターンを取得
2. `_generate_raw_pattern_dates()` で ±7日〜+60日の納入日リストを生成
3. 当日が納入日の場合:
   - 次回納入日が存在 → `[当日, ..., 次回納入日-1日]` をカバー
   - 次回納入日なし → `[当日]` のみ
4. 当日が納入日でない場合 → `[当日]` のみ
5. パターン未設定 → `[当日]` のみ（毎日納入扱い）

## 5. 数変更（保留）機能

仕入先が予定と異なる数量で納入した場合、その品番を一時保留し後から別途検収する。

### 5.1 動作

1. 品番横の「数変更」ボタンで保留ON → 実数を0にセット、確認済・日別✓をOFFにする
2. 保留中でも実数は編集可能
3. 数変更フィルタが「全」または「無」の場合、保留行の「確認済」ボタンと日別「✓」ボタンは無効化される（「有」モードでは制限なし）
4. 「検収確定」押下時: 保留行は除外される
5. 「数変更検収確定」押下時: 保留行のみ検収 + 保留状態を解除

### 5.2 未納機能

仕入先が予定品を納入しなかった場合に、未納として記録する。

#### 動作

1. 保留ON時に「未納」ボタンが表示される
2. 「未納」ボタン押下 → `received_qty = 0`、備考に「未納」を自動記入、未納フラグON
3. 「未納」ボタン再押下 → 未納フラグOFF、備考クリア
4. 保留OFF → 未納フラグも自動リセット
5. 「数変更検収確定」時、未納フラグONの行は `received_qty = 0` でも送信対象に含まれる

#### POST処理

- `non_delivery = true` の場合、`received_qty <= 0` のスキップ条件を回避して `ProcessRealtimeRecord` を作成
- `event_data` に `non_delivery: true` を記録（検収履歴で未納と判別可能）
- `LineBacklog` の実績更新（`_update_purchase_actual_backlog`）は未納時スキップ（qty=0のため）

### 5.3 永続化

- `localStorage` にキー `receiving_held_{supplierId}_{date}` で保存
- 保存内容: `{ product_id: { received_qty, note } }`
- リロードしても保留状態・入力値を維持
- 保留品が0件になったらキーを削除

## 6. 検収確定（POST）

### 6.1 リクエスト

```
POST /api/purchase-receiving/
{
  "supplier_id": int,
  "target_date": "YYYY-MM-DD",
  "items": [
    {
      "product_id": int,
      "expected_qty": int,
      "received_qty": int,
      "note": string,
      "non_delivery": bool  // 未納フラグ（省略時false）
    }
  ]
}
```

### 6.2 処理フロー

1. `received_qty <= 0` の行はスキップ（ただし `non_delivery = true` の場合は通す）
2. 各品番について `ProcessRealtimeCreateSerializer` で `ProcessRealtimeRecord` を作成
   - `record_type`: `PRODUCTION`
   - `process_id`: PURCHASEプロセス
   - `event_data.source`: `PURCHASE_RECEIVING`
   - `event_data.arrival_date`: 対象日
   - `event_data.supplier_id`: 仕入先ID
   - `event_data.non_delivery`: `true`（未納時のみ）
   - `event_data.line_id`: 購買ライン ID
   - `operator_name`: ログインユーザーの `username`
3. PURCHASE プロセスの `line_id` が NULL の場合:
   - シリアライザの `update_line_backlog_production` がスキップされるため、直接 `_update_purchase_actual_backlog()` を呼び出す
4. `_reconcile_purchase_actual_backlog_for_key()` で LineBacklog の actual_qty を再集計
   - 対象source: `['PURCHASE_ACTUAL_INPUT', 'PURCHASE_RECEIVING']`
5. `_recalculate_purchase_child_stock()` で子工程の在庫を再計算

### 6.3 レスポンス

```json
{
  "detail": "N件の検収を確定しました",
  "created_ids": [int, ...]
}
```

## 7. 検収履歴

### 7.1 API

```
GET /api/purchase-receiving/history/?supplier_id=N&target_date=YYYY-MM-DD
```

### 7.2 処理

- `ProcessRealtimeRecord` を `event_data.source in ['PURCHASE_ACTUAL_INPUT', 'PURCHASE_RECEIVING']` + `event_data.line_id` でフィルタ
- `target_date` が指定されていれば `timestamp__date` でフィルタ
- 最新100件を返却

### 7.3 表示列

| 列 | 内容 |
|----|------|
| 日時 | `timestamp`（`YYYY-MM-DD HH:MM`） |
| 品番 | `product_code` |
| 品名 | `product_name` |
| 数量 | `qty` |
| 検収者 | `operator_name` |
| 備考 | `remarks` |

## 8. Excel出力

- ライブラリ: `xlsx`（クライアントサイド）
- 対象: フィルタ後の行
- 列: 品番, 品名, 予定, 実績, 日別列（`M/D(曜日)`形式）, 実数, 備考
- ファイル名: `仕入れ検収_{supplier_code}_{date}.xlsx`

## 9. 後工程名の取得

- `Routing`（`is_active=True, is_default=True`）からルーティングを取得
- `RoutingStep` を `step_no` 順にスキャンし、`process_code='PURCHASE'` の次の工程名を返す

## 12. 納入リスト方式（タブ: 納入リスト）

進度方式とは別の検収方式。事務員が事前に登録した納入予定データに基づいて検収する。

### 12.1 運用フロー

```text
① 自動送信 or 手動納品リスト出力で数量入りExcelを仕入先へ送付
  → 詳細は「自動納入リスト送信仕様書.md」参照
  ↓
② 仕入先が数量を確認・修正してExcelを返送
  ↓
③ 事務員が納入予定画面（/purchase/delivery-schedule）でExcelを取込・保存
  → 合計数を LineBacklog に保存。日別数は LineDemand と照合し、差異時は警告ダイアログ表示
  ↓
④ 検収担当が仕入れ検収画面の「納入リスト」タブで検収確定
```

### 12.2 納入予定画面（`/purchase/delivery-schedule`）

- 納品リスト出力: バックエンドで数量入りExcel生成（日別内訳・確認修正方法シート・製品リストシート・納品リスト印刷用シート付き）
- Excel取込:
  - ヘッダー名マッピングで列順不問
  - `数量`列の合計数を `LineBacklog`（`sequence_no=1, plan_date=対象日`）に `plan_qty` として保存
  - Excelの日別列（`M/D(曜日)` 形式）をパースし、`LineDemand` のカバー期間日別データと照合
  - **照合チェック1**: Excel日別列の各日値 vs LineDemand の各日値（不一致時は警告に含む）
  - **照合チェック2**: Excel合計数（`数量`列） vs LineDemand カバー期間日別合計（不一致時は警告に含む）
  - 差異がある場合、品番・移動先・差異内容を一覧表示する警告ダイアログを表示
  - 「はい」→ 取込続行、「いいえ」→ 取込キャンセル
  - 差異は警告のみで、保存をブロックしない（合計数変更はよくある業務ケース）

### 12.3 データソース

| データ | ソース | 説明 |
|--------|--------|------|
| 納入予定（合計数） | `LineBacklog`（`sequence_no=1, plan_date=対象日, plan_qty > 0`） | 事務員が登録した納入予定数量 |
| 日別内訳 | `LineDemand`（`plan_date in coverage_dates, firm_qty + forecast_qty`） | 顧客需要に基づくカバー期間の日別数量 |
| 実績 | `LineBacklog`（`sequence_no=0, actual_qty > 0`） | 検収済みの実績数量 |
| カバー期間 | `SupplierOrderSchedule` + `SupplierOrderPattern` | 対象日〜次回納入日前日 |
