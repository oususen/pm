# リードタイム仕様書

## 概要

本システムのリードタイム（LT）は用途別に複数種が存在する。  
生産・在庫・購買・出荷・枚方集荷で参照元と計算ルールが異なるため、本書で整理する。

## リードタイムの種類

| 種類 | 主なフィールド | 単位 | 用途 |
| --- | --- | --- | --- |
| 工程ステップLT | `m_routing_step.lead_time_days` | 日 | 生産計画/在庫/展開で最優先 |
| ライン既定LT | `m_line.lead_time_days` | 日 | 工程ステップLTの次点 |
| 製品×ラインLT | `m_line_product_lt.lt_days` | 日 | 工程ステップLTの補完に使用 |
| BOM明細LT | `m_bom_item.lead_time_days` | 日 | 親→子の需要日シフト（購買/展開） |
| 製品標準LT | `m_product.standard_lt_days` | 日 | **特殊運用専用**（枚方集荷・運送などの参考値）。本命LTには使用しない |
| 自工程LT | `m_product.self_lt_days` | 日 | 現時点で実運用では未使用（`standard_lt_days` の二次フォールバック相当） |
| 購買LT | `m_supplier_product.purchase_lt_days` | 日 | 購買手配日の逆算 |
| 納入先別LT | `ship_to_code` 別定数 | 営業日 | 出荷対象抽出/出荷日逆算 |

参照: `仕様書/MASTER_TABLES_DEFINITION.MD`, `仕様書/schema.sql`

## 正本ルール（生産・在庫・棚卸・購買・pickupのLT解決）

### 統一ルール（`time_unit` 非依存）

MINUTE / DAY にかかわらず、投入LTは以下の優先順位で解決する。

| 優先順位 | 参照先 | 備考 |
| --- | --- | --- |
| 1 | `RoutingStep.lead_time_days` | **`0` は有効値としてそのまま採用する（フォールバックしない）** |
| 2 | `RoutingStep.line.lead_time_days` | step.lead_time_days が未設定(None)の時のみ |
| 3 | `BOMItem.lead_time_days` | 対応する RoutingStep が存在しない場合の最終フォールバック |
| 4 | 0 | |

補足:

- **`duration_min` は「サイクルタイム」専用のフィールドであり、LT 日数シフトには一切使用しない。**
- 従来あった「MINUTE中間品は `duration_min // 480` で日数換算」「MINUTE最終品は `lead_time_days + duration_min//480`」といった分岐はすべて廃止した。
- MINUTE と DAY は LT 解決において同一ルールで扱う。最終品/ライン最終品の特別扱いもしない。
- `lead_time_days` の日付シフトは営業日ベースで行う。
- `RoutingStep.lead_time_days=0` は「同日投入」を意味する有効値であり、0 を理由に line fallback を発動させてはならない。

### 共通ユーティリティ

このルールは `pm_backend/apps/production/inventory/lead_time_utils.py` の `resolve_lead_days_for_step(step)` に集約されている。LT を必要とするすべての計算経路（受注展開/在庫計算/進度/棚卸/購買/pickup/where-used）は本関数を経由すること。

### 製品マスタLT（`standard_lt_days` / `self_lt_days`）の扱い

`m_product.standard_lt_days` と `m_product.self_lt_days` は、上記統一ルール（本命LT）とは別系統の**特殊運用専用フィールド**である。

- **用途**: 枚方集荷依頼書・運送関連の日付逆算など、`RoutingStep` / `BOMItem` ベースのLT解決が適用できない参考値としてのみ使用する。
- **本命LTには使用禁止**: 生産計画・在庫計算・進度計算・購買需要・pickup・受注展開・where-used など、日次運用の需要日シフトは必ず `resolve_lead_days_for_step(step)` を経由すること。これらの経路で `product.standard_lt_days` / `product.self_lt_days` を参照してはならない。
- **生成方法**: `calculate_leadtime` 管理コマンドが `duration_min / 480` の積算で書き込む。この値はサイクルタイムから導出された参考値であり、投入LT（需要日シフト量）ではない。
- **`self_lt_days` の現状**: `standard_lt_days` が 0/NULL の場合の二次フォールバックとして定義されているが、実運用では `standard_lt_days` が常に設定されるため到達しない。将来の再利用余地として残している。
- **`self_lt_days` の歴史的経緯**: 分管理（`time_unit='MINUTE'`）を導入した当時、工程1段の `duration_min` を日換算して「製品の自工程LT」として表現するために追加された派生フィールド。現在は統一ルールにより `RoutingStep.lead_time_days` が投入LTの正本となったため、本フィールドの当初の設計意図は失効している。
- **画面表示**: `ProductMaster.vue` の「標準LT(日)」入力欄には本用途の注記を表示している。本命LTと混同しないよう、UI・ドキュメントで明示すること。

参照: `仕様書/枚方集荷.md`

## BOM/ルーティングの一次情報方針

- **一次情報は BOMItem（`m_bom_item`）とする。**
- RoutingStep（`m_routing_step`）はBOMから生成される派生データとして扱う。
- 画面/バッチの同期キーは `remark` 単独依存を避け、FK（`source_bom_item_id`）優先で解決する。
- `remark` は運用上必要な表示情報として維持する。

参照: `仕様書/MASTER_TABLES_DEFINITION.MD`, `仕様書/scheduling_logic_v3.md`

## 用途別の使い方

### 1. 生産計画・ライン展開

- 親製品の計画日からLT分遡って前工程の需要日を決定する。
- LT解決は本書「正本ルール（統一ルール）」に従う。`RoutingStep.lead_time_days` を使用し、未設定(None)時のみ `Line.lead_time_days` にフォールバック、対応するStepが無い場合のみ `BOMItem.lead_time_days` を使用する（`0` は有効値）。

参照: `仕様書/在庫計算仕様書.md`, `仕様書/scheduling_logic_v3.md`

### 2. 在庫計算

- 進度や計画出庫で、LT分遡った日を計上日として扱う。  
- 実績は後追いで、LT逆算は計画側で使う。

参照: `仕様書/在庫計算仕様書.md`

### 3. 購買需要計算

- BOM明細の `lead_time_days` を使い、親の計画日から購買部品の必要日を算出する。  
- 購買LTの設定は `m_supplier_product.purchase_lt_days` を参照。

参照: `仕様書/購買需要計算仕様書.md`, `仕様書/MASTER_TABLES_DEFINITION.MD`

### 4. 出荷指示・納入先別出荷日

- `ship_to_code` ごとに営業日LTを定義し、納期から出荷日を逆算する。  

参照: `仕様書/出荷指示書機能仕様書.md`, `仕様書/受注管理仕様書.md`

### 5. 枚方集荷依頼書

- 製品の `standard_lt_days` / `self_lt_days` を参照し、納品日から集荷日を逆算する。  

参照: `仕様書/枚方集荷.md`
