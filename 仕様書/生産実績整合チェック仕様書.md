# 生産実績整合チェック仕様書

## 1. 目的

`ProcessWorkSession` / `ProcessRealtimeRecord`（生産実績）と `LineBacklog.actual_qty` の不整合を、

1. 比較
2. レポート保存
3. 差分通知
4. 手動修正

の順で運用し、夜間は自動修正せずに整合性を担保する。

## 2. 対象データ

- 実績側:
  - `t_process_work_session`
    - `line.line_type in ('PROD', 'OUTSOURCE')`
    - 実績計上対象セッション（`session_type='WORK'` かつ `end_action in ('END', 'PAUSE')`）
  - `t_process_realtime_record`
    - `record_type='PRODUCTION'`
    - `event_data.source!='PURCHASE_ACTUAL_INPUT'`
    - 親セッションと同一キーの重複レコードは除外
- Backlog側: `line_backlog`
  - `sequence_no=0`
  - `line.line_type in ('PROD', 'OUTSOURCE')`

比較キーは以下。

- `line_id`
- `process_id`
- `product_id`
- `plan_date`

`plan_date` は実績レコードの `event_data.session.plan_date` → `event_data.plan_date` → 業務日付変換（`resolve_workday_date_for_process`）の順で決定する。

## 3. 定時タスク

- タスク名: `PRODUCTION_ACTUAL_RECONCILE_CHECK`
- 表示名: `生産実績整合チェック`
- 実行内容: 比較のみ（自動修正しない）
- 差分がある場合:
  - レポートを保存
  - 通知先設定がある場合は通知を作成

## 4. 手動修正

定時タスク設定画面の `修正実行` ボタンで、差分キーの `LineBacklog.actual_qty` を実績側に合わせて更新する。

- 期待値が0でBacklog行がある場合: `actual_qty=0` へ更新
- 期待値が正でBacklog行がない場合: `line_backlog` 行を新規作成
- 実行結果はレポートとして保存（モード: `FIX`）

## 5. レポート保存テーブル

### 5.1 ヘッダ

- テーブル: `production_production_actual_reconcile_report`
- 主な項目:
  - `mode` (`CHECK` / `FIX`)
  - `status` (`SUCCESS` / `FAILED`)
  - `compared_count`
  - `diff_count`
  - `fixed_count`
  - `message`
  - `created_by`
  - `created_at`

### 5.2 明細

- テーブル: `production_production_actual_reconcile_report_detail`
- 主な項目:
  - `report_id`
  - `line_id`, `process_id`, `product_id`
  - `plan_date`
  - `expected_qty`
  - `backlog_qty`
  - `diff_qty`
  - `fixed`

## 6. API

- `GET /api/schedule-config/production-actual-reconcile/reports/`
  - 最新レポート一覧と最新レポート明細を取得
- `POST /api/schedule-config/production-actual-reconcile/fix/`
  - 手動修正を実行し、`FIX` レポートを保存

## 7. 画面

`設定 > 定時タスク設定（mode=inventory）` に以下を追加。

- 生産実績整合チェックの実行時刻/有効設定
- 差分通知先設定
- `今すぐ実行`（比較のみ）
- `修正実行`（手動修正）
- 最新レポート概要/差分明細表示
