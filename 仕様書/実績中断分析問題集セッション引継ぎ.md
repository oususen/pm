# 実績・中断分析 問題集セッション 引継ぎ

作成日: 2026-10-18。作成元: 実績系AIビュー作成セッション（本セッションの部下セッション）。

## 目的

実績系AIビュー作成の出発点となったBOSSの要求（「実績系は大事です。例えば誰が何月なにを何個作った。どの設備なにを作る時よく中断するとかの問題を回答」）に、実際にAI分析が正しく答えられるかを、具体的な質問集（問題集）を作って検証する。

ビューを作っただけでは「正しく分析できる」ことの証明にならない。過去に`v_ai_routing_step`で、BOSSがAIチャットに検証用の質問を投げたところ`process_id`の曖昧性の問題が実際に見つかった前例がある。同じやり方で、実績・中断系ビューも検証する。

## 対象ビュー（実績系AIビュー作成セッションが実装・コミット済み。開発DB反映済み・本番未反映）

| ビュー | 元テーブル | 主な用途 |
|---|---|---|
| `v_ai_equipment` | `m_equipment` | 設備マスタ(結合用) |
| `v_ai_process_production_actual` | `t_process_realtime_record`(PRODUCTION) | 一般工程: 誰が何を何個作ったか |
| `v_ai_laser_production_actual` | `t_laser_actual_detail`+`t_laser_actual` | レーザー: 誰が何を何個作ったか |
| `v_ai_brake_production_actual` | `brake_line_record`(全行) | ブレーキ・スポット: 誰が何を何個作ったか |
| `v_ai_process_interruption` | `t_process_work_session`(PAUSE/TEMP_END) | 一般工程: 中断時間・理由・作業者 |
| `v_ai_laser_interruption` | `t_laser_actual`(PAUSE/TEMP_END) | レーザー: 中断理由・設備・パターン・材料 |
| `v_ai_brake_interruption` | `brake_line_record`(PAUSE/TEMP_END) | ブレーキ・スポット: 中断理由・設備 |

各ビューの公開列・業務上の意味は、`仕様書/AI用ビュー作成計画.md`の§32〜§38、および`仕様書/AI運用規約・AI用DB辞書.md`の該当節（§6.5-17〜6.5-22付近）を参照。

## 検証してほしいこと（問題集の作り方）

1. BOSSの2つの原要求に沿って、具体的な質問を複数パターン作る。
   - 「誰が何月何個作ったか」系: 例「2026年9月に、作業者000175は何個生産しましたか」「一般工程で最も生産数が多い作業者は誰ですか」
   - 「どの設備が中断しやすいか」系: 例「レーザーで最も中断の多い設備はどれですか」「ブレーキラインで中断理由の内訳を教えてください」
2. 各質問について、**AI分析機能を使う前に、まず自分でDBに直接SQLを実行し、正解（期待値）を確定する**（推測禁止の原則はこの検証でも適用する）。
3. その後、AI分析（ai.analysisの画面、または社内LLM経由のチャット）に同じ質問を投げ、回答がDBの正解と一致するか確認する。
4. 不一致があれば、原因を切り分ける（ビューの設計問題か、列の公開範囲の問題か、AIの解釈の問題か、集計ロジックの問題か）。
5. 見つかった問題は、実績系AIビュー作成セッション（親セッション）または該当するビューの担当セッションにフィードバックする。

## 注意点（実績系セッションで得た教訓）

- `interruption_reason`（`v_ai_process_interruption`の計算列）は、過去データの補完が進行中（単位C-5、コミット`45a71a3c`、開発DBでドライラン確認済みだが`--apply`未実行）。現時点では一部の行で理由が空のままなので、集計結果にこの影響が出ることを踏まえて検証すること。
- `operator_login_id`等、作業者ログインIDに紐づく列は、開発DBでは本番ほどデータが充実していない（本番は約93%充足、開発DBは補完が別途必要）。人物に関する質問は、この充足率の違いに注意すること。
- `v_ai_brake_production_actual`・`v_ai_laser_production_actual`は、開始(START)行も含む「1行=1イベント」形式のため、「生産数」を聞く質問では、AIがSTART行(qty=0)を誤って合計に含めていないか確認すること。
- 本番ではAI分析機能自体が現在無効化されている（`memory/project_ai_analysis_state.md`参照）。検証は開発環境・社内LLM(Qwen等)、またはBOSSが利用可能な分析経路で行うこと。

## 進め方

- 質問集と期待値（DB確認済みの正解）をまず作成し、BOSSに確認を取ってから、実際にAI分析へ質問を投げる。
- 結果は一覧表（質問・期待値・AIの回答・一致/不一致・原因）としてまとめ、BOSSへ報告する。
- コミット・push・本番反映は、BOSSの指示がない限り行わない。
