# 工程実績 作業者の列化 実装計画

## 状態（反映状況）
- 単位1: 開発 作業ツリーのみ。評価待ち。migrate は未実施。本番: 未反映。
- 単位2〜4: 未着手。

## 目的
一般の工程実績 `t_process_realtime_record` に、作業者のログインID（`auth_user.username`）を専用列 `operator_login_id` で保存し、AI分析・既存画面から扱いやすくする。仕損の作業者列化（`仕損作業者列化実装計画.md`）の前例を踏襲する。

## BOSS決定事項
1. 保存する値は `username`（例: 000175）。姓名は保存しない。`operator_name`（表示用）は従来どおり残す。
2. `ProcessRealtimeRecord.operator_login_id` = CharField(150, null=True, blank=True, db_index=True)。`ProcessWorkSession.operator_login_id` = CharField(150, null=True, blank=True)。NOT NULL 化はしない。補完を RunPython で行わない。
3. 親行（PRODUCTION / OPERATOR_ACTION / EQUIPMENT_STATE）はサーバーがログイン者の username を保存。クライアントの `operator_login_id`・`event_data.operator_login_id`・`event_data.operator_user_id` は通常入力では無視。認証されたユーザーがなければ400。
4. EQUIPMENT_STATE もログイン者（従来は作業者名が空）。工程作業記録の設備状態モードの作業者欄の初期値をログイン者の姓名にする。
5. SCRAP 行は NULL（仕損は `t_scrap_record` 側）。PURCHASE は対象外（NULL。認証必須の400を課さない）。
6. END/PAUSE で作る PRODUCTION 行と連産子行は親（OPERATOR_ACTION）行と同じ値。

## 単位1の内容
- マイグレーション `production/0119_process_realtime_operator_login_id`（2列の AddField のみ）。
- `ProcessRealtimeCreateSerializer`: PRODUCTION / OPERATOR_ACTION / EQUIPMENT_STATE は未認証なら400、認証済みなら親行・END/PAUSE の PRODUCTION 行・連産子行へ `request.user.username` を保存。
- `expand_coproduct_children_production` に `operator_login_id`（既定 None）を追加。`rebuild_session_production_records` は `session_obj.operator_login_id` を引き継ぐ（単位1ではセッションが NULL のため NULL）。
- `ProcessRealtimeRecordSerializer`: `operator_login_id` を read_only で追加。
- フロント `DesktopProcessInput.vue`（工程作業記録）: 設備状態モードの作業者欄の初期値をログイン者の姓名にし、設備状態の送信に `operator_name` を含める。
- LineBacklog・在庫・進度の計算式は変更しない。

## デプロイ順序
単位1〜3を実装・評価後、フロントとバックエンドを同時に本番へ push（起動時の自動 migrate で列追加）→ 本番SQLで列を確認 → 補完コマンドを `--apply` なしで実行 → BOSS承認後 `--apply` → 利用者に再読み込みを依頼。
