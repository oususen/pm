# 製品チェックシート仕様

## 概要

製品チェックシートは、ライン・工程・製品に紐づく品質確認帳票である。工程作業入力でまとめて実績数量を入力する場合でも、対象テンプレートが存在する場合は、数量分の製品チェックシートを1製品1枚ずつ入力完了しなければ工程実績を登録できない。

## 紐づけ条件

テンプレートは以下の3条件に紐づく。

- ライン
- 工程
- 製品

工程作業入力時は、入力中のライン・工程・製品に一致する有効テンプレート版を検索する。一致する有効テンプレート版が存在しない場合、製品チェックシート入力は不要とする。

## テンプレートと版管理

- `ProductChecksheetTemplate` はライン・工程・製品に紐づく管理単位。
- `ProductChecksheetTemplateVersion` は台紙画像/PDFと配置項目を固定する版。
- テンプレート版は帳票ヘッダーとして、帳票タイトル、元シート名、改訂日、改訂内容、運用開始日、編集メモを保持する。
- 配置編集を保存すると、新しいテンプレート版を作成し、有効版を切り替える。
- 新しい版を作成する際は、既存の有効版のヘッダー情報を引き継ぎ、画面で変更された内容だけを新しい版に反映する。
- 入力済みの `ProductChecksheetRecord` は入力時点のテンプレート版に紐づけるため、後から配置を変更しても過去記録の版は変えない。

## 入力ロットと個票

工程作業入力で数量を入力すると、製品チェックシート用の入力ロットを作成する。

- `ProductChecksheetBatch`: 工程入力1回分の親。ロットNo、数量、ライン、工程、製品、テンプレート版を保持する。
- `ProductChecksheetRecord`: 1製品1枚の個票。`sequence_no` でロット内の何個目かを保持する。

例:

```text
ロット A001 / 実績数 50
  1/50
  2/50
  ...
  50/50
```

全ての個票が入力完了になるまで、工程実績登録画面では実績登録を進めない。

## 出荷日・台目

品質問題発生時に、対象品がいつの出荷分か追跡できるよう、個票に以下を保持する。

- 出荷日: `planned_ship_date`
- 台目: `shipment_unit_no`
- 出荷分内番号: `shipment_sequence_no`

これは品質調査用の情報であり、出荷便・配車系テーブルには紐づけない。

例:

```text
ロット A001 / 50個
  1〜20個目  -> 2026-05-10 / 1台目 / 1〜20個目
  21〜50個目 -> 2026-05-10 / 2台目 / 1〜30個目
```

## 承認PDF

品質確認一覧から入力完了済みの個票を承認すると、台紙画像に入力内容、写真、手書き、承認印を合成し、完成PDFを `MEDIA_ROOT/product_checksheets/approved_pdfs/` 配下に保存する。

PDF台紙登録時は、最初のページを背景画像へ変換する。PDF台紙を利用するには `PyMuPDF` が必要である。

## 権限制御

バックエンドでは権限判定を行わず、PM共通仕様どおりフロントエンドUIで表示制御する。

| 画面 | resource |
| --- | --- |
| 台紙登録・配置編集 | `quality.product_checksheet_template` |
| 工程作業入力からの個票入力 | `quality.product_checksheet_input` |
| 品質確認一覧・承認PDF生成 | `quality.product_checksheet_review` |
