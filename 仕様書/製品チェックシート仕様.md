# 製品チェックシート仕様

## 概要

製品チェックシートは、ライン・工程・製品に紐づく品質確認帳票である。工程作業入力でまとめて実績数量を入力する場合でも、対象テンプレートが存在する場合は、数量分の製品チェックシートを1製品1枚ずつ入力完了しなければ工程実績を登録できない。

## 紐づけ条件

テンプレートは以下の3条件に紐づく。

- ライン
- 工程
- 製品

工程作業入力時は、入力中のライン・工程・製品に一致する有効テンプレート版を検索する。一致する有効テンプレート版が存在しない場合、製品チェックシート入力は不要とする。

## テンプレートと版管理

- `ProductChecksheetTemplate` はライン・工程・製品に紐づく管理単位。
- `ProductChecksheetTemplateVersion` は台紙画像/PDFと配置項目を固定する版。
- テンプレート版は帳票ヘッダーとして、帳票タイトル、元シート名、改訂日、改訂内容、運用開始日、編集メモを保持する。
- 配置編集を保存すると、新しいテンプレート版を作成し、有効版を切り替える。
- 新しい版を作成する際は、既存の有効版のヘッダー情報を引き継ぎ、画面で変更された内容だけを新しい版に反映する。
- 入力済みの `ProductChecksheetRecord` は入力時点のテンプレート版に紐づけるため、後から配置を変更しても過去記録の版は変えない。
- 承認済み版を `改訂` した場合、改訂版の班長担当 / 係長担当 / 部長担当は、改訂版作成者の現在の組織情報を基準に再判定する。
- 改訂版の `確認依頼` 時も、その時点の改訂版作成者の現在組織で再判定し、担当者を上書きしてから承認フローを開始する。

## 入力ロットと個票

工程作業入力で数量を入力すると、製品チェックシート用の入力ロットを作成する。

- `ProductChecksheetBatch`: 工程入力1回分の親。ロットNo、数量、ライン、工程、製品、テンプレート版を保持する。
- `ProductChecksheetRecord`: 1製品1枚の個票。`sequence_no` でロット内の何個目かを保持する。

例:

```text
ロット A001 / 実績数 50
  1/50
  2/50
  ...
  50/50
```

全ての個票が入力完了になるまで、工程実績登録画面では実績登録を進めない。

## 出荷日・台目

品質問題発生時に、対象品がいつの出荷分か追跡できるよう、個票に以下を保持する。

- 出荷日: `planned_ship_date`
- 台目: `shipment_unit_no`
- 出荷分内番号: `shipment_sequence_no`

これは品質調査用の情報であり、出荷便・配車系テーブルには紐づけない。

例:

```text
ロット A001 / 50個
  1〜20個目  -> 2026-05-10 / 1台目 / 1〜20個目
  21〜50個目 -> 2026-05-10 / 2台目 / 1〜30個目
```

## 承認PDF

品質確認一覧から入力完了済みの個票を承認すると、台紙画像に入力内容、写真、手書き、承認印を合成し、完成PDFを `MEDIA_ROOT/product_checksheets/approved_pdfs/` 配下に保存する。

PDF台紙登録時は、最初のページを背景画像へ変換する。PDF台紙を利用するには `PyMuPDF` が必要である。

## バッチ削除

チェック実施画面からバッチを削除できる。

### 削除条件

- **入力済みレコードがあるバッチは削除不可**: COMPLETED または APPROVED 状態のレコードが1件でも存在する場合、削除ボタンは無効化される。
- **権限制御**: `quality.product_checksheet_batch_delete` の `can_edit` 権限が必要。バックエンド側でも権限チェックを行う（403エラー）。
- 削除時はバッチに紐づく全レコード（未入力のもの）も連動削除される。

### 運用想定

- 作業者（`quality.product_checksheet_input` のみ保持）: 入力のみ可能、削除不可
- 管理者（`quality.product_checksheet_batch_delete` を付与）: 未入力バッチの削除が可能

## 生産計画からのバッチ自動生成

生産計画入力で計画数量を変更すると、対象製品のチェックシートバッチが自動生成される。

### 生成条件

- 対象製品が `is_line_final_product = True` であること
- 対象製品に承認済み（APPROVED）かつ有効（is_active=True）のテンプレートが存在すること

### 全工程発行

テンプレートは **製品 + 工程** で一意であるため、生産計画の1行に対して、その製品に紐づく **全工程のテンプレート分** のバッチを発行する。

例: YD60000441 に5工程分のテンプレートがある場合、計画数量21の計画1行に対して5バッチが自動生成される。

### 重複防止

同一条件（テンプレート、ライン、工程、製品、計画日、数量）のバッチが既に存在する場合は再作成しない（イデンポーテント）。

## 工程一体チェックシート（チェック実施画面）のバッチ手動作成

- 新規バッチ作成時は以下を必須入力とする。
  - ライン
  - 製品
  - 台数
  - 最終工程計画日（`plan_date`）
- `plan_date` 未入力時はフロントエンドで「バッチ作成」を実行できない。
- API（`integrated-checksheet-batches/prepare`）でも `plan_date` を必須とし、未入力は 400 を返す。

## 権限制御

バッチ削除のみバックエンドで権限判定を行う。それ以外はPM共通仕様どおりフロントエンドUIで表示制御する。

| 画面 | resource |
| --- | --- |
| 台紙登録・配置編集 | `quality.product_checksheet_template` |
| 工程作業入力からの個票入力 | `quality.product_checksheet_input` |
| 品質確認一覧・承認PDF生成 | `quality.product_checksheet_review` |
| バッチ削除 | `quality.product_checksheet_batch_delete` |
