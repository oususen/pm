# レーザー実績 ライン・工程列追加 実装計画

作成日: 2026-10-13 / 状態: **列追加と補完コマンドまで実装（作業ツリーのみ。評価待ち）**。NOT NULL化は未着手。

## 1. 目的

`t_laser_actual` に `line_id` / `process_id` を追加し、保存時の値を持たせる。実績の所属ライン・工程を設備マスタの現在値に依存せず、保存時点の値として残す。

## 2. BOSS決定事項

1. 値の決め方: サーバーが定数コード `L0801`（`Line.line_code`）・`0801`（`Process.process_code`）でマスタ行を引き、設備（パターンの設備が実際の設備になる点に注意）の line / process がそのマスタ行と一致するか検証する。一致しなければ 400（設備側が NULL の場合も不一致）。保存値は引いたマスタ行のID（IDのハードコードなし）。クライアントからは送らせない（read_only）。マスタ行が無い場合は明示エラー。create / update の両方で同じ検証と再設定。
2. 列: `LaserActual.line` / `process`（FK、PROTECT、初回は null=True, blank=True）。定数は `models_laser_actual.py`（`laser_service.py` が serializers を import し循環するため service には置かない）。
3. マイグレーションは列追加（NULL許可）の1本のみ。NOT NULL化は補完完了後に別コミット・別デプロイ。補完を RunPython で行わない（本番は起動時に migrate が自動実行されるため）。
4. 既存データ補完は管理コマンド `backfill_laser_actual_line_process`。
5. 画面（`LaserProcessInput.vue`）の設備絞り込みは変更しない。サーバー側が最終防衛。
6. 生産実績照会の絞り込み、AI公開列（`sql_queries.py`）、LineBacklog の反映先は変更しない。
7. 板金スポットラインの設備でレーザー実績を入れる運用はない（BOSS確認済み）。

## 6. デプロイ順序

1. push（起動時に列追加の migrate が自動実行される）
2. 本番で確認SQL（列の存在、`SELECT COUNT(*) FROM t_laser_actual WHERE line_id IS NULL OR process_id IS NULL`）
3. 補完コマンドを `--apply` なしで実行し、結果（対象・候補・不一致件数と不一致一覧）をBOSSへ報告
4. BOSS承認後に `--apply`
5. null_cnt=0 を確認
