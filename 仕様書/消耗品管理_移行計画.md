# 消耗品管理システム（syomohin）→ pm 移行計画

## Context
syomohin は Flask + 素のJS の単体アプリ（DB: 共通MySQL の `inventory_db`、ポート8504）。
ユーザー・権限・承認・SMTP を独自に持っており、pm（Django + Vue3）と二重管理になっている。
これを pm の1機能「消耗品」として取り込み、ログイン・権限・承認ルート・通知・SMTP を pm に一本化する。

BOSS 決定事項:
- 購入先: **消耗品専用テーブル**（m_supplier とは統合しない）
- 社員: **消耗品側で作業者マスタを保持**（ログインしない現場作業者も選べる）
- 注文書の確認・承認: **pm の承認ルート（ApprovalRouteConfig / ApprovalRequest）に載せる**
- データ移行: **現行データを CSV 出力 → pm でマスタを新規作成**（履歴・過去注文書は移さない）。**画像は移行する**
- メニュー: **新しい大メニュー「消耗品」**
- 安全在庫割れ自動依頼: **pm の定時タスクで実装**

## 1. バックエンド: 新アプリ `pm_backend/apps/consumables/`
`settings.py` の INSTALLED_APPS と `project/urls.py` に登録。

### モデル（テーブル名 `t_consumable_*`）
| モデル | 主な項目 | 元テーブル |
|---|---|---|
| ConsumableSupplier | name, contact_person, phone, email, address, note | suppliers |
| ConsumableEmployee | code(unique), name, department, is_active | employees |
| Consumable | code(unique), order_code, name, category, unit, storage_location, stock_quantity, safety_stock, order_unit, unit_price, supplier(FK), image(ImageField `consumables/images/`), note, is_active | consumables |
| ConsumableRequest（注文依頼） | consumable(FK), quantity, unit_price, total_amount, deadline(最短/通常/余裕あり), requester_employee(FK), requester_name, request_type(manual/auto), status, requested_at, ordered_at, completed_at, created_by(User) | orders |
| ConsumableDispatchOrder（注文書） | order_number(PO-YYYYMMDD-NNN), supplier(FK)+supplier_name, total_items, total_amount, status, approval_request(FK→ApprovalRequest), pdf_file, sent_at, sent_email, note, created_by(User) | dispatch_orders |
| ConsumableDispatchOrderItem | dispatch_order(FK), consumable(FK), request(FK), code/order_code/name/quantity/unit/unit_price/total_amount/deadline/note（スナップショット） | dispatch_order_items |
| ConsumableStockMovement（入出庫履歴） | consumable(FK), movement_type(inbound/outbound), inbound_type(manual/dispatch), quantity, employee(FK)+氏名/部署スナップショット, usage_line, unit_price, total_amount, note, moved_at, created_by(User) | inbound_history + outbound_history を1本化 |

- 日時は `datetime.now()`（USE_TZ=False 規約）。
- **状態の表記ゆれを解消**: 依頼の status は choices `requested/preparing/ordered/received/rejected/cancelled` に統一する。現行では「発注済/発注済み」「入庫済/入庫済み」が混在している。
- 消耗品の「注文状態」は保存しない。未完了の依頼から導き出してAPIで返す。「欠品状態」も同様に、在庫と安全在庫から導き出す（二重管理の廃止）。

### API（DRF ViewSet、`/api/consumables/...`）
- `items/`：消耗品のCRUD、`import-csv`、`upload-image`、`filter-options`
- `suppliers/`、`employees/`：CRUD、`import-csv`
- `movements/`：`inbound`・`outbound`・`dispatch-inbound`（発注済み依頼の入庫で、依頼を received にする）、履歴一覧、部署一覧。在庫の更新は `select_for_update` と `transaction.atomic` で行う。
- `requests/`：依頼の作成・一覧・更新・削除、`set-status`（発注準備にする／却下）
- `dispatch-orders/`：
  - `create`：購入先と依頼IDから注文書を作り、PDFを生成し、ApprovalRequest を作る
  - 一覧・詳細・削除・`pdf`
  - `send`：承認が approved のときだけ送れる。メール送信後、承認を sent・依頼を ordered にする
- 注文書CSVの取込は、syomohin の `config.py` にある `CSV_FIELD_ALIASES` を移植する。

### 承認ルート連携（`apps/accounts/approval_views.py` を最小限変更）
- `item_key='consumable_dispatch_order'` の ApprovalRouteConfig を、データマイグレーションで初期作成する（作成者=leader、確認者1=supervisor、承認者=manager。承認設定画面で調整可能）。
- `_approval_request_path()` に上記 item_key の遷移先 `/consumables/dispatch-orders?id=` を追加する。
- `_refresh_laser_material_order_pdf()` と同じ呼び出し位置に `_refresh_consumable_dispatch_pdf()` を追加する。承認欄（確認者・承認者の姓と日付）をPDFに反映するため。
- context には `{dispatch_order_id, supplier_name, order_number}` を持たせ、`_approval_context_label` で件名に表示する。

### PDF・メール
- syomohin の `pdf_generator.py`（承認欄は姓のみ・商品名は自動折り返し）を `apps/consumables/pdf.py` へ移植する。フォントの登録は pm の既存方式（`overtime/pdf_generator.py` 参照）に合わせる。
- 送信は `shipping/services/email_service.py` の `EmailService().send_email_with_attachment(..., user_id=request.user.id)` を使う。SMTP は pm の UserSmtpConfig になり、syomohin の users.smtp_* は廃止する。

### 権限
`accounts/models.py` の `UserPermission.RESOURCE_CHOICES` に次を追加する（choices の変更のみのマイグレーション）。
`consumables`（消耗品）、`consumables.inventory`（在庫一覧）、`consumables.operations`（入出庫・依頼）、`consumables.dispatch`（注文書）、`consumables.history`（履歴）、`consumables.masters`（マスタ）
- 注文書の作成可否は、承認ルートの creator 判定（既存の作成可能ユーザーのチェック）に従う。

### 定時タスク（安全在庫割れの自動依頼）
- `production/models_schedule_config.py` の TASK_CHOICES に `CONSUMABLE_AUTO_REQUEST` を追加する。
- `production/management/commands/run_scheduler.py` の `_register_jobs` に、既存の `inventory_jobs` と同じ形で登録する（初期値は無効、7:00）。
- 処理本体は `apps/consumables/scheduler_tasks.py` の `run_consumable_auto_request()` に置く。
- 定時タスク設定画面にこの行を追加する。

## 2. フロントエンド: `pm-ui/src`
- `router/consumables.js` を新しく作り、`router/index.js` に登録する。`meta.resource` で権限を指定する。
- `components/SideMenu.vue` に「消耗品」セクションを追加する。
- `views/consumables/`
  - `ConsumableMenu.vue`：タイルメニュー（`PurchaseMenu.vue` と同じ形）
  - `ConsumableInventory.vue`：在庫一覧・在庫カード・入庫履歴。検索、注文状態・欠品のフィルタ
  - `ConsumableOperations.vue`：スマホ向け。QR読み取りで出庫・入庫（手動／発注済み分）・注文依頼。QRは既存依存の `jsqr` を使いブラウザ側でデコードする（サーバー側OpenCVの `/api/decode-qr` は廃止）
  - `ConsumableRequests.vue`：依頼一覧、発注準備、購入先ごとの注文書作成
  - `ConsumableDispatchOrders.vue`：注文書一覧、PDF表示、承認申請・状況、送信
  - `ConsumableHistory.vue`：入出庫履歴（期間・部署・種別で絞り込み）
  - `ConsumableMasters.vue`：タブで消耗品・購入先・作業者を切り替え。CSV取込と画像アップロード
- UI方針（CLAUDE.md）：1行に情報をまとめる、ラベルは省略しない、日付の組み立てに `toISOString()` を使わない。

## 3. データ移行（切替手順）
1. syomohin 側に `scripts/maintenance/export_to_pm_csv.py` を追加する。本番の inventory_db から、次の3つのCSVを出力する（UTF-8 BOM）。
   - `consumables.csv`：購入先名、在庫数、画像ファイル名を含む
   - `suppliers.csv`
   - `employees.csv`
2. 本番 syomohin の `uploads/images/*` を `pm_backend/media/consumables/images/` へコピーする。
3. pm の消耗品マスタ画面で、購入先 → 作業者 → 消耗品の順にCSVを取り込む。消耗品は購入先名で購入先に結び付け、画像ファイル名は `consumables/images/<file>` として保存する。
4. 切替時点で未完了の依頼や未送信の注文書は、pm で登録し直す（履歴・過去注文書は移行しない）。
5. 並行確認のあと、syomohin コンテナを停止する。

## 4. ドキュメント

- `pm-ui/public/manual/消耗品/`：在庫一覧、入出庫、注文依頼・注文書、マスタとCSV取込

## 実装前にBOSSの確認が必要な点（不確実事項）
1. **自動依頼の数量式**：現行は `max(発注単位, int((安全在庫×2−在庫)/発注単位 + 1)×発注単位)` で、端数がなくても常に1単位多くなる。この式をそのまま移すか、`ceil` に直すか。
2. **自動依頼の重複**：現行は「発注済」以外なら毎回作成するため、定時で毎日動かすと依頼中のものに重複が出る。未完了の依頼（依頼中・発注準備・発注済）がある品目は除外する案でよいか。
3. **「今日」の判定**：注文書番号の日付と当日の回数を、pm の日替わり8時ルールに合わせるか、暦日のままにするか。
4. 状態の件数など実データの確認用SQL（移行前に実行）：
   `SELECT status, COUNT(*) FROM inventory_db.orders GROUP BY status;`
   `SELECT order_status, COUNT(*) FROM inventory_db.consumables GROUP BY order_status;`

## 検証
- `python manage.py makemigrations --dry-run` と `migrate` をローカルDBで実行する。
- `apps/consumables/tests.py` に単体テストを書き、`python manage.py test consumables` で実行する。対象：
  - 出庫で在庫が減る／不足時はエラー
  - 発注済み分の入庫で依頼が received になる
  - 注文書を作成すると ApprovalRequest ができる
  - 未承認では送信できない
  - 自動依頼が重複しない
- 画面：`npm run dev` と `runserver 8081` で次を通しで確認する。
  CSV取込 → QR出庫（スマホ実機）→ 依頼 → 注文書作成 → 確認・承認（別ユーザー）→ PDFの承認欄反映 → 送信（テストアドレス）→ 入庫
- 移行リハーサル：本番CSVをローカル pm に取り込み、件数と在庫数の合計を inventory_db と SQL で照合する。
- 本番反映時に必要な作業：`docker exec -it pm-backend python manage.py migrate`、画像のコピー、承認ルートとユーザー権限の設定。
