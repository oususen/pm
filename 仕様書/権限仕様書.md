# 権限仕様書（フロントエンドUIのみ）

## 概要

本システムの権限制御はフロントエンドUIのみで行う。  
バックエンドは権限判定ロジックを持たず、APIは認証のみ（または無制限）で動作する。  
ルータでのブロックは行わず、**画面上の非表示/非活性で制御する**（URL直打ちは許容）。

## 権限データの取得元

ログイン後、`/api/auth/me/` の `user.effective_permissions` を参照する。  
形式は以下の通り。

```
[
  { "resource": "orders", "can_view": true, "can_edit": false },
  { "resource": "production", "can_view": true, "can_edit": true }
]
```

## 判定ルール

- `can_edit = true` の場合は閲覧も許可扱いとする。
- `can_view = false` かつ `can_edit = false` は非表示または押下不可とする。
- 下層ボタン用の権限が未設定の場合は、上位（例: `production`）の権限でフォールバック判定する。

## 適用範囲（UIのみ）

### 1. グローバルナビゲーション（タブ）※SideMenu未使用

現在のUIは `GlobalNavigation.vue` のタブのみを使用し、`SideMenu.vue` は未使用。  
各タブの表示可否は `resource` 単位で判定し、未許可の場合はタブ自体を非表示とする（押下不可）。  
ルータガードは行わないため、直打ちでの遷移は可能だがメニューからは辿れない。

| タブ | resource |
| --- | --- |
| 受注 | orders |
| 生産 | production |
| 仕入 | purchase |
| 出荷 | shipping |
| 在庫 | inventory |
| 品質 | quality |
| 通知 | notifications |
| マスタ | masters |
| 設定 | settings |

既定の判断基準は以下の通り（必要に応じて変更可能）。

| タイル | 既定の必要権限 |
| --- | --- |
| 工程作業入力 | production.process_input / can_view |
| 生産実績照会 | production.process_input / can_view |
| 仕損品記録 | production.scrap_record / can_edit |
| 生産計画入力 | production.plan_input / can_edit |
| 在庫/残量一覧 | production.inventory / can_view |
| 仕損履歴 | production.scrap_history / can_view |
| 進捗管理 | production.progress / can_view |
| ライン需要一覧 | production.line_demands / can_view |
| ライン勤務カレンダ | production.line_calendars / can_edit |
| 在庫引当 | production.stock_allocations / can_edit |
| 製造指示 | production.orders / can_edit |
| ミックス順序ボード | production.sequence_board / can_view |
| ライン稼働監視 | production.line_monitor / can_view |
| モバイル作業入力（ライン） | production.mobile_input / can_edit |

### 3. 通知（タブ）

| 画面 | 既定の必要権限 |
| --- | --- |
| 通知一覧 | 権限なし（対象者判定で表示） |
| 知らせ源入力 | notifications / can_edit |

※「表示しない」か「押下不可」はUI側で切替可能（`PERMISSION_MODE`）。現在の実装ではタブ同様、未許可項目は非表示を基本とする。

### 4. 設定メニュー（タイル）

設定タブ内のボタンもタイル単位で許可を判定する。  
下位リソース（`settings.xxx`）が未設定の場合は、上位の `settings` 権限でフォールバック判定する。

| タイル | 既定の必要権限 |
| --- | --- |
| プロフィール編集 | settings.profile / can_view |
| ユーザー管理 | settings.users / can_view |
| ユーザー権限編集 | settings.user_permissions / can_view |
| 権限テンプレート | settings.permission_templates / can_view |
| SMTP設定 | settings.smtp / can_view |
| 仕入計画ロック設定 | settings.purchase_plan_lock / can_view（保存は can_edit） |
| 生産計画ロック設定 | settings.production_plan_lock / can_view（保存は can_edit） |
| 定時タスク設定 | settings.scheduled_tasks / can_view（保存/実行は can_edit） |
| 棚卸初期化 | settings.stocktake_init / can_view（実行は can_edit） |

※ ユーザー関連画面は「基本情報編集」と「権限編集」を分離する。  
- ユーザー管理（`/settings/users`）: `settings.users`  
  - 基本情報（プロフィール編集・新規作成・保存）を扱う
  - `スタッフ`/`管理者` チェックは表示しない
- ユーザー権限編集（`/settings/user-permissions`）: `settings.user_permissions`  
  - 個別権限（閲覧/編集）を扱う
  - `スタッフ` 表示名は `backendスタッフ`
  - 個別ユーザー削除（DELETE）を提供

### 5. ユーザー一覧フィルタ（ユーザー管理 / ユーザー権限編集 共通）

ユーザー一覧には以下のフィルタを持つ。

- 部署（事業部のみ）
- 係
- 班
- 役職
- 有効のみ
- 無効のみ

各セレクトには `すべて` に加えて `未設定` を持つ。  
件数は `（絞り込み後 / 全件）` で表示する。

## 設定方法

権限はテンプレートを基本とし、必要なユーザーのみ個別に上書きする。

1. テンプレート（部署・役職/部署/役職）で基本権限を設定  
2. ユーザー管理で個別権限を有効化し、例外のみ追加/変更  

テンプレートと個別権限の両方が設定されている場合、個別権限が優先される。

## 注意事項

- この仕様はUI制御のみ。URL直打ちやAPI呼び出しは制限しない。
- 権限の正当性・セキュリティはバックエンドで保証しない。
- ルータでの強制ブロックは行わないため、機能露出を防ぎたい場合はUI側の非表示で対応する。
