# 承認設定仕様書

## 概要

承認項目ごとに、作成者・確認1・確認2・承認者の基本役割を設定する。  
確認2は承認項目ごとに使用有無を選択できる。
基本は個人名を設定せず、ユーザーの組織ロール（リーダー、班長、係長、事業部長・課長）で承認担当を判定する。

## 保存先

設定は `accounts_approval_route_config` に保存する。

| 項目 | 内容 |
| --- | --- |
| `item_key` | 管理コード。画面で空のまま保存した場合は自動作成する |
| `item_name` | 承認項目名 |
| `creator_role` | 作成者の基本役割 |
| `reviewer1_role` | 確認1の基本役割 |
| `reviewer2_role` | 確認2の基本役割 |
| `reviewer2_enabled` | 確認2を使用するか |
| `approver_role` | 承認者の基本役割 |
| `*_task_enabled` | その段階へ進んだ時に次担当者へタスクを作成するか |
| `*_app_notification_enabled` | その段階へ進んだ時にアプリ通知を送るか |
| `*_email_notification_enabled` | その段階へ進んだ時にメール通知を送るか |
| `*_allowed_users` | その段階を特定ユーザーだけに限定する場合のユーザー |
| `*_proxy_users` | その段階を代理実行できるユーザー |
| `approved_result_app_notification_enabled` | 承認結果を全段階の担当者へアプリ通知するか |
| `approved_result_email_notification_enabled` | 承認結果を全段階の担当者へメール通知するか |
| `rejected_result_app_notification_enabled` | 却下結果を全段階の担当者へアプリ通知するか |
| `rejected_result_email_notification_enabled` | 却下結果を全段階の担当者へメール通知するか |
| `is_active` | 有効/無効 |
| `note` | 備考 |

`*_allowed_users` が空の場合は、基本役割に該当するユーザーを対象とする。  
`*_allowed_users` が設定されている場合は、その指定ユーザーだけを実行可能候補として扱う。  
`*_proxy_users` は、基本役割・限定ユーザーとは別に代理実行を許可するユーザーとして扱う。

一段階進んだ後は、次の段階の担当者候補へタスクを作成する。  
`reviewer2_enabled=false` の承認項目では、確認1の次は確認2を飛ばして承認者へ進める。  
アプリ通知とメール通知は承認項目・段階ごとに有効/無効を設定する。  
既定値はタスク作成あり、アプリ通知あり、メール通知なしとする。

承認・却下の結果通知は、全段階の担当者候補を対象にする。  
結果通知の既定値はアプリ通知あり、メール通知なしとする。

## 画面

| 画面 | URL | 権限 |
| --- | --- | --- |
| 承認設定 | `/settings/approval-routes` | `settings.approval_routes` |

画面はタスク設定メニューから開く。  
承認項目を追加・削除し、各段階に以下を設定する。  
管理コードはシステム内部用の値で、画面には表示しない。  
利用者は承認項目名に業務名を入力する。例: レーザ材料発注、設備点検表。

- 基本役割
- 確認②の使用有無
- 次段階タスク作成
- アプリ通知
- メール通知
- 限定ユーザー
- 代理ユーザー
- 結果通知（承認時アプリ通知、承認時メール通知、却下時アプリ通知、却下時メール通知）

## API

| メソッド | URL | 内容 |
| --- | --- | --- |
| GET | `/api/accounts/approval-routes/` | 承認設定一覧取得 |
| PUT | `/api/accounts/approval-routes/bulk-save/` | 承認設定一括保存 |

`bulk-save` は、送信された `routes` の追加・更新と、明示された `delete_ids` の削除だけを行う。  
送信された `routes` に含まれない既存設定を自動削除しない。  
これは、画面側の不具合や通信異常で空リストが送信された場合に、既存の承認設定が全削除されることを防ぐため。

リクエスト形式:

```json
{
  "routes": [],
  "delete_ids": []
}
```

`item_key` は必須で、半角英数字と `_` のみ使用できる。  
画面では利用者に `item_key` を入力させず、承認項目名から自動作成した管理コードを保存する。

## 権限

権限制御はフロントエンドUIのみで行う。  
閲覧は `settings.approval_routes / can_view`、保存は `settings.approval_routes / can_edit` を使用する。
