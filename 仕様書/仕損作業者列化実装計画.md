# 仕損 作業者の列化 実装計画（Codex依頼用）

## 状態
- 2026-10-13 BOSS承認済み（計画・依頼範囲）。作業ツリーへの実装・チェックを実施、独立評価待ち。
- 先の「仕損記録 担当者 実装計画」（`仕損記録三者選択実装計画.md`）の**JSON保存を、本計画の列保存に差し替える**。画面の三者選択UI・仕損専用ルートのUI整理は維持する。

## 目的
「誰が仕損を記録したか」を、AI分析・既存画面から扱いやすくするため、作業者を `event_data`（JSON）ではなく `t_scrap_record` の専用列に保存する。

## BOSS決定事項
1. JSONは使わない（AI分析に不親切）。専用列にする。
2. 保存先は `t_scrap_record`。3列とも文字列でNULL可。**既存行がNULLのままでも可**。
3. 保存する値は `000175` のようなユーザーコード（`auth_user.username`）。**姓名は保存しない**。`operator_name`（表示用）は従来どおり。
4. ブレーキ・スポットの仕損は、入力画面に三者の入力欄がなく、作業者自身。**3列ともログイン者**。
5. 仕損専用画面 `/production/scrap-record` と一般画面（`MobileProcessInput` Scrapモード）は、記入者=ログイン者固定、起因者=任意、報告者=必須（初期値ログイン者）。
6. 既存データは、`operator_name` がユーザーの「姓 名」と完全一致して1人に決まる行だけ補完。決まらない行は空のまま、一覧をBOSSへ。報告者・起因者は補完しない。推測で補完しない。
7. ユーザーの `username` は今後変更禁止にする方針（別単位。本計画では実装しない。実装は `仕様書/ユーザー名変更禁止実装計画.md`）。仕損の作業者列は `username` を保存するため、`username` は変更不可である前提とする。

## データの流れ
| 項目 | 内容 |
|---|---|
| 列 | `t_scrap_record.operator_login_id` / `cause_login_id` / `reporter_login_id`（CharField、max_length=150、null=True、blank=True） |
| 記入者 | サーバーが `request.user.username` を保存。クライアントの値は使わない |
| 報告者・起因者（専用画面・一般画面） | 画面が選んだユーザーの `username` を送る。**サーバーが `auth_user` に存在するか検証し、存在しなければ400で拒否**。起因者の未選択は NULL |
| ブレーキ・スポット | 画面変更なし。サーバーが3列ともログイン者の `username` を設定（クライアントが送った場合も無視） |
| 戻し（RETURN） | 戻した人（ログイン者）の `username` を `operator_login_id` に保存。報告者・起因者はNULL |
| JSON | 先の変更の `event_data.operator` / `cause_person` / `reporter` の保存・送信は**削除**する |
| 既存データ補完 | 管理コマンド。**既定は照合のみ（更新しない）**。BOSSが承認した後に適用オプションで実行。対象は `operator_login_id` のみ。適用前後の件数と、補完できなかった行の一覧（id・operator_name・件数）を出力 |
| 既存画面 | `ScrapHistory` の表示は変更しない。APIの返却に3列を追加するだけ |

3. 存在しない `username` を報告者・起因者に送ると、400で拒否される。起因者の未選択は NULL で登録できる。報告者が未指定の画面入力は登録できない（ブレーキ・スポットは、サーバーが設定するので対象外）。
