# スポットライン実績入力仕様書

## 1. 概要

ナットスポット工程専用の実績入力機能。
ブレーキライン実績（`BrakeLineRecord`）を流用し、計画在庫（`LineBacklog`）への実績反映を行う。

## 2. 目的

- スポットライン（ナットスポット工程）の開始・終了・中断・再開を記録する
- 終了・中断時に `LineBacklog.actual_qty` へ実績数量を加算する
- 2台同時使用製品に対応した複数設備選択をサポートする

## 3. データモデル

### 3.1 実績レコード `t_brake_line_record`

スポットラインはブレーキラインと同一テーブルを使用。`line_id` で区別する。

| カラム | 内容 |
|--------|------|
| `plan_date` | 計画日 |
| `line_id` | スポットライン（`m_line`） |
| `process_id` | 工程（`m_process`） |
| `product_id` / `product_code` | 製品 |
| `equipment_id` | 使用設備（`m_equipment`） |
| `operator` | 作業者名 |
| `operator_action` | `START / END / PAUSE / TEMP_END / RESUME` |
| `operator_action_reason` | 中断・一時終了時の理由 |
| `qty` | 加工数（END・PAUSE時のみ有効） |
| `sequence_no` | LineBacklogのsequence_no |
| `recorded_at` | 記録日時 |

### 3.2 計画実績 `t_line_backlog`

`operator_action = END` または `PAUSE` で `qty > 0` の場合、`actual_qty` を加算する。

## 4. 複数設備対応

### 4.1 仕様

- 同一工程に2台の設備を同時使用する製品に対応
- 設備ボタンはトグル選択（複数選択可）
- 作業の状態管理は設備ごとに独立（`workStateKey = process_id-product_key-equipment_key`）
- 状態表示は最初に選択した設備の状態を基準とする

### 4.2 保存時の数量処理

| 設備 | qty送信 | actual_qty加算 |
|------|---------|--------------|
| 1台目（先頭） | 入力値をそのまま送信 | 加算される |
| 2台目以降 | `skip_qty_update: true` で送信 | スキップ（二重カウント防止） |

`skip_qty_update=true` の場合、バックエンドでqty検証および `actual_qty` 加算をスキップし、レコードのみ作成する。

## 5. API

### 5.1 計画取得
```
GET /api/production/spot-line-plan/?date=YYYY-MM-DD
```
`LineBacklog` から当日計画（`sequence_no > 0`）を返す。手動追加品は `BrakeLineRecord` から補完。

### 5.2 設備一覧
```
GET /api/production/spot-line-equipments/
```
対象ラインに紐づく設備一覧を返す。

### 5.3 作業記録取得
```
GET /api/production/spot-line-record/?plan_date=YYYY-MM-DD&process_id=X
```
レスポンス:
- `item_states`: 品目×設備ごとの最新アクション
- `item_operators`: 品目×設備ごとの開始者
- `processing_by_equipment`: 設備ごとの現在加工中情報

### 5.4 作業記録保存
```
POST /api/production/spot-line-record/
```

| パラメータ | 必須 | 内容 |
|-----------|------|------|
| `line_id` | ○ | ラインID |
| `process_id` | ○ | 工程ID |
| `product_id` | | 製品ID |
| `product_code` | | 製品コード |
| `equipment_id` | | 設備ID |
| `plan_date` | ○ | 計画日（YYYY-MM-DD） |
| `operator` | | 作業者名 |
| `operator_action` | ○ | `START/END/PAUSE/TEMP_END/RESUME` |
| `operator_action_reason` | | 中断・一時終了理由 |
| `qty` | | 加工数（END・PAUSE時） |
| `skip_qty_update` | | `true` の場合qty検証・actual_qty加算をスキップ |
| `sequence_no` | | LineBacklogのsequence_no |

## 6. 入力制約

| アクション | qty制約 | reason必須 |
|-----------|---------|-----------|
| START | 不要 | 不要 |
| END | 1以上（`skip_qty_update=true` 時はスキップ） | 不要 |
| PAUSE | 0以上（`skip_qty_update=true` 時はスキップ） | 必要 |
| TEMP_END | 不要 | 必要 |
| RESUME | 不要 | 不要 |

## 7. 生産実績照会との連携

- 板金タブの照会で `BrakeLineRecord` データが表示される
- ライン絞り込みは板金タブでは非表示（スポットラインとブレーキラインでデータソースが異なり、ライン選択時にスポットデータが取得されなくなるため）
- 工程・品番での絞り込みは有効

## 8. 設定

`ProductionRecordInquirySetting`（TAB_SPOT）で対象ラインコードを管理する。

## 9. 業務ルール

- 日替わり時刻は 8:00（7:59以前は前日扱い）
- 前日の中断・一時終了は翌日に持ち越し表示される
- 手動追加品（DB未登録）は「＋新規/追加 → 新規」から登録
- 付属外加工は「＋新規/追加 → 追加」から登録

## 10. セッション基盤への二重保存（2026-04 追加）

- 既存どおり `t_brake_line_record` へ保存を継続する（互換維持）。
- 併せて、作業者アクションを `t_process_realtime_record`（`record_type=OPERATOR_ACTION`）へ保存する。
- `skip_qty_update=false`（1台目）時のみ、`t_process_work_session` へセッション同期する。
- `skip_qty_update=true`（2台目以降）時はセッション重複を防ぐため、`t_process_work_session` への新規同期は行わない。
- セッション設備紐付けは `t_process_work_session_equipment` に保存する。
  - 1台目は `role=PRIMARY`
  - 2台目以降は `role=SUB`
