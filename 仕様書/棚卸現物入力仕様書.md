# 棚卸現物入力・結果確認 仕様書

## 1. 概要

棚卸時に現場でスマホから現物数を入力し、その結果をPCで確認するための機能。

- **棚卸現物入力**: `pm-ui/src/views/inventory/StocktakeInput.vue`
- **棚卸結果確認**: `pm-ui/src/views/inventory/StocktakeResults.vue`

## 2. データモデル

### 2.1 StocktakeRecord（`production_stocktake_record`）

| フィールド | 型 | 説明 |
|-----------|-----|------|
| stocktake_date | DateField | 棚卸日 |
| product | FK(Product) | 製品 |
| line | FK(Line, null) | ライン |
| process | FK(Process, null) | 工程 |
| system_stock_qty | IntegerField | 保存時の机上在庫（フロントエンドから送信） |
| system_progress_qty | IntegerField | 保存時の机上進度（LineBacklog sequence_no=0の progress_qty Sum） |
| actual_stock_qty | IntegerField | 現物数 |
| area_name | CharField(50) | 入力時の選択エリア名 |
| note | CharField(255) | 備考 |
| recorder_name | CharField(50) | 記入者名 |
| counter_name | CharField(50) | カウンター名 |
| updated_by | FK(User, null) | 更新者 |
| updated_at | DateTimeField(auto_now) | 更新日時 |
| created_at | DateTimeField(auto_now_add) | 作成日時 |

### 2.2 StocktakeArea（`production_stocktake_area`）

| フィールド | 型 | 説明 |
|-----------|-----|------|
| name | CharField(50, unique) | エリア名 |
| locations | JSONField | 所属置き場リスト（文字列配列） |
| sort_order | IntegerField | 表示順 |

## 3. API仕様

### 3.1 棚卸入力一覧 GET `/api/stocktake-records/`

パラメータ: `stocktake_date`(必須), `line_id`, `stock_location`, `product_code`, `product_name`, `has_image`, `diff_only`, `masters_only`

レスポンス: `{ rows, locations, lines }`

### 3.2 棚卸入力保存 POST `/api/stocktake-records/`

リクエスト:
```json
{
  "stocktake_date": "YYYY-MM-DD",
  "items": [
    {
      "product_id": 123,
      "system_stock_qty": 100,
      "actual_stock_qty": 95,
      "note": "備考",
      "recorder_name": "田中",
      "counter_name": "鈴木",
      "area_name": "板金"
    }
  ]
}
```

処理:
- 各itemごとにStocktakeRecordを新規作成（更新ではない）
- `system_progress_qty`はサーバー側で`LineBacklog`（`plan_date=stocktake_date, sequence_no=0`）の`progress_qty`をSum集計して保存
- `line`, `process`は`Product`マスタから取得

### 3.3 棚卸結果確認 GET `/api/stocktake-results/`

パラメータ: `stocktake_date`(必須), `area_name`, `product_code`, `stock_location`

レスポンス:
```json
{
  "rows": [
    {
      "id": 1,
      "product_id": 123,
      "product_code": "YD40006000-00",
      "product_name": "プレート_00",
      "area_name": "板金",
      "stock_locations": "S1-4",
      "system_stock_qty": 450,
      "system_progress_qty": 120,
      "actual_stock_qty": 234,
      "recorder_name": "田中",
      "counter_name": "鈴木",
      "note": "",
      "updated_by_name": "admin",
      "updated_at": "2026-08-29T01:36:00"
    }
  ],
  "area_choices": ["板金", "溶接"],
  "location_choices": ["S1-4", "B1-1", "B2-1"]
}
```

個別レコード（分行データ）を返す。フロントエンドで合計モード（製品ごと集約）と分行モード（個別レコード表示）を切り替える。

## 4. 他エリア品入力

### 4.1 動作仕様

- 特定エリア選択中に品番検索を行うと、エリアフィルタをバイパスして全エリア横断で検索する
- 選択エリアの製品が先頭にソートされる
- 他エリア品は置き場セルの背景色が赤（`#f87171`）になり、「他エリア品」と右寄せ表示される
- クライアント側でも品番の`includes`フィルタを適用し、API応答前の旧データ表示を防止する

### 4.2 保存時の動作

- 全レコードに選択中のエリア名（`area_name`）が保存される
- 他エリア品の場合、備考に「他エリア」が自動付与される（既に含まれている場合は重複しない）

## 5. 棚卸結果確認画面

### 5.1 表示モード

| モード | 説明 |
|-------|------|
| 合計 | 製品ごとに集約。現物数合計・差異・入力件数・エリア一覧を表示 |
| 分行 | 個別レコード表示。記入者・カウンター・備考を表示 |

切替はフロントエンドのcomputedで行い、API再取得は不要。

### 5.2 注意事項

- `system_progress_qty`は棚卸入力の保存時点のLineBacklog値。保存後に進度再計算が行われた場合、現在値と異なる可能性がある
- 棚卸日は必須フィルタ
