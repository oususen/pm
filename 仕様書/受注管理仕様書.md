## 概要

本システムは、複数の得意先から**内示（FORECAST）**と**確定受注（FIRM）**を受け取り、優先順位を制御しながら生産計画を立てる受注管理システムです。

### 主な特徴

- **内示と確定の二元管理**: 予測情報（内示）と正式受注（確定）を区別して管理
- **自動優先順位制御**: 需要計算は確定優先（前倒し衝突時は合算）
- **内示の自動上書き**: 毎日更新される内示を最新版で置き換え
- **複数得意先・複数フォーマット対応**: 得意先ごとに異なるCSVフォーマットに対応
- **ステージングテーブル**: CSV取込時の生データを保持し、トラブルシューティングを容易に

## 受注タイプと優先順位

### 受注タイプ（order_type）

| order_type | 日本語 | 意味 | 更新頻度 | スケジューリング優先度 |
|-----------|--------|------|----------|----------------------|
| **FIRM** | 確定 | 正式な受注、必ず生産する | 適宜 | **最高**（必ず生産計画に含める） |
| **FORECAST** | 内示 | 予測情報、変更される可能性が高い | 毎日 | 低（確定がない場合のみ使用） |

### 受注ステータス（status）

| status | 日本語 | スケジューリング | 説明 |
|--------|--------|----------------|------|
| `OPEN` | オープン | ○ 対象 | 有効な受注 |
| `SUPERSEDED` | 無効 | × 除外 | 確定受注により無効化された内示 |
| `CLOSED` | クローズ | × 除外 | 完了した受注 |
| `CANCELED` | キャンセル | × 除外 | キャンセルされた受注 |

### 受注番号体系（order_no）

```
内示（FORECAST）:
  FC-{得意先コード}-{タイムスタンプ}
  例: FC-000001-20251204153000

  クボタ内示（customer_code=000196）は `calc_date` が取得できる場合:
  FC-000196-{calc_date}
  例: FC-000196-20260415

確定（FIRM）:
  リーデン: FIRM-{得意先コード}-{発注日YYYYMMDD}
  例: FIRM-000001-20251224

  ティエラ: FIRM-{得意先コード}-{送付No}
  例: FIRM-000002-1311

  クボタ（堺）: FIRM-000196-SAKAI-{issue_date}  (issue_date=発行日YYMMDD)
  例: FIRM-000196-SAKAI-251211

  クボタ（枚方）: FIRM-000196-HIRAKATA-{issue_date}  (issue_date=発行日YYMMDD)
  例: FIRM-000196-HIRAKATA-251211

  クボタ（KMT）: FIRM-000196-KMT-{issue_date}  (issue_date=発行日YYMMDD)
  例: FIRM-000196-KMT-260414

  クボタ（枚方・特殊）: FIRM-000196-HIRAKATA-sp-{issue_date}  (issue_date=発行日YYMMDD)
  例: FIRM-000196-HIRAKATA-sp-251211

  クボタ確定の追加取込:
  - 同品番+同納期で既存FIRMがあり、注番が異なる → `-tuika`
    例: FIRM-000196-SAKAI-260303-tuika
  - 同一発行日の通常受注番号が既に存在し、かつ同品番+同納期で既存FIRMがない明細 → `-tuika2-{取込日YYYYMMDD}`
    例: FIRM-000196-SAKAI-260303-tuika2-20260304

  ※ 発注日・送付Noがない場合はタイムスタンプを使用
  例: FIRM-000001-20251204153000
```

## テーブル定義

### 1. t_order（受注ヘッダ）

受注の基本情報を管理するヘッダテーブル。内示（FORECAST）と確定（FIRM）を区別して管理。

#### テーブル構造

```sql

    UNIQUE KEY (customer_id, order_no, order_type, version_no),
```

#### 主要フィールド

| フィールド名 | 型 | 説明 |
|------------|-----|------|
| `order_type` | VARCHAR(20) | 受注タイプ（FIRM/FORECAST） |

## 優先順位制御ロジック

### 1. 内示の更新（製品ごとの部分置換方式）

#### 課題

内示は毎日更新される予測データだが、以下の特性がある：

- 内示CSVには「今日より先の計画」のみ含まれる（開始日は製品ごとに異なる）
- 内示の開始日より前の期間は、確定受注が入る予定の期間
- 新しい内示で古い内示を完全置換すると、確定待ちの期間のデータが消える

#### 解決策（製品ごとの部分置換）

新しい内示CSVがインポートされると、**製品ごとに、新しい内示の開始日以降のみ既存内示を無効化**する。

- 新しい内示がカバーする範囲：置き換え
- 新しい内示に含まれない近い未来：既存内示を残す（確定待ち）
- クボタ（`customer_code=000196`）は、工場混在時の誤上書きを防ぐため **品番+納入先（ship_to_code）単位** で置換する

#### 処理フロー

```
1. 内示CSVアップロード
2. ステージングテーブルへ保存
3. ユーザーが「受注作成」実行
   ↓
4. 製品ごとの最小納期（開始日）を記録
   例：製品A → 12/16、製品B → 12/20、製品C → 1/6
   ↓
5. 製品ごとに、開始日以降の既存OPEN内示を無効化（SUPERSEDED）
   例：製品Aは 12/16以降の既存内示を無効化
       → 12/15の内示は残る（確定待ち）
   ↓
6. 新しい内示オーダを作成し、全ての明細を追加
```

#### 実装コード

```python
# pm_backend/apps/orders/core/services/csv_import.py:265-305

    product_earliest_dates = {}
    for daily in dailies:
        current_earliest = product_earliest_dates.get(daily.product_code)
        if current_earliest is None or daily.due_date < current_earliest:
            product_earliest_dates[daily.product_code] = daily.due_date

    # 製品ごとに、開始日以降の既存内示を無効化
    for product_code, earliest_date in product_earliest_dates.items():
        Order.objects.filter(
            customer_id=customer_id,
            order_type='FORECAST',
            status='OPEN',
            lines__product_code=product_code,
            lines__due_date__gte=earliest_date  # 開始日以降のみ
        ).distinct().update(status='SUPERSEDED')

    # 新しい内示明細を全て作成
    for daily in dailies:
        OrderLine.objects.create(
            order=order,
            product_code=daily.product_code,
            quantity=daily.quantity,
            due_date=daily.due_date,
            ...
        )
```

#### 結果

- 新しい内示がカバーする範囲（開始日以降）のみ置き換え
- 近い未来（開始日より前）の内示は残る
- 確定受注が来たら、その時点で内示を無効化（次のセクション参照）

### 2. 確定受注と内示の独立管理

#### 設計方針（2026年1月変更）

**確定受注インポート時は内示のステータスを変更しない。**

- **内示（FORECAST）**: 長期的な生産計画用の予測データ
- **確定受注（FIRM）**: 短期的な確実な受注データ

両者は**独立して管理**され、画面では以下のように表示される：

| 項目 | データソース | 用途 |
| ----- | ------------ | ------ |
| **内示** | FORECAST（OPEN） | 長期生産計画の参考 |
| **確定** | FIRM（OPEN） | 確実な生産計画 |
| **需要** | 内示 or 確定 | 生産計画の基準（確定優先） |

#### 処理フロー

```
1. 確定CSVアップロード
2. ステージングテーブルへ保存
3. ユーザーが「受注作成」実行
   ↓
4. 確定受注を作成
   ↓
5. 内示は変更しない（OPENのまま維持）
```

#### 実装

```python
# pm_backend/apps/orders/core/services/csv_import.py:376-379
# 確定インポート時は内示をSUPERSEDEDにしない
# 内示インポート時のみ、古い内示をSUPERSEDEDにする
# （確定と内示は別々に管理する）
pass
```

#### 変更理由

**旧仕様の問題点**:

- 確定受注インポート時に内示をSUPERSEDEDに変更していた
- その後、新しい内示がインポートされないと、OPENの内示が存在しなくなる
- 画面で内示が表示されない問題が発生

**新仕様の利点**:

- 内示は内示インポート時のみ更新される（古い内示 → SUPERSEDED、新しい内示 → OPEN）
- 確定受注は独立して管理される
- 画面では両方が常に表示される（内示=長期計画、確定=短期確定）

### クボタ 枚方確定（RCV_NVAN / NO=45・47混在）

- 対象: 得意先 000196 / 確定（FIRM） / 枚方工場
- 取り込みAPI: `POST /api/stg-order-raw/upload_csv/`
- 形式: ヘッダあり、列位置固定、`NO=45` と `NO=47` が同一ファイルに混在する場合がある
- 取り込み条件: `NO=45` と `NO=47` の行を取り込み（それ以外はスキップ）
- 列番号（0-based）:
  - 共通: 0=NO, 3=注番（order_no）, 5=品番（product_code）
  - NO=45: 8=品名, 10=検区, 18=納入指示日（YYMMDD）, 19=納入指示数, 21=発行日（YYMMDD）
  - NO=47: 10=品名, 14=検区, 23=納期（MMDD/MDD/YYMMDD 等）, 24=指示数, 26=発行日（YYMMDD）

### クボタ KMT確定（NO=27）

- 対象: 得意先 000196 / 確定（FIRM） / KMT工場
- 取り込み条件: `NO=27` の行を取り込み
- 列番号（0-based）:
  - 3=注番（customer_order_no）
  - 5=品番（product_code）
  - 10=品名
  - 12=納入場所（ship_to_code）
  - 14=検区
  - 21=納期（YYYYMMDD）
  - 22=指示数
  - 24=発行日（YYMMDD）

### クボタ KMT内示（データNo=4）

- 対象: 得意先 000196 / 内示（FORECAST） / KMT工場
- 取り込み条件: `データNo=4` の行を取り込み
- 列番号（0-based）:
  - 7=品番（product_code）
  - 8=品名
  - 11=納入場所（ship_to_code）
  - 16=検区
  - 46〜70=予定納入指示数1〜25
  - 71〜95=納入指示日1〜25（YYYYMMDD）
- 内示数量は `予定納入指示数` を使用し、対応する `納入指示日` と組み合わせて日次レコード化する

#### Step 2: インポートサービスを実装

```python
# pm_backend/apps/orders/core/services/tiera_import.py
import csv
from datetime import datetime
from decimal import Decimal
from django.db import transaction
from orders.core.models import StgOrderRaw
from masters.models import Customer

class TieraNaijiImportService:
    """ティエラ内示（FORECAST）用CSVインポート"""

    # Column index definitions (0-based)
    IDENTIFIER_COL = 0      # データ区分 = "B17"
    COL_PRODUCT_CODE = 6    # 図番
    COL_DELIVERY_DATE = 8   # 納期 (YYYYMMDD)
    COL_QUANTITY = 11       # 数量
    COL_PRODUCT_NAME_FULL = 12  # 品名（全角）列13
    COL_PRODUCT_NAME_HALF = 13  # 品名半角 列14

    def __init__(self):
        self.errors = []
        self.warnings = []

    def import_csv(self, file, customer_code, order_type, source_system='CSV'):
        """ティエラ専用フォーマットを取り込み"""
        self.errors = []
        self.warnings = []

        try:
            # CP932 (Shift-JIS系) で読み込み
            file.seek(0)
            raw_data = file.read()

            # デコード試行
            encodings = ['cp932', 'shift-jis', 'utf-8-sig', 'utf-8']
            decoded_file = None
            for encoding in encodings:
                try:
                    decoded_file = raw_data.decode(encoding)
                    break
                except UnicodeDecodeError:
                    continue

            if decoded_file is None:
                return {
                    'success': False,
                    'message': 'Failed to decode CSV file',
                    'errors': ['Unsupported encoding']
                }

            # CSVを解析（ヘッダ無し、列番号で抽出）
            lines = decoded_file.splitlines()
            csv_reader = csv.reader(lines)

            raw_records = []
            row_no = 0

            for row in csv_reader:
                row_no += 1

                # ヘッダ/空行のスキップ
                if row_no == 1 or len(row) < max(self.COL_PRODUCT_CODE, self.COL_DELIVERY_DATE, self.COL_QUANTITY):
                    continue

                try:
                    # 列番号で抽出
                    product_code = row[self.COL_PRODUCT_CODE].strip()
                    product_name_full = row[self.COL_PRODUCT_NAME_FULL].strip() if len(row) > self.COL_PRODUCT_NAME_FULL else ''
                    product_name_half = row[self.COL_PRODUCT_NAME_HALF].strip() if len(row) > self.COL_PRODUCT_NAME_HALF else ''
                    delivery_date_str = row[self.COL_DELIVERY_DATE].strip()
                    quantity_str = row[self.COL_QUANTITY].strip()

                    # 日付パース（YYYYMMDD）
                    due_date = None
                    if delivery_date_str and len(delivery_date_str) == 8:
                        try:
                            due_date = datetime.strptime(delivery_date_str, '%Y%m%d').date()
                        except ValueError:
                            self.warnings.append(f"Row {row_no}: Invalid date format: {delivery_date_str}")

                    # 数量パース
                    quantity = None
                    if quantity_str:
                        try:
                            quantity = Decimal(quantity_str)
                        except:
                            self.warnings.append(f"Row {row_no}: Invalid quantity: {quantity_str}")

                    # 生データを作成
                    raw_record = StgOrderRaw(
                        customer_code=customer_code,
                        order_type=order_type,
                        source_system=source_system,
                        source_file=file.name,
                        source_row_no=row_no,
                        record_token='',
                        due_date=due_date,
                        product_code=product_code,
                        product_name=product_name_full,
                        product_name_halfwidth=product_name_half,
                        quantity=quantity,
                        raw_payload={'row': row},  # 行全体を保存
                        parse_status='PENDING'
                    )
                    raw_records.append(raw_record)

                except Exception as e:
                    self.errors.append(f"Row {row_no}: {str(e)}")

            if not raw_records:
                return {
                    'success': False,
                    'message': 'No valid records found',
                    'errors': self.errors
                }

            # DB保存（標準処理に委譲）
            # ...（デフォルトサービスと同様）

            return {
                'success': True,
                'message': f'{len(raw_records)} 件を取り込み',
                'raw_count': len(raw_records),
                'errors': self.errors,
                'warnings': self.warnings
            }

        except Exception as e:
            return {
                'success': False,
                'message': f'取込失敗: {str(e)}',
                'errors': self.errors + [str(e)]
            }
```

### 数量集約（Aggregation）

#### 背景

実際のCSVデータ（例：ティエラ_確定.csv）では、**同じ製品コード + 同じ納期で複数行（10行以上）が存在**することがあります。これは、異なる注文番号で同じ製品・納期の受注が入るためです。

#### 要件

1. **個別情報の保持**: 各注文番号と明細情報は、後で参照する必要があるため、個別に保存
2. **スケジューリング用の集約**: 生産計画を立てる際は、製品コード + 納期で数量を合計して使用

#### 実装方法

`get_active_order_lines_for_scheduling()` メソッドは、`aggregate` パラメータで動作を切り替え：

##### 方法A: 集約モード（aggregate=True、デフォルト）

製品コード + 納期で数量を合計したデータを返す：

```python

# スケジューリング用：集約データ取得
aggregated = CSVImportService.get_active_order_lines_for_scheduling(
    customer_id=1,
    aggregate=True  # デフォルト

for item in aggregated:
    print(f"{item['product_code']}: {item['total_quantity']} ({item['line_count']}行を集約)")
    # 例: 24201-36010: 150.000 (12行を集約)
```

#### 分析ロジック仕様

- **データソース**: `StgOrderRawKubota`（`data_no='36'`, `parse_status='PARSED'`）
- **確定数量**: `OrderLine`（`order_type='FIRM'`, `status='OPEN'`）のSUM
- **スナップショット**: `source_file` 単位で識別、`created_at` 昇順で時系列整列
- **休日除外**: `kubota_muke` カレンダーで稼働日のみを分析対象とする
- **内示未着荷除外**: 各納期の `qty_series` は最初に数量 > 0 が現れたスナップショット以降のみ使用（0値先頭除外）
- **誤差計算**: 全スナップショット × 全納期の `(内示量 − 確定量)` を収集
- **ワースト算出**: 納期ごとの最大過小量を集計し `Counter` でグループ化、上位2グループを返す
- **収束安定期間**: 各納期で `abs(qty − firm_qty) < 0.5` が連続して続いた最後のストリーク開始日→納期の営業日数（クボタカレンダー基準）

## 納入先コード処理仕様

### 概要

### 納入先コードの検出と正規化

#### CSVからの自動検出

以下のキーワードで納入先コード列を自動検出：

| カテゴリ | キーワード |
|---------|----------|
| **納入先キーワード** | 納入、納入先、delivery |
| **コードキーワード** | コード、ｺｰﾄﾞ、code、cd |

検出例：
- ✅ 「納入先コード」
- ✅ 「納入先ｺｰﾄﾞ」
- ✅ 「納入コード」
- ✅ 「delivery code」

#### クボタの正規化処理（2026-09-08）

- 堺・枚方・枚方2027形式・KMTの内示／確定すべてで、数値のみの納入先コードを先頭ゼロで5桁にそろえる。
- `971 → 00971`、`5476 → 05476`、`4 → 00004`。全角数字だけの場合も半角数字にして同じ処理を行う。
- 英数字コード、空欄は変更しない。5桁以上の数値コードは切り詰めない。
- 内示のV2/V3の組合せ判定より前に正規化し、抽出値 `raw_payload.ship_to`、日別ステージング、納入地マスタへ引き継ぐ。原票の行配列はそのまま保持する。
- 既存データの更新は `クボタ納入先コード5桁統一手順.md` を参照する。
- 以下の6桁ゼロ埋めはリーデン用であり、クボタには適用しない。

#### リーデンの正規化処理

```python
def normalize_ship_to_code(value: str) -> str:
    """納入先コードの正規化

    処理内容：
    1. Unicode正規化（NFKC）- 全角→半角変換
    2. ハイフン・スペース除去
    3. 数字のみの場合、6桁ゼロパディング

    例：
    "000010" → "000010"
    "10" → "000010"
    "１０" → "000010"
    "0-0-0-1-0" → "000010"
    """
    if not value:
        return ''

    import unicodedata
    normalized = unicodedata.normalize('NFKC', value)
    normalized = normalized.replace('-', '').replace(' ', '').replace('　', '')

    if normalized.isdigit():
        normalized = normalized.zfill(6)

    return normalized
```

### 納入先別リードタイム管理

#### 設定方法

各インポートサービスで納入先別のリードタイム（営業日）を定義：

```python
# 例：リーデン確定インポートサービス
SHIP_TO_LEAD_TIME_DAYS = {
    "000010": 2,  # 納入先コード 000010 → 2営業日前出荷
    "000030": 2,  # 納入先コード 000030 → 2営業日前出荷
}
```

#### 出荷日計算ロジック

納期（`due_date`）から納入先別リードタイムを引いて、出荷日を算出：

```python
def calculate_shipping_date(due_date: date, ship_to_code: str, calendar: Calendar) -> date:
    """納入先コードに基づいて出荷日を計算

    Args:
        due_date: 納期
        ship_to_code: 納入先コード
        calendar: カレンダ（営業日管理）

    Returns:
        出荷日（営業日ベース）
    """
    normalized_code = normalize_ship_to_code(ship_to_code)
    lead_days = SHIP_TO_LEAD_TIME_DAYS.get(normalized_code, 0)

    if lead_days <= 0:
        return due_date

    # カレンダーの営業日を使って逆算
    return subtract_working_days(due_date, lead_days, calendar)
```

### 営業日計算

#### カレンダーテーブル

#### 営業日逆算ロジック

```python
def subtract_working_days(base_date: date, days: int, calendar: Calendar) -> date:
    """営業日を逆算

    Args:
        base_date: 基準日（納期）
        days: 逆算する営業日数
        calendar: カレンダ

    Returns:
        逆算した日付（出荷日）

    例：
        base_date = 2026-01-15（納期）
        days = 2（営業日）
        → 2026-01-13（出荷日）
        ※ 土日祝日をスキップ
    """
    if days <= 0:
        return base_date

    remaining = days
    current = base_date

    while remaining > 0:
        current = current - timedelta(days=1)

        # カレンダから営業日判定
        cal_day = CalendarDay.objects.filter(
            calendar=calendar,
            target_date=current
        ).first()

        is_working = cal_day.is_working_day if cal_day else (current.weekday() < 5)

        if is_working:
            remaining -= 1

    return current
```

#### 営業日計算の例

```
納期: 2026-01-15（水）
納入先コード: 000010
リードタイム: 2営業日

計算：
2026-01-15（水）← 納期
2026-01-14（火）← 1営業日前
2026-01-13（月）← 2営業日前 ← 出荷日

※ 土日（1/11, 1/12）はスキップ
```

### 注意事項

1. **営業日計算にはカレンダーマスタが必須**
   - 得意先マスタに `calendar` を設定する必要がある
   - カレンダが未設定の場合、週末判定（月～金を営業日）で代替

2. **納入先コードは任意項目**
   - NULL許容のため、納入先がない場合は空文字列

3. **リードタイム設定の変更**
   - リードタイム変更時は、各インポートサービスの定数を更新
   - 既存データには影響しない（新規インポート時のみ適用）

4. **出荷日の自動計算タイミング**
   - CSVインポート時に自動計算
   - 手動修正も可能（ShipmentActualの編集）
