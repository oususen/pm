# 出荷進度照会 仕様書（ドラフト）

現行画面（`pm-ui/src/views/shipping/ShippingProgress.vue`）の挙動を元にした叩き台です。実装準拠のため、要件確定時に調整が必要な項目は「留意点」に明記します。

## 1. 概要

- 受注明細を基準に、日付別の内示・確定・実績・調整・進度を一覧表示する。
- 表示単位は「品番 × 得意先 × 納入先」でグループ化したカード。
- 進度は「需要（確定優先、なければ内示）」と「実績・調整」の差分を日次で累積した値。

## 2. 画面構成

### 2.1 ヘッダ

- 画面タイトル: 出荷進度照会
- サブタイトル: 「受注明細を基準に、日付別の内示・確定・実績・調整・進度を一覧化します。」
- フィルタ・操作:
  - 品番/品名で絞り込み（文字列）
  - 得意先で絞り込み（文字列）
  - 納入先で絞り込み（文字列）
  - 開始日（date）
  - 期間（日数）: 31 / 62 / 92
  - 更新ボタン（データ再読込）

### 2.2 本文

- グループカード一覧（ページングあり）
  - 左: 基本情報・サマリー
  - 右: 日付マトリクス（内示/確定/実績/調整/進度）

### 2.3 ページング

- 既定の表示件数: 20件
- 選択肢: 10 / 20 / 50 / 100
- コントロール: 最初 / 前へ / ページ番号 / 次へ / 最後
- 件数表示: 「{総件数}件中 {開始}-{終了}件」

## 3. 表示内容

### 3.1 グループ情報（左カラム）

- 品番
- 品名
- 得意先（`得意先コード + 得意先名` の連結。名称が無い場合はコードのみ）
- 納入先

### 3.2 日付マトリクス（右カラム）

- 列:
  - 月合計列: 表示期間がまたぐ各月（表示形式 `7月`, `8月` など）
  - 日別列: 開始日から期間分の連続日（表示形式 `M/D`）
- 行:
  - 内示
  - 確定
  - 実績
  - 調整
  - 進度（累積）
- 数値表示:
  - 月合計列は `内示 / 確定 / 実績 / 調整` を表示し、`進度` は空欄
  - 月合計の集計範囲は表示列の一部分ではなく、対象月の月初から月末まで
  - 内示/確定/実績/調整は 0 の場合は空欄
  - 調整は負数の場合に赤背景・赤字強調
  - 進度は 0 を含めて常に表示（ロケール表記）

## 4. データ取得

### 4.1 受注明細

- API: `GET /api/order-lines/?page_size=10000`
- フロントでの用途:
  - 日別の内示/確定数量の集計
  - グルーピングキーの生成

### 4.2 出荷実績

- API: `GET /api/shipment-actuals/`
- 送信パラメータ:
  - `shipment_date__gte`: 開始日
  - `shipment_date__lte`: 終了日（開始日 + 期間 - 1）
  - `product_code`, `customer_code`, `ship_to_code`
  - `page_size`: 10000
- フロントでの用途:
  - 日別実績数量の集計（グループキー一致で付与）

### 4.3 取得タイミング

- **初期表示時はデータを取得しない。** フィルタ未入力の状態で一覧は表示しない。
- 「更新」ボタン押下時にのみデータを取得・表示する。
- フィルタ変更後も「更新」ボタンで再取得する。

## 5. グルーピング・フィルタ

### 5.1 フィルタ条件（受注明細側）

- 品番/品名: `product_code + product_name` を小文字化して部分一致（バックエンドの `product_code` icontains で絞り込み）
- 得意先:
  - コード一致: `customer_code` の**末尾一致**（endsWith）でフィルタ。「1」入力 → `000001`（ティエラ）はヒット、`000196`（クボタ）はヒットしない
  - 名称一致: `customer_name` を小文字化して部分一致（OR条件）
  - バックエンドAPIでも `customer_code__endswith` フィルタを適用して絞り込む
- 納入先: `ship_to_code` を小文字化して部分一致（バックエンドの `ship_to_code` icontains で絞り込み）

### 5.2 グルーピングキー

- `product_code__customer_code__ship_to_code`
- `product_code` または `due_date` が空の行は除外

### 5.3 内示/確定集計

- `order_type === "FORECAST"` → 内示
- それ以外（`FIRM` または未設定） → 確定
- `due_date` 日付ごとに集計
- **確定優先ルール**: 同一品番・得意先・納入先・納期で FIRM が存在する場合、同一 source_key の FORECAST は表示から除外する。source_key は `品番__得意先コード__納入先コード__納期日（LT調整前）` で構成される。これにより、確定注文が入った後に内示ファイルが未到着でも二重計上を防止する。集約モード時も納入先単位で判定するため、異なる納入先の内示は影響を受けない

### 5.4 実績集計

- `shipment_date` 日付ごとに集計
- 受注明細と同一のグルーピングキーで結合

## 6. 進度計算

### 6.1 日次（マトリクスの進度）

- 累積進度は開始日から該当日までの合計で算出。
- 需要は「確定がある場合は確定、無い場合は内示」。

```
累積進度(初期) = 0
日次の需要 = firm > 0 ? firm : forecast
累積進度(当日) = 累積進度(前日) - 需要 + 実績 + 調整
```

## 7. 例外・状態表示

- 初期状態（更新ボタン未押下）: 一覧を表示しない（空白）
- ローディング: 「読込中...」
- エラー: 「エラー: {message}」
- データなし: 「データがありません」
- 更新中は更新ボタンを非活性化

## 8. 留意点（現行実装準拠）

- 受注明細は開始日/期間で絞り込まれないため、サマリー合計は表示期間外の値を含む。
- 出荷実績は取得時点の開始日/期間・フィルタで固定されるため、入力変更後は更新ボタンが必要。
- 調整値は画面内で更新されず、現行では常に 0（空欄表示）になる。
- グループ表示順はAPIの返却順に依存し、明示的なソートは行わない。
