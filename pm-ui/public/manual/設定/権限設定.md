# 権限設定

## 目的

各画面の表示やボタンの押下可否を、権限テンプレート＋個別上書きで設定します。  
下層ボタン（例: 生産計画入力）の可否も設定できます。

## 事前条件

- 設定画面を開けるユーザー（管理者、または設定の編集権限があるユーザー）

## 設定の流れ（基本）

1. 上部メニューの「設定」を開きます。
2. 「権限テンプレート」を開きます。
3. 部署・役職を選択します。
4. 必要な項目の「閲覧」「編集」にチェックを入れます。
5. 「保存」を押します。

## テンプレート3種類の関係（重要）

権限テンプレートは次の3種類があり、同じリソースに複数設定がある場合は後ろほど優先されます。

1. 部署 権限テンプレート
2. 役職 権限テンプレート
3. 部署・役職 権限テンプレート

さらに、ユーザー管理で「個別権限を使う」が有効なユーザーは、個別権限が最優先で上書きされます。

## 優先順位の具体例

例: あなたが「製缶部 / 製缶係 / 資材班長」の場合

- 部署テンプレートで `画面a` を許可
- 役職テンプレートで `画面b` を許可
- 部署・役職テンプレート（製缶部 × 班長）で `画面c` を許可

このとき最終的な有効権限は `画面a + 画面b + 画面c` です。

理由:
- 権限はリソース単位で評価されます。
- `部署・役職` で `画面c` だけを許可しても、`画面a` や `画面b` の許可は自動で消えません。

補足:
- 権限テンプレート保存時は、閲覧/編集が両方OFFの項目は保存対象外です。
- そのため「OFFを明示保存して禁止する」というより、「そのテンプレートでは未設定」として扱われます。

## 例外対応（特定ユーザーだけ変更）

1. 「設定 > ユーザー管理」を開きます。
2. 対象ユーザーを選択します。
3. 「個別権限を使う」にチェックを入れます。
4. 変更したい項目だけチェックを変更します。
5. 「保存」を押します。

## 閲覧/編集の意味

- 編集が ON の場合、閲覧も許可扱いです。
- 閲覧も編集も OFF の場合、ボタンは押下不可または非表示になります。

## 生産メニューの下層ボタン例

下層ボタンは `production.*` の権限で制御します。
未設定の場合は `production` の権限でフォールバック判定されます。

- production.process_input: 工程作業入力
- production.plan_input: 生産計画入力
- production.stock_allocations: 在庫引当
- production.line_monitor: ライン稼働監視

## 出荷メニューの下層ボタン

出荷メニューも同様にサブリソース単位で権限設定できます。
未設定の場合は `shipping` の権限でフォールバック判定されます。

| リソース | 対象画面 |
| --- | --- |
| shipping.instruction | 出荷指示 |
| shipping.actual | 出荷実績 |
| shipping.progress | 出荷進度照会 |
| shipping.order_document | 出荷指示書 |
| shipping.hirakata_pickup | 枚方集荷依頼書 |
| shipping.fujishoji_document | 富士商事出荷指示書 |
| shipping.ship_to_lead_time | 納入地別出荷加算日数 |

**出荷実績の閲覧のみ設定：** `shipping.actual` を閲覧ONにすると、登録フォーム・編集・削除ボタンが非表示になり、参照専用になります。

## 注意事項

- 権限は主にフロントエンドで制御します。画面表示・メニュー表示に加えて、`meta.resource` が設定された画面はURL直打ちでも制限します。
- バックエンドAPIでは権限チェックを行わないため、API呼び出し自体は制限しません。
- 変更後は画面を更新するか再ログインすると反映が確実です。
