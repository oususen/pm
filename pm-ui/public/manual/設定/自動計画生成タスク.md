# 生産計画自動生成タスク操作マニュアル

## 概要

本マニュアルは、生産計画の自動生成タスク（定時実行機能）を、ユーザー視点から解説します。  
スケジュール設定、手動実行、実行結果確認、トラブル対応をカバーします。

---

## 1. スケジュール設定の基本

### 1.1 設定画面へのアクセス

**左メニューから移動：** 左メニュー → 「設定」 → 「スケジュール設定」

**または URL で直接アクセス：** 

### 1.2 設定項目の説明

- **タスク名** — 参照のみ（AUTO_PLAN）
- **対象ライン** — 自動生成の対象ライン（例: LINE II）
- **実行タイミング** — 毎月何日に実行するか（例: 1日）
- **対象期間** — 対象とする先月数（翌月 / 翌々月 / 翌々翌月）
- **有効** — このスケジュール設定を有効にするか
- **失敗時通知先** — 実行失敗時に通知するユーザー（複数選択可）

## 2. スケジュール設定の編集

### 2.1 スケジュール設定を表示

1. **「スケジュール設定」ページを開く**
   - 左メニュー → 「設定」 → 「定時タスク設定」

2. **対象ラインのスケジュール行が表示される**
   - 各行が 1 つのライン設定に対応
   - 設定項目は行内で直接編集可能

### 2.2 スケジュール設定を編集

1. **対象の設定行の項目をクリック**

2. **設定内容を修正**
   - 対象ライン：LINE II を選択
   - 実行タイミング：日付を選択（例: 1日）
   - 対象期間：チェックボックスで選択
     - ☑️ 翌月
     - ☑️ 翌々月
     - ☑️ 翌々翌月
   - 有効：☑️ チェックボックスで有効/無効を選択
   - 失敗時通知先：ユーザーを追加

3. **「保存」ボタンをクリック**
   - 修正内容が保存されます

## 4. 手動実行

### 4.1 UI から手動実行

1. **「定時タスク設定」ページを開く**
2. **「今すぐ実行」ボタンをクリック**
3. **実行中…** と表示される

### 4.2 実行結果の確認

**実行後、以下が表示される：**

- **成功** — ✅ `完了 lines=1 created=113 updated=0`
- **失敗** — ❌ `エラーが発生しました: xxx`
- **実行中** — ⏳ `実行中...`

### 4.3 最終実行情報の確認

設定行の「最終実行情報」セルに表示される内容：

- **最終実行日時** — 2026-02-13 02:33:15
- **ステータス** — 成功
- **メッセージ** — ライン:LINE II(11) 期間:2026-03-01~2026-03-31 作成:113 更新:0
- **実行時間** — 45.3秒

## 5. 定時実行（自動スケジュール）

### 5.1 定時実行の仕組み

- **毎月 1日 00:00 に自動実行**（設定した実行タイミング日）
- 設定が「有効」になっていないと実行されない
- 実行可否は「実行タイミング」で設定

### 5.2 実行が実行されない場合

**チェックリスト：**

1. ✅ スケジュール設定が「有効」になっているか
2. ✅ 本日が「実行タイミング」の指定日か
3. ✅ バックエンドサーバーが起動しているか
4. ✅ 対象ラインが「有効」になっているか

### 5.3 ログで実行を監視

**バックエンドのログで実行履歴を確認：**

- **ログファイル:** pm_backend/logs/production.log
- **フィルター:** "AUTO_PLAN" を含む行を検索
- **実行結果例:** [2026-02-02 00:00:05,123] INFO AUTO_PLAN 完了 lines=1 created=87 updated=0

## 6. 対象期間の理解

### 6.1 対象期間の設定方法

**「翌月」「翌々月」「翌々翌月」から複数選択可能**

例) 2月1日に実行する場合：

- **☑️ 翌月** → 3月（1ヶ月先）
- **☑️ 翌々月** → 4月（2ヶ月先）
- **☑️ 翌々翌月** → 5月（3ヶ月先）

### 6.2 月が重複する場合の動作

**LINE II の自動生成設定例：**
- 実行タイミング：1日（毎月1日）
- 対象期間：☑️ 翌月、☑️ 翌々月

**スケジュール例：**

- **1月1日実行** → 2月、3月を生成（翌月+翌々月を生成）
- **2月1日実行** → 3月、4月を生成（**3月は上書き**・新たに推計）
- **3月1日実行** → 4月、5月を生成（**4月は上書き**・新たに推計）

**重要：** 月が重複する場合、**前の実行結果は削除され、新たに計画が生成される**（重複や取り残しはありません）。

## 7. よくある質問（FAQ）

### Q1. 自動生成の計画と手動計画の違いは？

**A.** 自動生成も手動計画も同じロジックで生成されます。違いは以下の通り：

- **実行者** — 自動生成：スケジューラ、手動計画：ユーザー
- **実行日** — 自動生成：指定日に自動、手動計画：ユーザーが任意
- **後処理** — 自動生成：自動実行、手動計画：UI の「保存」で実行
- **計画品目** — 自動生成：ライン最終品のみ、手動計画：ユーザーが選択

### Q2. 計画が作成されないのはなぜ？

**A.** 以下を確認してください：

1. **ライン最終品に需要があるか** 
   - 生産計画UI → 需要取り込み → 期間内のライン最終品に需要があるか確認

2. **LINE が有効か**
   - マスタ → LINE 一覧 → 対象ラインが「有効」になっているか

3. **期間設定が正しいか**
   - 「対象期間」が 1つ以上選択されているか

### Q3. sequence_no や plan_id とは？

**A.**
- **sequence_no** — 同じ日付内での計画の順番（1,2,3,…）
- **plan_id** — 計画の一意識別子（例: YD60000441_20260315_12_1）

これらは自動で採番されるため、ユーザーが意識する必要はありません。

### Q4. 自動生成された計画を削除したい

**A.** 自動生成コマンドで生成された計画は、以下の方法で削除します：

1. **手動で期間を指定して再実行**
   - スケジュール設定で「今すぐ実行」をクリック
   - 同じ期間で計画を再生成すると、古い計画は置き換わります

2. **次の自動実行まで待つ**
   - 定時に自動実行されるまで待機

3. **データベースから直接削除（技術者向け）**
   - 技術支援チームに連絡してください

### Q5. 失敗時通知を受け取らない

**A.** 以下を確認：

1. ✅ 「失敗時通知先」にユーザーが登録されているか
2. ✅ 登録ユーザーのメールアドレスが正しいか
3. ✅ メール配信サーバーが正常に動作しているか

## 8. トラブルシューティング

### 問題: 「完了したが計画が反映されていない」

**対策：**

1. **ブラウザのキャッシュをクリア**
   - Ctrl+Shift+Del → キャッシュを消去 → 再度ページを開く

2. **ページをリロード**
   - F5 キーで強制リロード

3. **バックエンドの確認**
   - http://localhost:8081/api/health/ で API が応答しているか確認

### 問題: 「エラーが発生しました」と表示

**対応手順：**

1. **エラーメッセージをメモ**
2. **バックエンドのログを確認**
   - pm_backend/logs/production.log を確認
3. **技術担当者に報告**

**よくあるエラー：**

- **対象ラインがありません** — 原因：設定されたラインが無効 → 対応：ラインを有効化
- **需要なし** — 原因：対象期間に需要がない → 対応：需要データを確認
- **Database connection error** — 原因：DB が停止 → 対応：管理者に連絡

## 9. ベストプラクティス

### 9.1 設定のポイント

**✅ 推奨設定**

- **実行タイミングは「月初（1日）」に設定**
  - 前月の確定需要に基づいて計画を生成

- **対象期間は「翌月+翌々月」に設定**
  - 2ヶ月先までの需要を織り込む

- **失敗時通知先は「製造部長など複数人」に設定**
  - 万が一の失敗に気づきやすい

### 9.2 実行後の確認

**✅ 毎回実行後に確認すること**

1. **「最終実行情報」で状態確認** — 成功/失敗を確認
2. **「created」の件数が妥当か確認** — 0件の場合は要注意
3. **生産計画UI で計画が正しく反映されているか確認** — 画面で動作確認

### 9.3 月の初めにすべき作業

- [ ] 前月の計画実績を確認
- [ ] 今月のスケジュール設定が正しいか確認
- [ ] 手動実行 → 結果確認
- [ ] 必要に応じて計画を微調整

## 10. 自動生成の処理フロー

### 処理ステップ（ユーザー向け簡略版）

**1. 需要取り込み**
- 需要テーブルから最新需要を読込

**2. 既存計画を削除**
- 指定期間の古い計画をリセット

**3. 新しい計画を生成**
- LinePlan（最終品計画）を作成
- sequence_no / plan_id を自動採番

**4. 工程を展開**
- 最終品 → 各工程別に分割
- LineBacklog（詳細計画）を作成

**5. ガント計画を生成**
- 時間軸上にスケジュール配置
- 工程順序・リード時間を考慮

**✅ 完了 → 生産計画UI に反映**

## 12. 自動計画ロック機能

### 12.1 ロック機能とは

特定の日×製品の計画セルを、自動計画で**上書きされないように保護**する機能です。
手動で調整した計画を自動計画から守りたいときに使います。

### 12.2 ロックの設定方法

1. **生産計画入力画面**または**仕入計画入力画面**を開く
2. 計画を入力・**保存**する（未保存の数量はロックできません）
3. ツールバーの「**🔒ロック**」ボタンをクリック → **ロックモード ON**（ボタンがオレンジ色に変わる）
4. ロックしたい計画セル（日付×製品）をクリック → **黄色背景 + 🔒マーク**が表示される
5. 解除したいセルをもう一度クリック → ロック解除
6. 「**🔒ロック中**」ボタンをもう一度クリック → **ロックモード OFF**（通常の編集モードに戻る）

### 12.3 ロックの効果

| 操作 | ロック済みセルへの影響 |
|------|----------------------|
| **定時自動計画**（バックエンド） | ロック時の保存済み数量を使用 |
| **「自動計画」ボタン**（画面上） | ロック時の保存済み数量を使用 |
| **手動入力** | 変更前に解除が必要 |

### 12.4 注意事項

- ロックは**ライン×日×製品**の単位で設定されます（工程単位ではありません）
- ロック中は計画数を編集できません。解除→編集→保存→再ロックの順に操作します
- ロック情報はサーバーに保存されるため、画面を閉じても保持されます
- ロックを設定したら、次の自動計画実行時からその日×製品の計画は保護されます
